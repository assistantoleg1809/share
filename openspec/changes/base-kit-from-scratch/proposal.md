# Proposal

## Why

Анализ 14 скиллов суперпауэрс (`research/superpowers-skills/`, 2026-11-14)
выявил корневые боли v2: движок в прозе (`run` — машина состояний на
естественном языке: стадии, счётчики, loop guard, WAIT), конфигурация как
язык (yaml-реестр + манифест позиций + formatVersion), единица работы
«шаг» вместо «фаза» и тестирование машинерии вместо ценности. Подготовленный
change `simplify-to-base-kit` решает только состав (7→3 скиллов)
механической чисткой текстов — методика при этом наследует конвейерные
привычки. Решение пользователя 2026-11-14 («путь б»): писать три скилла
**с нуля** по решётке суперпауэрс — «методология + файловый контракт, без
движка и без конфигурации»; весь v2 сразу уезжает в пример, промежуточная
версия не строится.

## What Changes

- **BREAKING** Три скилла пишутся с нуля (не переименование analyst/
  courier/operator): `task` — фаза разработки (контекст задачи →
  спецификация опционально, инструментом спекирования проекта, имя не
  вшивается — discovery в рантайме → реализация TDD → коммиты;
  лёгкий/полный путь выбирается по заданию); `pr` — фаза доставки
  (ветка → карточка «пуш+PR» → цикл замечаний); `ci` — фаза CI
  (карточка запуска → запуск → ожидание → лог → секция диагностики:
  первая настоящая ошибка, категория, fixable; kind-файлы
  build.md/deploy.md).
- Маршрут фикса по связанности с задачей: ошибка внутри диффа задачи —
  правка в её ветке, пушем в тот же PR; посторонняя ошибка CI (инфра/
  конфиг/чужой код, не связана с бизнес-задачей и эволюционирует
  независимо) — отдельная техническая ветка от базовой и отдельный PR;
  посторонние правки не трогают артефакты спеки проекта.
- Порядок прогона с внешними скиллами (решение пользователя, пересмотр
  файла-профиля): перечень из задания → чек-лист plan.md → одно
  подтверждение в начале; гейт создания PR = вход в `pr` на строке
  слота — детерминизм позиции с первого прогона, без конфигурации.
  `ship-kit.workflows.md` — опциональный макрос типовых наборов, не
  механизм.
- Тесты базы (RED/GREEN-прогоны на моках, golden-снимки) отложены
  решением пользователя («без тестов пока»); проверки изменения —
  статические (validate --strict, grep-чистота поставки, структура,
  JSON-манифест).
- **BREAKING** Единица работы = фаза: один вызов проходит фазу целиком с
  внутренним чек-листом; один Шаг-0 (проверка MCP) и один контракт отчёта
  на вызов; handoff следующей фазы — строкой в отчёте, без авто-переходов.
- **BREAKING** Конфигурации нет: ни реестра, ни манифеста позиций, ни
  стадий/переходов, ни formatVersion; MCP-алиасы, имена джоб и ветки —
  аргументами вызова. Единственный файл состояния —
  `skill-runs/<КЛЮЧ>/plan.md` (чек-лист фаз со счётчиком попыток числом в
  строке, текущая фаза, журнал) + `issues.md` для провалов.
- **BREAKING** Гейты = три правила без семантики наследования карточек:
  карточка-превью → явное «да» → отдельное действие; отказ = стоп без
  перебора альтернатив; дословное «подтверждаю …» в задании =
  pre-approved. Повтор той же джобы после flaky — переспрос одной строкой.
- Дисциплина верификации: `OK: true` только с дословными свежими строками
  прогона/статусов в отчёте (evidence before claims).
- Границы необратимого из v2 сохраняются: пуш только в рабочие ветки
  `<X>/<КЛЮЧ>` (целевые ветки NEVER), статусы Jira не трогать, «ничего не
  искать» (джобы/пути — из args или вопроса человеку, не сканированием).
- Ядро каждого SKILL.md ≤ ~150 строк; тяжёлое — support-файлы по
  требованию (kind-файлы CI, шаблон карточки гейта).
- Весь конвейер v2 (скиллы `run`/`doctor`/`registry`/`adapt-kit`, манифест
  позиций, схема реестра — при переносе конвертируется из yaml в md,
  решение пользователя: для ии-агентов текстовый формат читаемее yaml,
  v2-документация, выжившие tests/e2e из `dev/`) выносится в
  `examples/conveyor/` в корне репо — рабочий образец, не продукт; change
  `simplify-to-base-kit` удаляется как поглощённый этим изменением.
- OpenSpec-корень переезжает в корень репо; каталог `dev/` ликвидируется;
  версия расширения — 2.0.0.

## Capabilities

### New Capabilities

- `base-skills`: три скилла-фазы базового комплекта (`task`, `pr`,
  `ci`) — контракт аргументов (MCP-алиасы в вызове), единица работы
  «фаза», гейты необратимого в три правила, диагностика падений CI внутри
  `ci` с маршрутом фикса по связанности, нейтральность к инструменту
  спекирования (discovery в рантайме), дисциплина верификации отчётов,
  границы веток и Jira; работа без какой-либо конфигурации проекта.

### Modified Capabilities

- `conveyor`: удаляются все требования — диспетчер `run`, обход стадий,
  счётчики/loop guard, WAIT-режим, гейт-контракт с наследованием карточек;
  семантика сохраняется снимком в `examples/conveyor/docs/`.
- `registry`: удаляются все требования — реестр не часть базы.
- `executors`: удаляются все требования (позиции, манифест, kind-наборы);
  выживающие инварианты (гейты, границы веток, MCP только из аргументов
  вызова) переформулированы в `base-skills`.

## Impact

- `extensions/ship-kit/skills/`: три каталога `task/`, `pr/`, `ci/`
  с текстами с нуля (v2-тексты analyst/courier/operator не переносятся);
  `ci/` получает kind-файлы `build.md`/`deploy.md` (переработанные из
  `doctor/`).
- `extensions/ship-kit/`: `QWEN.md` и короткий `docs/ship-kit.md` с нуля;
  `qwen-extension.json` — 2.0.0, новые displayName/description; удаляются
  `docs/ship-kit.positions.yaml`, `docs/ship-kit.projects.example.md`.
- `examples/conveyor/` (новое, корень репо): тексты скиллов
  run/doctor/registry/adapt-kit, манифест позиций, схема реестра в md
  (конвертация из yaml при переносе), полный v2-документ, снимок
  мейн-спек conveyor/registry/executors, выжившие tests/e2e из `dev/`
  (yaml-валидатор не переезжает), README (когда конвейер нужен,
  зависимость от имён базы, «оживление» копированием, миграция с v1.0.0).
- `dev/`: ликвидируется (76 незастейдженных удалений финальны, 13 выживших
  файлов переезжают в пример).
- `openspec/`: корень → корень репо; change `simplify-to-base-kit`
  удаляется; мейн-спеки conveyor/registry/executors закрываются REMOVED-
  дельтами этого изменения.
- Установленные v1.0.0: миграция = переустановка расширения, новые имена
  скиллов, вызов без реестра.
