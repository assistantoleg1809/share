# Proposal

## Why

v3 лишился тестового стенда: расширение `extensions/ship-kit/` удалено
(вместе со старым e2e), а `examples/conveyor/e2e/make_sandbox.mjs`
ссылается на несуществующий `dev/ship-kit/…`. Опросник
(`docs/review.md`) живёт отдельно от инструментов проверки. Нужен
самодостаточный каталог `dev/ship-kit/`: моки MCP, песочница, раннер
и проверка одного успешного прогона базы v3 (task → pr → ci) на
бюджетной модели glm-5.3-flash — с промптом и инструкцией для
человека. Прогоны — только на glm-5.3-flash (правило проекта).

## What Changes

- Новый `dev/ship-kit/` (не поставляется, только разработка/приёмка)
  с иерархией (доворка 2026-11-25: «в корне только скиллы»):
  `stand/` — тест-стенд (`mcp/mock.mjs` — универсальный мок
  (jenkins · jira · confluence · bitbucket · sonar; stdio JSON-RPC,
  состояние в файле; перенос из examples/conveyor/e2e),
  `make_sandbox.mjs` — песочница, `run_one.sh` / `check.sh`,
  `SCENARIOS.md`, `e2e-run.md`, `INSTRUCTION.md`),
  `review/review.md` — опросник, `docs/` — manual/changelog/схема/
  эталон плана, `examples/` и `research/` — образцы и снимки,
  `README.md` — карта воркспейса; корень репо — только `skills/`
  (+ `openspec/`: CLI и скиллы openspec-* ищут корень вверх от cwd —
  перенос ломает обнаружение).
- Опросник перенесён: `docs/review.md` → `dev/ship-kit/review/review.md`
  (приёмка = стенд + опросник в одном месте); `docs/ship-kit.md` п.9
  обновлён.
- Прочее из корня репо перенесено в `dev/ship-kit/docs/` (ship-kit.md,
  upgrade.md, flow.html, example-plan.md), `dev/ship-kit/examples/`
  (conveyor, central-catalog, demo-project) и `dev/ship-kit/research/`;
  относительные ссылки исправлены.
- Скиллы в песочницу копируются из `skills/` репо на момент сборки —
  тестируется текущее состояние поставки, дублей нет.
- Ручной режим (доворка по запросу 2026-11-25): `manual.sh` в
  песочнице (интерактивная сессия qwen на glm-5.3-flash, карточки
  подтверждает человек — промпт без pre-approved фраз), раздел README
  «Ручной запуск» с пошаговым ожиданием и местами для наблюдения;
  `check.sh` толерантен к отсутствию `run.log`.
- `INSTRUCTION.md` — самодостаточная инструкция для запускающего без
  истории сессии (запрос 2026-11-25): контекст проекта, оба режима
  (скриптом `run_one.sh [сценарий]` и руками `manual.sh`) с промптами
  и ожиданием по шагам, критерии, поведение после прогона (GREEN →
  журнал + «архив», RED → задача) и пошаговое создание новых
  сценариев (промпт/фикстуры/сид/ручной вариант/критерии — 5 шагов);
  `run_one.sh` параметризован именем сценария.
