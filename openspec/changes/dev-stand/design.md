# Design

## Context

v3: поставка — `skills/ship-kit-{task,pr,ci}`; стенд старой эпохи
удалён вместе с расширением. Моки и механика песочницы обкатаны в
`examples/conveyor/e2e/` (mock.mjs — универсальный stdio-мок с
файловым состоянием; make_sandbox — bare+клон; уроки: headless args
строкой, flash-сессии могут зависать — лечится `--resume`,
`--max-wall-time`). Прогоны — только glm-5.3-flash.

## Decisions

1. **Всё стенда — в `dev/ship-kit/`** (решение человека): моки,
   сборка песочницы, раннер, проверка, сценарий, журнал, опросник.
   Песочницы создаются в `$TMPDIR/ship-kit/` (cwd сессии прогона).
   Каталог `dev/` не входит в поставку — источник проверяется по
   месту.
2. **Мок — перенос проверенного `mock.mjs` из conveyor-e2e** почти
   дословно: роли argv (jenkins/jira/confluence/bitbucket/sonar),
   состояние — `MOCK_STATE` (каждый вызов свой stdio-процесс),
   `jenkins_get_build` первый опрос возвращает RUNNING (проверка
   правила ожидания из ci-wait-job), `create_pr` — autoMerge MERGED.
3. **Скиллы копируются в песочницу** (`skills/ship-kit-*` →
   `<sb>/.qwen/skills/`): тестируется текущее состояние репо, без
   глобальной установки; дублей в dev/ нет — единственный источник
   `skills/`.
4. **Гейты в headless — pre-approved фразами в промпте** («подтверждаю
   пуш ветки и создание PR», «подтверждаю запуск сборки PRJ-777»):
   механизмы спеки, обкатанный путь e2e. `poll=5` в промпте — чтобы
   ожидание RUNNING→SUCCESS не тянуло дефолтные 600 сек.
5. **Один сценарий green777**: happy-path база — возьми PRJ-777 →
   mul(a,b) → коммит → pr (пуш+PR, MERGED) → ci (запуск, RUNNING →
   SUCCESS) → план закрыт → предложение архивации. Критерии успеха —
   машино-проверяемые (`check.sh`: план-файл, слоты закрыты, PR
   MERGED, джоба polls ≥ 2 — агент ждал, не спрашивал; ветка в bare;
   в логе нет «ждать ли»).
6. **Без watchdog-драйвера** (в отличие от batch-прогона v2): один
   прогон запускает человек; зависание flash — Ctrl-C и
   `retry.sh` (`--resume`, план — токен возобновления).
7. **Опросник переезжает** в `dev/ship-kit/review/review.md`: приёмка =
   стенд (живое поведение) + опросник (тексты/эталоны) в одном
   месте; указатель в docs/ship-kit.md п.9 обновлён.

## Risks / Trade-offs

- [flash зависает на API-стриме] → README: Ctrl-C + retry.sh
  (`--resume`); `--max-wall-time 10m` как страховка.
- [Формат плана агентом может отличаться от чекбоксов] → проверка
  слотов — эвристика grep «[ ]»; остальные критерии не зависят от
  формата.
- [Моки детерминированы сидом] → сценарии расширяемы (RED-сидами из
  mock.mjs: FAIL_CODE/FAIL_CONFIG/FAIL_SONAR/FAIL_INFRA) — вне
  этого change.
