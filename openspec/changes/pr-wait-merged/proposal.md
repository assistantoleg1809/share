# Proposal

## Why

После создания PR цепочка прогона стоит на слоте `pr` до MERGED, но
механизма ожидания нет: правило «статус проверяй по ходу» оставляет
переход к `ci` на усмотрение человека — тот сам должен вернуться и
продолжить. Нужен явный цикл ожидания: `pr` опрашивает статус
созданного им PR и сам продолжает цепочку сразу после мержа.

## What Changes

- `pr` после создания PR (и при возобновлении прогона, пока слот `ci`
  закрыт мержем) активно ждёт MERGED: опрашивает статус PR через MCP
  репозитория с интервалом, по умолчанию 10 секунд.
- Интервал разрешается лесенкой: **задание > конвенция проекта >
  дефолт 10 сек**; вопрос человеку не задаётся (дефолт есть).
- MERGED (свежий дословный статус из MCP) → слот `pr` закрывается
  зелёным, следующий слот плана (обычно `ci`) вызывается без вопроса —
  цепочка уже авторизована планом.
- DECLINED (или закрыт без мержа) → честная ошибка и стоп; провал
  фиксируется задачей в `skill-runs/<КЛЮЧ>/issues.md` по действующим
  правилам.
- Ожидание — чтение (get_pr), не необратимое действие: карточка-гейт не
  оформляется. Транспортные сбои опроса — действующее правило
  авто-повтора (до 2), без повторного гейта.
- Ожидание относится к PR текущего прогона (создан этим вызовом или
  зафиксирован в plan.md). Разовая проверка `check` остаётся без
  ожидания.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `base-skills`: ADDED-требование «Ожидание мержа PR» — активный опрос
  статуса созданного PR до MERGED/DECLINED с интервалом (дефолт 10 сек,
  лесенка задание > конвенция > дефолт); MERGED открывает следующий
  слот без вопроса, DECLINED — стоп с провалом в issues.md.

## Impact

- `extensions/ship-kit/skills/pr/SKILL.md` — шаг ожидания в
  implement+pr, переработка «Завершения фазы» (опрос вместо «проверяй
  по ходу»), уточнение description (триггер «дождись мержа»).
- `extensions/ship-kit/docs/ship-kit.md` — ожидание мержа в описании
  работы комплекта (flowchart/«Как это работает»).
- `openspec/specs/base-skills/spec.md` — синк дельты при архивации.
- Установленная копия `~/.qwen/extensions/ship-kit` — переустановка по
  процедуре репо.
