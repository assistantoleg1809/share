# Design

## Context

Сегодня в `pr`/SKILL.md после создания PR действует правило «Завершение
фазы»: следующий слот вызывается сразу (обычно `ci` после MERGED), до
MERGED цепочка стоит на слоте `pr`, а статус предлагается «проверять по
ходу» — механизма нет, переход к `ci` происходит только когда человек
сам вернётся с продолжением. Требование «Состояние прогона — plan.md»
уже задаёт рамку: слот `ci` открывается после MERGED, статусы — только
свежие из MCP, слова человека — не статус. Скиллы комплекта — агентные
тексты: механика ожидания — предписанный скиллом цикл лёгких MCP-вызовов
с паузой между ними.

## Goals / Non-Goals

**Goals:**

- Детерминированный переход `pr` → `ci` по факту MERGED из свежего
  ответа MCP, без участия человека.
- Интервал опроса как параметр: дефолт 10 секунд, лесенка
  задание > конвенция проекта > дефолт, без вопроса.

**Non-Goals:**

- Ожидание чужих PR (не текущего прогона) — не делаем.
- Таймаут ожидания / эскалация по времени — не вводим: ревью может идти
  часами, порог произволен; прерывание сессии уже покрыто токеном
  возобновления plan.md.
- Уведомления о мерже в chat — вне этого изменения.
- Обработка замечаний внутри цикла ожидания — `fix` остаётся отдельным
  вызовом; ожидание следит только за статусом.

## Decisions

1. **Ожидание живёт в `pr`** — как хвост implement+pr (после создания
   PR) и как состояние возобновления слота. Альтернативы отвергнуты:
   отдельная фаза wait дробит фазу и противоречит «Единица работы —
   фаза»; ожидание в `ci` поздно — план открывает `ci` только после
   MERGED.
2. **Цикл**: лёгкий get_pr (чтение, allow) → OPEN → пауза длиной
   интервала → повтор. Исходы: MERGED (свежий дословный статус) → слот
   зелёный, следующий слот без вопроса (цепочка авторизована планом);
   DECLINED → честная ошибка, стоп, задача в issues.md. Альтернатива
   «спросить человека при DECLINED» отвергнута: провал уже произошёл,
   перебор альтернатив запрещён гейтовыми правилами.
3. **Аргумент интервала** — `poll=<сек>` в вызове; конвенция проекта
   может задать интервал своей записью (тогда применяется без вопроса);
   дефолт 10 секунд. Имена `interval=`/`wait=` отвергнуты: `poll=`
   короче и однозначно про опрос статуса.
4. **Каждый опрос — свежий вызов MCP**: статус из прошлого опроса не
   переносится на следующий цикл (действующее правило «слова — не
   статус» распространяется и на собственные прошлые ответы). Транспорт
   — действующее правило авто-повтора до 2, без повторного гейта.
5. **Description `pr`** получает триггер «дождись мержа»: одиночный
   вызов с ключом («дождись мержа PRJ-42») — то же возобновление слота
   `pr` по plan.md этого ключа, не поиск по репозиториям; после MERGED
   продолжение идёт по плану (если план прогона жив). `check` остаётся
   разовой проверкой без ожидания.
6. **Контракт отчёта не расширяется**: новых строк нет; MERGED
   фиксируется дословным статусом в теле отчёта, HANDOFF после
   дожатого мержа — `ci`. Число опросов/длительность — не статус,
   в верификацию не входят.

## Risks / Trade-offs

- [Долгое ревью → много циклов опроса, расход токенов/нагрузка на MCP]
  → интервал настраивается (`poll=60`, конвенция); человек может
  прервать сессию — план возобновит ожидание; дефолт 10 сек задан
  требованием пользователя.
- [У MCP репозитория нет читаемого статуса PR] → выявляется на Шаге-0
  лёгкими вызовами до каких-либо необратимых действий — блок ошибки.
- [Спорный статус (человек говорит MERGED, MCP — OPEN) посреди
  ожидания] → действует существующий сценарий «слова против статуса»:
  один вопрос, ждать или собрать на рабочей ветке.

## Migration Plan

Текстовые правки: `pr`/SKILL.md (description, implement+pr, «Завершение
фазы»), docs/ship-kit.md (описание работы и flowchart), строка фазы `pr`
в QWEN.md комплекта. Синк дельты в `openspec/specs/base-skills` — при
архивации. Переустановка постоянной копии `~/.qwen/extensions/ship-kit`
— по процедуре репо. Откат не нужен: правка текстов, git-история
сохраняет предыдущее состояние.
