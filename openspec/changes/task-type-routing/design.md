# Design

## Context

После skill-slots (2.2.0) переменные исполнители разрешаются слотом:
дословная метка `slot:<имя>` в description SKILL.md + каскад «задание
> конвенция > метки сессии» (см. proposal.md — Why; исследование
обоснования — `research/cross-skillset-invocation`). Типов задач
комплект не различает: любой тикет идёт одним ходом. Шаг-0 `task`
состоит из трёх пунктов: 1) проверка MCP, 2) план прогона, 3)
спецификация. Правила комплект дублирует в трёх точках: SKILL.md
(исполнение), QWEN.md (инварианты), docs/ship-kit.md (докуметация).

## Goals / Non-Goals

**Goals:**

- Детерминированное определение типа задачи (business/technical) на
  Шаге-0 и сборка набора скиллов типа — переиспользованием механизма
  слотов, без новой машинерии.
- Поведение при пустом наборе — асимметрично, по решению человека
  (диалог 2026-11-20): technical — молча без скиллов, business — один
  вопрос.

**Non-Goals:**

- Правки openspec-скиллов репо и dogfood-метки в этом репо (граница
  change подтверждена человеком).
- Типы в фазах `pr`/`ci`; третьи типы (механизм допускает добавлением
  метки, отдельным change).
- Рантайм-классификация типа по смыслу текста задачи (отвергнуто
  исследованием: из 13 систем никто не использует матчинг по описанию
  как единственный механизм).

## Decisions

1. **Наборы — слотами, не новым механизмом.** Словарь слотов пополняется
   `business` и `technical`; набор = скиллы сессии с меткой слота типа,
   дословный поиск — как у `slot:spec`. Альтернатива — центральный
   манифест наборов в комплекте: отвергнута, набор переменный от
   проекта к проекту, комплект его не знает (инвариант «работа без
   конфигурации проекта»). Список конвенции остаётся переопределением
   поверх меток — конвенция сильнее, как в spec-каскаде.
2. **Семантика метки расширена, словарь один.** Метка слота типа
   означает членство в наборе, а не исполнение единственной роли
   (исполнитель роли один, членов набора много). Фиксируется в docs
   п.4 рядом со словарём; отдельного словаря типов не заводим.
3. **Точка встраивания — новый пункт 4 Шага-0 `task`** («Тип задачи и
   набор»), после спецификации: не перенумеровывает существующие пункты
   1–3 (меньше диффа), а расщепление смешанных задач дописывает в план,
   созданный пунктом 2. Альтернатива — вставка пунктом 3 со сдвигом
   нумерации: отвергнута из-за шума в диффе.
4. **Маркер типа — дословный `(business)` / `(technical)`**, латиницей в
   скобках, единый для задания и тикета. Русские слова («бизнес»,
   «техническая») не матчатся — дословность по аналогии с метками
   `slot:`.
5. **Дефолт business без вопроса; пустой набор асимметричен** (решение
   человека): technical-задачи агент выполняет и сам — молча без
   скиллов; бизнес-задачи обычно идут через скиллы — пустой набор
   business это аномалия, отсюда один вопрос закрытыми опциями
   (продолжить без скиллов / назвать скиллы). Явная запись конвенции
   (даже фиксирующая «business — без набора») вопрос убирает: запись
   есть — набор задан.
6. **Версия 2.2.0 → 2.3.0 + секция docs/upgrade.md.** Существующий
   детектор дрейфа сам сообщит прогонам о смене комплекта; рецепты:
   поставить метки нужным скиллам или назначить списки конвенцией;
   ничего не сделали — technical идёт без скиллов, business спрашивает.

## Risks / Trade-offs

- [В проекте без business-меток каждая немаркированная задача
  заканчивается вопросом] → конвенция явно назначает набор (или явный
  «без набора»); вопрос закрытыми опциями — один клик.
- [Маркер `(technical)` случайно в тексте задания] → маркер специфичен
  (скобки, латиница); ложное срабатывание видно в строке диагностики
  «источник: задание» и правится явным маркером другого типа.
- [Чужие скиллы без меток молча не попадают в наборы] → соответствует
  принятому принципу (метка заявляется автором скилла; «похоже по
  смыслу» не трактуется); отсутствие фиксируется строкой диагностики.

## Migration Plan

Бамп версии манифеста + секция рецептов; существующие прогоны увидят
дрейф штатно (одна строка отчёта, конфиги проекта не правятся).
Откат — возврат версии и текстов (правки только в файлах комплекта,
проектного состояния нет).
