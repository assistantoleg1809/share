# Spec Delta

## MODIFIED Requirements

### Requirement: Три скилла-фазы с говорящими именами

Комплект MUST поставлять ровно три скилла: `task` — контекст задачи и
правки кода (спецификация изменения — опциональный путь), `pr` — рабочая ветка,
пуш, PR и цикл замечаний, `ci` — запуск и ожидание джоб CI с
диагностикой падений. Description каждого скилла MUST содержать только
«когда использовать» с триггерами вызова, без словаря конвейера.
Закрытый слот плана прогона MUST продолжаться следующим незакрытым
слотом **без остановки** (цепочка авторизована планом; паузы — только
🔒-гейты и вопросы правил; конец плана — стоп). Одиночный вызов скилла
человеком вне плана выполняется без цепочки. Тексты поставки MUST
обращаться к MCP по ролям, не по именам конкретных продуктов; роли на
серверы мапит конвенция проекта. Канонические роли: **tracker** (трекер
задач), **docs** (вики/runbook), **repo** (репозиторий и PR), **build**
(сборка), **deploy** (деплой), **quality** (качество кода), **vuln**
(уязвимости/сканирование), **chat** (чаты/мессенджеры).

#### Scenario: правка по тикету

- **WHEN** человек вызывает `/ship-kit:task возьми PRJ-42, mcp-tracker=tasks`
- **THEN** task собирает контекст, оформляет изменение (или правит напрямую — по весу задания), коммитит и сразу продолжает следующим слотом плана — `pr` с карточкой «пуш+PR»

#### Scenario: имя продаёт вызов

- **WHEN** человек читает description скилла, не открывая SKILL.md
- **THEN** из description понятно, какой скилл звать: «возьми задачу» → task, «отправь на ревью» → pr, «запусти сборку» → ci

#### Scenario: одиночный вызов вне плана

- **WHEN** человек зовёт один скилл для одиночного шага (например «проверь PR» или «дай лог»)
- **THEN** выполняется только этот вызов, цепочка не тянется

### Requirement: Работа без конфигурации проекта

Всё необходимое скиллы получают аргументами вызова: MCP-алиасы, имена
джоб, стенды, ветки. Формат алиаса: `mcp-<роль>=<сервер>`; **одна роль
может иметь несколько MCP** — серверы перечисляются через запятую
(`mcp-tracker=jira1,jira2`): все перечисленные рабочие, чтение идёт по
всем, запись — в названный заданием сервер, не назван — один вопрос.
Аргументы MUST разрешаться лесенкой: **задание > конвенция проекта >
один вопрос человеку**. Конвенция проекта — обычный контекст сессии
(файлы проекта, например файл проектов); комплект MUST NOT требовать её,
фиксировать имя или формат. После конвенции недостающее скилл MUST
запросить у человека. Комплект MUST NOT требовать реестра, манифеста
или иного файла конфигурации. Сканирование серверов и перебор
джоб/путей («поиск») запрещён.

#### Scenario: алиасы переданы вызовом

- **WHEN** вызов содержит `mcp-tracker=jira-corp, mcp-repo=bb`
- **THEN** скилл работает ровно с этими серверами и не читает никаких файлов конфигурации

#### Scenario: одна роль — несколько MCP

- **WHEN** алиас роли перечисляет несколько серверов (`mcp-chat=telegram,whatsapp`)
- **THEN** скилл считает рабочими оба: чтение по всем, запись — куда названо заданием; не названо — один вопрос

#### Scenario: алиасы не названы, конвенция проекта есть

- **WHEN** задание не назвало алиасы, но конвенция проекта их содержит
- **THEN** алиасы берутся из конвенции без вопроса; источник отмечается в отчёте

#### Scenario: не хватает аргумента джобы

- **WHEN** задание просит запустить сборку, имя джобы не названо ни в задании, ни в конвенции
- **THEN** ci спрашивает у человека; перечисление джоб сервера не выполняется
