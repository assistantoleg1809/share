# Proposal

## Why

Три находки живых прогонов пользователя (2026-11-15): (1) скиллы базы
упоминают конкретные инструменты (bitbucket, mcp-jira/sonar/confluence)
— а инструменты бывают разными; (2) в песочницах/новых проектах нет
`permissions.allow` в settings — человек жмёт разрешения в терминале
на каждом шаге; (3) сессия e2869085: человек сказал «смержил», MCP
показывал OPEN — агент зелёнил слот и ушёл в сборку. Должно быть:
спросить в фазе pr, собирать ли на рабочей ветке; «да» → можно, слот в
плане — жёлтый (⚠), не зелёный.

## What Changes

- **Абстрактные алиасы в поставке**: pr/ci и kind-файлы говорят
  ролями («MCP трекера/вики/репозитория/сборки/деплоя/качества»),
  категория диагноза `sonar` → `quality`; конвенция проекта мапит роли
  на конкретные серверы (пример сценария в спеке — абстрактный).
- **permissions.allow**: сборщики песочниц (make_sandbox*.mjs) пишут
  `permissions.allow` в `.qwen/settings.json` (эталон — песочница
  пользователя GFeFOY); чек-лист адаптации docs — соответствующий пункт.
- **Статус PR — только из MCP**: слова человека — не статус; расхождение
  («смержил» vs OPEN) → вопрос в фазе pr: ждать MERGED или собирать на
  рабочей ветке; сборка на рабочей ветке — только по явному «да»;
  карточка запуска ci фиксирует ветку и её источник; такой слот в плане
  помечается ⚠ (жёлтый — успех на неподтверждённой базе), не зелёным.
