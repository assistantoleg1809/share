# Spec Delta

## MODIFIED Requirements

### Requirement: Три скилла-фазы с говорящими именами

Комплект MUST поставлять ровно три скилла: `task` — контекст задачи и
правки кода (спецификация изменения — опциональный путь), `pr` — рабочая ветка,
пуш, PR и цикл замечаний, `ci` — запуск и ожидание джоб CI с
диагностикой падений. Description каждого скилла MUST содержать только
«когда использовать» с триггерами вызова, без словаря конвейера.
Закрытый слот плана прогона MUST продолжаться следующим незакрытым
слотом **без остановки** (цепочка авторизована планом; паузы — только
🔒-гейты и вопросы правил; конец плана — стоп). Одиночный вызов скилла
человеком вне плана выполняется без цепочки. Тексты поставки MUST
обращаться к MCP по ролям (трекер, вики, репозиторий, сборка, деплой,
качество), не по именам конкретных продуктов; роли на серверы мапит
конвенция проекта.

#### Scenario: правка по тикету

- **WHEN** человек вызывает `/ship-kit:task возьми PRJ-42, mcp-трекер=tasks`
- **THEN** task собирает контекст, оформляет изменение (или правит напрямую — по весу задания), коммитит и сразу продолжает следующим слотом плана — `pr` с карточкой «пуш+PR»

#### Scenario: имя продаёт вызов

- **WHEN** человек читает description скилла, не открывая SKILL.md
- **THEN** из description понятно, какой скилл звать: «возьми задачу» → task, «отправь на ревью» → pr, «запусти сборку» → ci

#### Scenario: одиночный вызов вне плана

- **WHEN** человек зовёт один скилл для одиночного шага (например «проверь PR» или «дай лог»)
- **THEN** выполняется только этот вызов, цепочка не тянется

### Requirement: Состояние прогона — plan.md и issues.md

Межвызовное состояние прогона MUST жить в `skill-runs/<КЛЮЧ>/plan.md`:
чек-лист фаз (счётчик попыток — числом в строке), текущая фаза, журнал,
открытые вопросы. План создаётся при первом вызове фазы по ключу —
всегда, включая прогоны без внешних скиллов (слоты фаз комплекта по
умолчанию); слот `ci` открывается после MERGED PR. Статусы PR и джоб
MUST браться из свежих ответов MCP: слова человека — не статус; при
расхождении (человек говорит MERGED, MCP показывает OPEN) `pr` MUST
спросить: ждать MERGED или собрать на рабочей ветке; сборка на рабочей
ветке разрешена только после явного «да», и такой слот помечается в
плане **⚠ (жёлтым — успех на неподтверждённой базе)**, не зелёным.
Файл MUST быть токеном возобновления: после паузы скилл читает план,
сверяется с фактическим состоянием (git, статусы PR/джоб) и продолжает.
Провалы MUST фиксироваться задачами в `skill-runs/<КЛЮЧ>/issues.md`.

#### Scenario: возобновление после паузы

- **WHEN** человек возвращается с «продолжи PRJ-42»
- **THEN** скилл читает plan.md, сверяет фактическое состояние и продолжает с зафиксированной фазы, не переспрашивая сделанное

#### Scenario: слова против статуса

- **WHEN** человек говорит «смержил», а свежий get_pr показывает OPEN
- **THEN** pr не закрывает слот зелёным и спрашивает: ждать MERGED или собирать на рабочей ветке; при «да» карточка запуска ci фиксирует рабочую ветку и её источник, слот помечается ⚠
