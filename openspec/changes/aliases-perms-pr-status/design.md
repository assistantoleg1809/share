# Design

## Context

Сессии e2869085 (PR OPEN против слов «смержил» — агент зелёнил слот),
плюс требования: абстрактные алиасы (инструменты бывают разными) и
permissions.allow в песочницах (человек устал жать разрешения).

## Goals / Non-Goals

**Goals:** поставка говорит ролями, не брендами; песочницы не задают
вопросов терминала; слова человека не overriding свежий статус MCP —
расхождение решает вопрос в pr, сборка на рабочей ветке — осознанный
выбор с жёлтой пометкой плана. **Non-Goals:** автосинхронизация статуса
PR (опрос шину не строим — статус проверяется по ходу фазы pr).

## Decisions

1. **Роли**: трекер / вики / репозиторий / сборка / деплой / качество.
   Мапинг роль→сервер — конвенция проекта (файл проектов), комплект не
   знает брендов. Категория диагноза `sonar` переименована в `quality`
   (kind-файлы; смысл — гейт качества, не конкретный SonarQube).
2. **permissions.allow** — копия эталона пользователя (GFeFOY):
   Bash-паттерны (git checkout/log, openspec, node) + MCP-инструменты
   моков песочницы (чтение и запуск: 🔒-гейт kit остаётся единственным
   вопросом к человеку). Пишется сборщиками; docs чек-лист — пункт.
3. **Правило статуса**: перед продолжением на ci — свежий статус PR;
   расхождение → один вопрос в pr («ждать MERGED или собрать на рабочей
   ветке?»); «да» → ci запускается с веткой=рабочей (в карточке — ветка
   и источник решения), слот в плане ⚠. Зелёный — только MERGED-база.

## Risks / Trade-offs

- [flash перепутает роли без имён] → конвенция проекта перечисляет роли
  рядом с алиасами; kind-файлы говорят «MCP трекера» и т.п.
- [allow открывает слишком много] → состав = эталон пользователя;
  🔒-гейты kit не зависят от терминальных разрешений.

## Migration Plan

Тексты + сборщики + переустановка копии; откат — git revert.
