# Design

## Context

Находки ревью extensions/ship-kit 2026-11-20 (f1–f4, все Suggestion,
`.qwen/reviews/2026-11-20-extensions-ship-kit.md`); человек подтвердил
исправление всех («делать все»). См. proposal.md — Why.

## Goals / Non-Goals

**Goals:** закрыть четыре находки ревью минимальными правками; для f2 —
флэш-заточка (устранение двусмысленности «два набора скиллов»).

**Non-Goals:** расширение механики типов/гейтов; переписывание текстов.

## Decisions

1. **f1 закрывается дельтой, не прямой правкой спеки**: модифицированные
   требования «Порядок прогона» и «Ожидание мержа» попадают в мейн-спеку
   синком при архивации — тот же контракт, что у любого change; файлы
   комплекта уже консистентны (проверено ревью).
2. **f2 — одна строка в трёх точках + сценарий**: «перечень задания
   сильнее набора типа» зеркалит приоритеты spec-каскада («задание
   сильнее конвенции»); чек-лист п.2 остаётся единственным подтверждением
   — второго вопроса правило не вводит.
3. **f3 — перестановка, не переписывание**: фраза об отсутствующем alias
   склеивается, список «Роли алиасов» переносится после неё (образец —
   ci/SKILL.md, где правило цельным абзацем).
4. **f4 — нейтральная формулировка** «(git/<CLI спек-инструмента
   проекта>/node)»: чек-лист адаптации остаётся практичным, инвариант
   «имя не вшивается» восстановлен.
5. **Версия 2.4.0 → 2.5.0**: f2 меняет поведение Шага-0 (правило
   приоритета) — по дисциплине upgrade.md бамп + секция.

## Risks / Trade-offs

- [Описание требования «Типы задач и наборы» превысит 500 символов]
  → допустимо: MODIFIED-блоки и мейн-спека несут предупреждение о длине
  (прежний стиль спеки), strict-валидация дельты проходит по ADDED;
  сценарии держат поведение.

## Migration Plan

Бамп + секция upgrade.md. Откат — возврат текстов, проектного состояния
нет.
