# Proposal

## Why

При обновлении комплекта ship-kit (переустановка расширения) проектные
файлы, на которые он опирается (`.gitignore` `runs/`, `settings.json`
mcpServers/permissions, макрос `ship-kit.workflows.md`, конвейер-копии
`.qwen/skills`), отстают молча: прогон не знает версии комплекта и не
замечает подмены. Кейс: переход `skill-runs/` → `runs/` (runs-archive)
— проекты со старой адаптацией остались со старым `.gitignore` без
какого-либо сигнала.

Решение по исследованию `research/upgrade-config-sync/` (готовые
решения популярных проектов): паттерн Terraform-lock — версия
фиксируется в проекте, обновление обнаружимо; паттерн Angular/Nx —
рецепты/миграции едут в поставке.

## What Changes

- **Строка версии в плане**: `runs/<ПРОЕКТ>/<КЛЮЧ>/plan.md` хранит
  строку `ship-kit: <версия>` — из манифеста комплекта
  (`qwen-extension.json`); пишется при создании плана; легаси-план без
  строки дополняется при первом Шаге-0 `task`.
- **Сверка на Шаге-0 `task`**: строка плана сверяется с манифестом;
  расхождение — строка обновляется, в отчёт идёт одна строка
  «комплект обновился X → Y …» со ссылкой на рецепты. Правки проектных
  конфигов НЕ выполняются — синхронизация остаётся решением человека.
- **Рецепты `docs/upgrade.md`** (новый файл комплекта): по версиям —
  что меняется в проектных файлах; дисциплина: change комплекта,
  меняющий проектные ожидания или Шаг-0, бампает версию манифеста и
  добавляет секцию.
- Манифест: 2.0.0 → 2.1.0 (первый бамп по новой дисциплине; сам
  детектор — повод).
