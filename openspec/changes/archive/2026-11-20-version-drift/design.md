# Design

## Context

Обновление комплекта сегодня невидимо прогону: план не знает, какая
версия его создала. Исследование `research/upgrade-config-sync`
(2026-11-20): Terraform фиксирует версии провайдеров в lock-файле
проекта и печатает дифф с просьбой отревьюить; pre-commit хранит rev в
конфиге проекта; Angular/Nx везут миграции в поставке. Пользователь
согласился: детектор + рецепты сейчас; пофайловое применение под
гейтом (kubeadm/Rails) — отдельным change при необходимости;
минимизация проектного следа (husky/VS Code) — принцип на будущее.

## Goals / Non-Goals

**Goals:**

- Прогон знает версию комплекта; смена версии замечается и сообщается
  одной строкой в отчёте.
- Рецепты обновления едут в поставке (`docs/upgrade.md`) — источник
  правды для синхронизации человеком.

**Non-Goals:**

- Автоматические правки проектных конфигов (gitignore/settings/макрос/
  конвейер-копии) — паттерн kubeadm/Rails отдельным change, если
  детектора окажется мало.
- Сверка в `pr`/`ci`: план может создать любой скилл, но сверяет
  `task` — владелец полного Шага-0; прогоны из только-pr/ci живут без
  строки до первого task-вызова.
- История версий в плане: строка одна, перезаписывается; история — в
  git-истории plan.md.

## Decisions

1. **Источник версии — манифест комплекта.** Поле `version` в
   `qwen-extension.json` в корне комплекта — два уровня выше базового
   каталога скилла; относительный путь одинаков в dev-копии и
   установленной, поиска по ФС нет («ничего не искать» соблюдён).
   Хардкод версии в текстах отвергнут: забудут бампать. Манифест не
   читается — строка не пишется, пометка в отчёте (честно, без фейка).
2. **Строка — поле состояния, не журнал.** Одна строка
   `ship-kit: <версия>` рядом с текущей фазой; при дрейфе
   перезаписывается. Журнал не засоряется служебными записями.
3. **Сообщение о дрейфе — одна строка отчёта, не карточка.** Чтение
   манифеста — не действие, гейт не нужен. Правки конфигов не
   выполняются вовсе (Non-Goal) — карта «показать и спросить»
   (kubeadm/Rails) придёт отдельным change.
4. **Рецепты — текст в комплекте, дисциплина версий.** Change, меняющий
   проектные ожидания или Шаг-0, бампает minor манифеста и пишет
   секцию в `docs/upgrade.md`. Детектор без рецептов слеп, рецепты без
   детектора не находят адресата.
5. **Бамп 2.0.0 → 2.1.0 в этом change.** Первый прецедент дисциплины
   п.4; дрейф 2.0.0 → 2.1.0 — живой сценарий для существующих планов.

## Risks / Trade-offs

- [Манифест недоступен в экзотической установке] → мягкая деградация:
  строки нет, пометка в отчёте, работа продолжается.
- [Скилл прочитает чужой манифест] → путь строго относительный от
  базового каталога скилла, без поиска.
- [Забывают бампать/писать рецепты] → дисциплина закреплена в шапке
  upgrade.md; нарушение заметит сам детектор (дрейф без рецепта).

## Migration Plan

Правки `task/SKILL.md` (Шаг 0.2), QWEN.md, docs/ship-kit.md; новый
`docs/upgrade.md` (секции 2.1.0 и линия 2.0.0 с переходом
`skill-runs` → `runs`); манифест 2.1.0. Синк дельты при архивации;
копия переустанавливается.
