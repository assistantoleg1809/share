# Design — resume-plan-approval

## Context

См. proposal.md (Why). Текущее состояние: токен возобновления упомянут
в QWEN.md и в `pr` («продолжи PRJ-42» — скилл читает план и продолжает),
но: (а) фразы нет в триггерах description ни одного скилла — новая
сессия не обязана сопоставить её с комплектом; (б) алгоритм продолжения
не расписан (что показывает человеку, что вызывает сам, что делать при
сомнении); (в) отчёты фаз заканчиваются голой строкой `HANDOFF: pr` —
готовой фразы для копирования нет. Правило цепочки «закрытый слот →
следующий незакрытый без остановки» уже действует («Три скилла-фазы…»),
паузы разрешены на 🔒-гейтах и вопросах правил — на них и опираемся,
нового механизма не вводим.

## Goals / Non-Goals

**Goals:**

- Одна короткая фраза «продолжи <КЛЮЧ>» как единственный ручной вход в
  продолжение прогона; имена скиллов человек не печатает.
- Контроль человека сохранён: остаток плана утверждается, 🔒-карточки и
  пауза-ревью спеки остаются.
- Живой план: дописывание слотов и попыток без отдельных команд.

**Non-Goals:**

- Не меняем «Единица работы — фаза», механику гейтов, слоты, типы задач.
- Не делаем автопереходы между вызовами без участия человека: вход в
  продолжение — всегда фраза человека или выбор опции.
- Не переучиваем узкие resume-фразы pr/ci и не чиним автодополнение
  клиентов (это вне комплекта).
- examples/ (conveyor, demo-project) не синхронизируем с этим change'ом.

## Decisions

1. **Канонический вход — `task`, а не «любой скилл».** Триггер
   «продолжи <КЛЮЧ>» добавляется только в description `task`: он уже
   владеет Шаг-0 и сборкой плана. Альтернатива — дублировать триггер во
   всех трёх — отклонена: в новой сессии фраза должна детерминированно
   попадать на один скилл, а pr/ci получают остаток плана через вызов
   слота самим task. Узкие фразы pr/ci остаются.
2. **Подтверждение остатка — переиспользование правил гейтов.** Блок
   «остаток плана + одно подтверждение» оформляется вопросом с закрытыми
   опциями — тот же контракт, что у «подтверждения чек-листа плана» в
   «Гейтах необратимого»: согласие = выбор опции, текст вне опций — не
   подтверждение. Отдельного механизма или списка дословных фраз не
   вводим. Подтверждение остатка НЕ наследуется карточками: каждый пуш и
   запуск джобы спрашивается своей карточкой (запрет наследования уже в
   спеке).
3. **Внешние слоты вызывает сам task инструментом вызова скиллов.** Имена
   слотов лежат в плане (перечень задания / конвенция), комплект остаётся
   нейтральным к именам инструментов — имя исполнителя в файлах комплекта
   не упоминается, вызов идёт по имени из плана. Альтернатива «попросить
   человека набрать /<имя>» — исходная боль, отклонена.
4. **Пауза-ревью — только после слота `spec`.** Спека — единственный
   артефакт прогона, обязательный к человеческой проверке до продолжения
   (полный путь всегда); после остальных слотов цепочка идёт сама.
   Альтернатива «вопрос после каждого слота» отклонена как возвращение
   трения.
5. **Живой план без нового формата.** Дописывание слота тех-PR и рост
   счётчика попыток ×N — те же строки чек-листа; новое правило — только
   показывать дописывание на ближайшей карточке/вопросе. Формат plan.md
   не расширяется.
6. **Строка `ДАЛЬШЕ: продолжи <КЛЮЧ>` — в формате отчёта, не в контракте
   полей.** Добавляется в «Формат отчёта» каждого скилла после HANDOFF как
   условная строка (план не закрыт). Альтернатива «заменить HANDOFF»
   отклонена: HANDOFF несёт семантику следующей фазы, ДАЛЬШЕ — способ
   входа в неё.
7. **Скилл слота не загружен — вопрос, не стоп.** Жёсткий стоп
   заблокировал бы прогон навсегда при смене окружения; опция «пропустить
   с пометкой» сохраняет прогон живым, пометка не даёт потерять слот из
   вида.

## Risks / Trade-offs

- [Модель в новой сессии сопоставит «продолжи…» не с task] → триггер
  дословно в description + фраза в конце каждого отчёта (ДАЛЬШЕ) держит
  формулировку перед глазами; при промахе пользовательская фраза всё
  равно доезжает до скилла-получателя по узким триггерам.
- [Двойное подтверждение: остаток плана + карточка пуша подряд] →
  осознанный trade-off в пользу контроля; подтверждение остатка не
  наследуется карточками (решение 2), зато после него цепочка до конца
  плана больше не спрашивает ничего, кроме 🔒.
- [Разрастание плана дописанными слотами] → счётчик попыток и слоты
  тех-PR — короткие строки; журнал с датами уже ограничивает хаос.
- [Токен ДАЛЬШЕ устареет при переименовании ключа] → ключ неизменяем
  в рамках прогона (нет такой операции в комплекте).

## Migration Plan

Изменение текстовое (скиллы, QWEN.md, docs, манифест). Обновление
установленных копий — стандартной переустановкой расширения из репо;
рецепты — секция 2.7.0 в `docs/upgrade.md`: новых файлов нет, формат
plan.md совместим, действующие прогоны продолжаются по старым планам —
фраза «продолжи <КЛЮЧ>» начинает работать с любой существующей
каталогом `runs/<ПРОЕКТ>/<КЛЮЧ>/`. Откат — переустановка версии 2.6.0.
