# Proposal

## Why

База ship-kit 2.0.0 (task/pr/ci) описана спекой и схемами, но у комплекта
нет ни одного целевого проекта, на котором видно: откуда берутся данные
вызова (файл проектов), как выглядит живой прогон с карточками гейтов и
что происходит при падении деплоя. Коллегам и будущим проектам нужен
читаемый сквозной пример, а не абстракция.

## What Changes

- Новый каталог `examples/demo-project/` — самодостаточный учебный
  пример целевого проекта «calc» (Jira-ключ PRJ) для базы ship-kit,
  без реальных MCP: читаемый walkthrough с дословными примерами
  карточек и отчётов скиллов.
- **Файл проектов** `ship-kit.projects.md` — единственное место правды
  проекта (MCP-алиасы, джобы, стенды, ветки); агент читает его как
  обычный контекст проекта и **собирает аргументы вызова** — скиллы
  базы файл не читают и формат не вшит (позиция «ноль вшивания»
  сохранена).
- `ship-kit.workflows.md` — пример опционального макроса «feature»
  (типовой набор: openspec-спека → имплементация → ревью → слоты
  `/ship-kit:pr` и `/ship-kit:ci`).
- `repo/` — мини-репозиторий приложения (app.js, тест, локальный
  прогон, учебный CI-конфиг): правкам фиксов есть что править.
- `skill-runs/PRJ-777/{plan.md,issues.md}` — образцы состояния прогона:
  подтверждённый чек-лист с 🔒-строками, журнал с падением деплоя на
  стенде ST (infra) → issues.md + эскалация DevOps → «продолжи PRJ-777»
  → зелёные стенды.
- `INTERVIEW.md` — интервью-тест примера (вместо отложенных агентных
  тестов): 15 вопросов с эталонами и точные инструкции прохождения —
  режим «человек-коллега» и режим «модель» (один вопрос = один вызов
  glm-5.3-flash, отвечающий только по файлам примера).
- README — пошаговый сценарий: задание → аргументы из файла проектов →
  task (спека через **openspec-скиллы**, найденные discovery; TDD) →
  pr (карточка «пуш+PR») → ci (build зелёный, deploy: DEV ок, ST падает
  по infra, маршруты фикса из диаграммы деплоя) + таблица
  «строка файла проектов → аргумент вызова».

## Impact

- Добавляется `examples/demo-project/**` (пример, не поставка
  расширения; `extensions/ship-kit` не меняется).
- Ссылки README примера на базу — `ship-kit:task/pr/ci`; пересечений с
  `examples/conveyor` нет (тот — образец конвейера v2, этот — целевой
  проект базы).
- Поставку расширения, спеки и версии не трогаем.
