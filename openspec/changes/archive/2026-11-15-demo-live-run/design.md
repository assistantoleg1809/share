# Design

## Context

База 2.0.0 применена (65dab29), пример demo-project — текстовый (02fff2b).
Моки v2-стенда живы в `examples/conveyor/e2e/mcp/mock.mjs` (state-driven,
роли jira/jenkins/bitbucket/confluence; jenkins `results` по ключу
`job:STAND` — сценарные исходы; bitbucket `create_pr` auto-MERGE;
`jenkins_get_build` первый опрос RUNNING). Прогоны — только
glm-5.3-flash. Грабли вложенных сессий известны (headless, $version в
settings, скиллы читаются с диска установленной копии).

## Goals / Non-Goals

**Goals:** живой прогон кейса пользователя (5 шагов) реальными скиллами;
артефакты прогона в песочнице: `specs/PRJ-700-<название из jira>/`,
`skill-runs/PRJ-777/plan.md`, ветка+PR с фикс-коммитом, IFT #2 SUCCESS;
воспроизводимость — одной командой сборки песочницы + протокол вызовов.

**Non-Goals:** правки скиллов/спек базы; реальные MCP; INTERVIEW.md
(отложен пользователем); конвейер v2.

## Decisions

1. **Моки не расширяем кодом.** Родительская стори — поле в
   `jira.issues[]` state (get_issue отдаёт объект как есть); исходы
   деплоя — `jenkins.results['calc-app-deploy:IFT'] = ['FAIL_CODE',
   'SUCCESS']`; build — `['SUCCESS']`. Ноль правок mock.mjs.
2. **Конвенция спеки — в файле проектов сценария** (секция «Конвенции
   спеки»: стори по jira → `specs/<ключ стори>-<slug названия задачи>`),
   действует только для этого проекта: агент применяет её как контекст;
   скилл и комплект правила не знают («ноль вшивания»).
3. **Гейты — pre-approved дословными фразами** в заданиях («подтверждаю
   пуш и создание PR», «подтверждаю запуск …», включая повторный запуск
   после фикса; «порядок подтверждаю»): headless-вызов неинтерактивен,
   механика равносильна «да» по трём правилам гейтов, источник
   фиксируется в отчётах.
4. **Цепочка — отдельными headless-вызовами** (task → pr → ci → task
   fix → pr → ci): состояние между вызовами живёт в
   `skill-runs/PRJ-777/plan.md` — заодно проверяется токен
   возобновления. Фикс после MERGED PR-1 — новая ветка от main и новый
   PR-2 (правило «новый PR — только на новый фикс»; auto-merge мока
   делает его MERGED → перезапуск IFT).
5. **Песочница одноразовая** (`mktemp -d`), сборщик
   `make_sandbox.mjs`: копия repo/, git init main, сценарный
   `ship-kit.projects.md`, `.qwen/settings.json` с моками
   (MOCK_STATE → общий state-файл песочницы), сид `mcp-state.json`.
   Абсолютные пути моков — из расположения стенда.
6. **Протокол** `RUN.md`: дословные команды вызовов, ответы-контракты и
   вердикт приёмки по шагам кейса 1–5.

## Risks / Trade-offs

- [flash не соберёт аргументы из файла проектов сам] → в задании
  допустима подсказка «аргументы — из ship-kit.projects.md» (проверяет
  ли агент файл; шаг кейса 2), провал фиксируется в протоколе честно.
- [$version дописывается в settings песочницы] → песочница одноразовая.
- [Скиллы не подгрузятся во вложенной сессии] → смоук: первый вызов
  обязан позвать скилл; иначе стоп и разбор.
- [headless зависнет] → таймаут обёртки, повтор один.
