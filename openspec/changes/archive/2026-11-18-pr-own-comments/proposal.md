# Proposal

## Why

Две боли живых прогонов базы. (1) Слабая модель на шаге ожидания мержа
иногда пытается спросить у человека разрешение подождать, хотя спека уже
требует «без вопроса» — нужен явный императив в тексте скилла. (2) Когда
агент и человек (владелец ПК) пишут в PR под одной учёткой (один токен
MCP), поле «автор» не различает их: агент может ответить на собственный
комментарий, посчитать свой unresolved замечанием или потерять чужое.

## What Changes

- **Маркер своих комментариев**: каждый комментарий агента в PR
  (add_comment) завершается дословной строкой `[ship-kit]`; свои =
  с маркером, чужие = без. id своих комментариев фиксируются в журнале
  `skill-runs/<КЛЮЧ>/plan.md` — точная проверка поверх маркера.
- **Цикл замечаний — только чужие**: `fix` отвечает и пушит только по
  чужим (без маркера) комментариям; `check` считает unresolved только
  чужие; свои unresolved замечаниями не считаются.
- **Ожидание мержа — явный запрет вопроса** (решение по пункту 1,
  особенности слабой модели): шаг 5 и «Завершение фазы» pr/SKILL.md
  получают императив «разрешение на ожидание не спрашивается; первый
  опрос — сразу после создания PR».

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `base-skills`: MODIFIED «Ожидание мержа PR» (+1 сценарий «ожидание
  стартует сразу, без вопроса»); ADDED «Различение своих и чужих
  комментариев в PR» (маркер `[ship-kit]`, id-журнал плана, fix/check
  работают только с чужими).

## Impact

- `extensions/ship-kit/skills/pr/SKILL.md` — check, fix, шаг 5,
  «Завершение фазы».
- `extensions/ship-kit/docs/ship-kit.md` — одна фраза о маркере
  ответов агента.
- `openspec/specs/base-skills/spec.md` — синк дельты при архивации.
- Установленная копия `~/.qwen/extensions/ship-kit` — переустановка.
