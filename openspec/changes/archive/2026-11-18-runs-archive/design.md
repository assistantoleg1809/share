# Design

## Context

Боль из живого использования (пользователь, 2026-11-18): в каталоге
прогонов не видно проекта; `skill-runs` длинно; worktrees не связаны с
прогонами именем; завершённые прогоны и осиротевшие worktrees копятся.
Сегодня состояние живёт в `skill-runs/<КЛЮЧ>/{plan.md,issues.md}`
(требование «Состояние прогона»), worktree — «из задания, работай
строго внутри него».

## Goals / Non-Goals

**Goals:**

- Принадлежность прогона и worktree проекту видна из листинга ФС.
- Явная судьба завершённого прогона и его worktree (архив/удаление).

**Non-Goals:**

- Автоматическая миграция старых `skill-runs`-прогонов (легаси —
  только чтение при возобновлении).
- Удаление веток при архивации (ветки нужны PR/истории).
- Новый формат plan.md — меняется только путь и строка про worktree.

## Decisions

1. **`runs/<ПРОЕКТ>/<КЛЮЧ>/` — проект в пути.** Альтернатива «проект в
   шапке plan.md» отвергнута: не видна из листинга каталога, а боль
   именно в листинге. Двухуровневая вложенность достаточна, глубже не
   уходим.
2. **Источник `<ПРОЕКТ>`: конвенция > имя каталога репозитория.** Файл
   проектов называет проект явно; нет конвенции — имя каталога репо
   (cwd/клона) как бесплатный дефолт. Имя комплекта не фиксируется
   (принцип «конвенция без конфигурации»).
3. **Worktree — плоский слаг `<ПРОЕКТ>-<КЛЮЧ>`.** Нативные инструменты
   worktree плоские (`.qwen/worktrees/<slug>`); дефис-слаг совпадает с
   идентичностью прогона и читается из листинга. Worktree уже создан
   инструментом с другим именем — не ломаем: соответствие фиксируется
   в plan.md (строка «worktree: <путь>»).
4. **Удаление worktree — гейт; перенос — рабочая операция.** Удаление
   необратимо (объединяем с гейтовыми правилами: карточка/структурный
   вопрос, отказ ≠ стоп архивации — выбор только про worktree).
   Перенос `git worktree move` сохраняет регистрацию; удаление —
   `git worktree remove`. Ветки не трогаем.
5. **Архивация — по команде или предложению, не авто.** Закрытие плана
   — скилл предлагает архивацию (один вопрос); команда человека
   («архивируй прогон <КЛЮЧ>») работает всегда. Перенос каталога — mv,
   обратим.
6. **Легаси `skill-runs/` — чтение.** Возобновление проверяет оба
   места; новые — только `runs/`. Миграция — отдельной командой
   человека, если понадобится (не в этом change).

## Risks / Trade-offs

- [Разные источники имени проекта дадут разные каталоги для одного
  проекта] → правило разрешения одно (конвенция > каталог репо),
  фиксируется в journal плана при создании.
- [Каталог репо переименовали] → новый прогон попадёт в новый каталог;
  лечится конвенцией (файл проектов называет имя явно).
- [`git worktree move` не поддержан старым git] → git ≥2.17 повсеместно;
  при отказе — честная ошибка и ручной перенос в issues.md прогона.

## Migration Plan

Текстовые правки трёх скиллов, QWEN.md, docs (пути + предложение
архивации); чек-лист адаптации: `.gitignore: runs/`. Существующие
`skill-runs/` остаются на месте, читаются при возобновлении. Синк при
архивации; копия переустанавливается.
