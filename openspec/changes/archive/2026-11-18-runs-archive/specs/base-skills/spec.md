# Spec Delta

## MODIFIED Requirements

### Requirement: Состояние прогона — plan.md и issues.md

Межвызовное состояние прогона MUST жить в
`runs/<ПРОЕКТ>/<КЛЮЧ>/plan.md`: чек-лист фаз (счётчик попыток — числом
в строке), текущая фаза, журнал, открытые вопросы. `<ПРОЕКТ>`
разрешается из конвенции проекта (файл проектов), иначе — имя каталога
репозитория (cwd/клона); имя проекта комплектом не фиксируется. План
создаётся при первом вызове фазы по ключу — всегда, включая прогоны без
внешних скиллов (слоты фаз комплекта по умолчанию); слот `ci`
открывается после MERGED PR. Возобновление проверяет и легаси
`skill-runs/<КЛЮЧ>/` (только чтение, новые прогоны создаются только в
`runs/`). Статусы PR и джоб MUST браться из свежих ответов MCP: слова
человека — не статус; при расхождении (человек говорит MERGED, MCP
показывает OPEN) `pr` MUST спросить: ждать MERGED или собрать на рабочей
ветке; сборка на рабочей ветке разрешена только после явного «да», и
такой слот помечается в плане **⚠ (жёлтым — успех на неподтверждённой
базе)**, не зелёным. Файл MUST быть токеном возобновления: после паузы
скилл читает план, сверяется с фактическим состоянием (git, статусы
PR/джоб) и продолжает. Провалы MUST фиксироваться задачами в
`runs/<ПРОЕКТ>/<КЛЮЧ>/issues.md`.

#### Scenario: возобновление после паузы

- **WHEN** человек возвращается с «продолжи PRJ-42»
- **THEN** скилл читает plan.md, сверяет фактическое состояние и продолжает с зафиксированной фазы, не переспрашивая сделанное

#### Scenario: слова против статуса

- **WHEN** человек говорит «смержил», а свежий get_pr показывает OPEN
- **THEN** pr не закрывает слот зелёным и спрашивает: ждать MERGED или собирать на рабочей ветке; при «да» карточка запуска ci фиксирует рабочую ветку и её источник, слот помечается ⚠

#### Scenario: прогон привязан к проекту

- **WHEN** два проекта имеют прогон с одинаковым ключом X-1
- **THEN** прогоны лежат раздельно и узнаваемы из листинга: `runs/<проект1>/X-1/` и `runs/<проект2>/X-1/`

#### Scenario: легаси-каталог skill-runs

- **WHEN** план прогона существует только в старом `skill-runs/<КЛЮЧ>/plan.md`
- **THEN** возобновление читает его оттуда; новые записи и новые прогоны создаются только в `runs/<ПРОЕКТ>/<КЛЮЧ>/`

## ADDED Requirements

### Requirement: Архивация прогона и worktree

Завершённый прогон MUST архивироваться по команде человека
(«архивируй прогон <КЛЮЧ>») или по предложению при закрытии плана:
каталог переносится в `runs/archive/<ПРОЕКТ>/<КЛЮЧ>/`. Worktree
прогона — имя `<ПРОЕКТ>-<КЛЮЧ>`, соответствие в plan.md. Выбор
человека по worktree: удалить (гейт, ветки не трогаются) или
`git worktree move` в архив прогона; отказ от удаления архивацию не
отменяет.

#### Scenario: архивация с удалением worktree

- **WHEN** план закрыт, человек на вопрос о worktree выбрал «удалить» и подтвердил гейт
- **THEN** каталог прогона перенесён в `runs/archive/<ПРОЕКТ>/<КЛЮЧ>/`, worktree удалён (git worktree remove); ветки прогона остались

#### Scenario: worktree перенесён в архив

- **WHEN** человек отказался удалять worktree
- **THEN** архивация прогона продолжается, worktree перенесён внутрь архива прогона (git worktree move), регистрация worktree сохранена

#### Scenario: имена узнаваемы

- **WHEN** прогон создан и использует worktree
- **THEN** оба имени содержат проект и ключ: `runs/<ПРОЕКТ>/<КЛЮЧ>/` и worktree `<ПРОЕКТ>-<КЛЮЧ>` — принадлежность видна из листинга каталогов
