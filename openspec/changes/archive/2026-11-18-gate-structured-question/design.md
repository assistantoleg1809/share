# Design

## Context

Гейт «три правила» сегодня завершается шагом «явное "да"», которое модель
вычисляет из свободного текста человека. Исследование
`research/confirmation-gates/` (2026-11-18): Claude Code, Gemini CLI, Codex
и ACP проводят подтверждение необратимого структурированным выбором (кнопки
хоста), дословным правилом (exact match, deny wins) или вводом имени объекта
— трактовку свободного текста как согласия не доверяют никому. Решение
пользователя 2026-11-18: уровень 1 — структурный вопрос хоста.

## Goals / Non-Goals

**Goals:**

- Убрать модель из петли авторизации там, где хост даёт структурный вопрос:
  решение = выбранная опция.
- Нейтральность к имени инструмента (тот же принцип, что у инструмента
  спекирования): наличие определяется в рантайме.

**Non-Goals:**

- Exact-match список дословных affirmations для чисто-текстовых каналов
  (уровень 2 исследования) — отложено, не выбрано.
- Echo-nonce «да \<id\>» на карточке (уровень 3) — отложено.
- Информационные вопросы лесенки (alias-вопрос и т.п.) — не гейты, формат не
  регламентируется.
- Расширение контракта отчёта (новые строки) — источник подтверждения
  отмечается в теле отчёта как факт.

## Decisions

1. **Признак инструмента — способность, не имя.** «Инструмент вопроса с
   закрытыми опциями»: в Qwen Code — ask_user_question, в ACP-хостах —
   request_permission; скилл говорит о способности («вопрос с закрытыми
   опциями») и находит её по списку инструментов сессии. Альтернатива —
   вшить имя инструмента — отвергнута: нарушает нейтральность поставки
   (прецедент «инструмент спекирования не вшивается»).
2. **Согласие = ровно утвердительная опция.** Отказ-опция = стоп (действующее
   правило). Свободный текст (в т.ч. поле «Other») — не согласие и не отказ:
   ответить на содержание и один раз переспросить тем же инструментом;
   повторный не-выбор — стоп (default-deny из permission-правил больших).
3. **Охват — все подтверждения человека, не только три карточки.** Карточки
   пуш+PR / фикс-пуш / запуск джобы, подтверждение чек-листа плана в task,
   переспрос flaky-повтора в ci — один класс «вопрос-гейт». Единая
   формулировка в трёх скиллах, дублирование трёх строк дешевле слоя
   диспетчеризации (тот же размен, что у дисциплин верификации).
4. **Деградация без изменения правил.** Нет инструмента — текущий
   свободный текст («явное "да"», pre-approved дословной фразой) без
   правок: headless-прогоны e2e продолжают работать как раньше.
5. **Очередь apply.** `pr-wait-merged` применяется первым (создан раньше,
   ждёт подтверждения), этот change — вторым; оба правят `pr`/SKILL.md,
   текстовые правки второго накладываются на результат первого.

## Risks / Trade-offs

- [Хост без структурного вопроса — правило не работает] → деградация
  сохраняет сегодняшнее поведение; улучшение только там, где хост умеет.
- [Поле свободного ввода «Other» в руках нетерпеливого человека] → не
  согласие: переспрос один раз, затем стоп; человек видит закрытые опции и
  выбирает их.
- [Формулировка способности разъедется с будущими хостами] → текст говорит
  о поведении («закрытые опции, выбор = решение»), а не о конкретном
  протоколе.

## Migration Plan

Текстовые правки трёх SKILL.md + QWEN.md + docs; синк дельты при архивации;
переустановка копии. Откат — `git revert`.
