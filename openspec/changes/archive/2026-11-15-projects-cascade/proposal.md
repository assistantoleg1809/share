# Proposal

## Why

Команды расходятся в привычках: одним удобно держать файл проекта в
каждом репозитории, другим — один общий репозиторий с файлом проектов
всех команд. Текущая спека знает только «конвенцию проекта» как единый
контекст сессии и не отвечает, что делать при двух представлениях — а
без правила мастера ручные правки в обоих вернут спор о расхождениях.
Подтверждённое решение (2026-11-15): каскад с одним мастером —
репо-файл, центральный каталог — автособираемое зеркало.

## What Changes

- Лесенка аргументов получает средний ярус: конвенция проекта
  разрешается каскадом **файл проекта в репо (cwd) → центральный
  каталог проектов**, затем — один вопрос человеку.
- Роль мастера: запись проекта правится руками только в репо-файле;
  центральный каталог — автособираемый индекс, ручные правки запрещены.
- Коллизия одинаковых имён проектов: репо-файл побеждает; генератор
  индекса фиксирует дубликат как ошибку сборки индекса.
- Клон проекта: разрешённая запись называет репозиторий (SSH) и cwd не
  является этим репозиторием → `task` клонирует его в рабочую папку
  сессии и работает в клоне (авторизация — SSH-ключи машины; клон —
  локальное действие, не гейт).
- Поставка (скилл `task`, docs, QWEN) описывает каскад текстом;
  имя файла и формат записи по-прежнему не вшиты (инвариант «без
  конфигурации» сохраняется — каскад про источники конвенции, не про
  формат).
- Пример: `examples/central-catalog/` — центральный каталог с
  генератором индекса (сборка из репо-файлов, контроль дубликатов) и
  живой проверкой на `examples/demo-project`.

## Capabilities

### New Capabilities

(нет — поведение принадлежит базовому комплекту)

### Modified Capabilities

- `base-skills`: два новых требования к лесенке аргументов —
  «Каскад конвенции — репо-файл мастер, каталог индекс» (средний ярус
  лесенки: репо-файл → центральный каталог, ручные правки только
  в репо-файле, коллизия имён — в пользу репо-файла) и «Клон проекта
  из записи» (SSH-адрес записи → клон → работа в клоне).

## Impact

- `extensions/ship-kit/skills/task/SKILL.md` — Шаг-0: каскад
  разрешения конвенции + шаг клона.
- `extensions/ship-kit/docs/ship-kit.md` — раздел про файл проектов
  и каскад; строка в чек-листе адаптации.
- `extensions/ship-kit/QWEN.md` — строка инварианта про лесенку.
- `examples/central-catalog/` — новый пример (README, генератор
  `collect.mjs`, сгенерированный индекс).
- `examples/demo-project/README.md` — строка про клон в разделе
  данных вызова.
- Установка поставки: копия в `~/.qwen/extensions/ship-kit`
  переустанавливается (конвенция dev-режима).
