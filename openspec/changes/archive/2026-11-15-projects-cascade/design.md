# Design

## Context

Механизм файла проектов уже существует как конвенция примера
(`examples/demo-project/ship-kit.projects.md`): агент сессии читает
файл как контекст и подставляет значения в аргументы вызова; скиллы
базы файл не читают, формат не вшит (инвариант «Работа без
конфигурации проекта»). Решение пользователя 2026-11-15 («ок»): каскад
с мастером — см. proposal. Motivation — proposal.md.

## Goals / Non-Goals

**Goals:**

- Средний ярус лесенки: конвенция разрешается каскадом
  репо-файл (cwd) → центральный каталог.
- Мастер один: правки руками только в репо-файле; каталог —
  автособираемый индекс с контролем дубликатов.
- Клон проекта из записи (SSH) силами `task`, работа фаз в клоне.
- Живой пример центрального каталога с генератором и проверкой.

**Non-Goals:**

- Не вшиваем имя файла, формат записи и структуру каталога в поставку
  (пример показывает один из форматов, конвенция проекта может быть
  другой).
- Не строим генератор в поставке: он живёт в центральном репо
  организации (в нашем случае — пример).
- Не трогаем pr/ci SKILL.md: они работают в cwd, клон — шаг входа
  `task` (кто начал в клоне, тот и доставляет из клона).
- Не делаем автообновление индекса в рантайме скилла: скилл каталог
  только читает.

## Decisions

1. **Каскад как ярус лесенки, не новая сущность.** Лесенка
   «задание > конвенция > вопрос» уже в спеке; каскад уточняет ярус
   «конвенция» при нескольких источниках. Альтернатива — отдельный
   механизм разрешения «проекта» как объекта — отвергнута: плодила бы
   вторую лестницу рядом с первой.
2. **Мастер — репо-файл, каталог — индекс** (решение пользователя).
   Альтернатива «каталог мастер, репо-файлы — экспорт» отвергнута:
   клонирование репо не даёт конфигурацию, регистрация нового проекта
   требует доступа к общему репо, а каталог собирает SSH-адреса всех
   проектов (требует закрытого общего репо).
3. **Коллизия имён — репо-файл побеждает**, дубликат внутри каталога —
   ошибка сборки. Альтернатива «ошибка при любой коллизии» отвергнута:
   каталог по определению отстаёт от репо-файлов (собирается позже),
   репо-файл всегда свежее — он и правда.
4. **Клон — шаг Шага-0 `task`, не гейт.** Клон локален и обратим
   (удалить папку), не виден никому снаружи; гейт трёх правил — для
   необратимого. Транспортные повторы клона — по общему правилу
   (до 2, без вопросов).
5. **Генератор индекса — `collect.mjs` в примере.** Node без
   зависимостей (конвенция примеров — .mjs-скрипты, как
   `make_sandbox.mjs`): обход списка путей репо → чтение их файлов
   проектов → контроль уникальности имён → запись
   `projects.index.md` с маркером автогенерации и датой. Ошибка
   дубликата — ненулевой exit и список источников; индекс не пишется.
6. **Разрешение проекта по ключу задачи и имени.** Практика примера:
   ключ задач (PRJ) и имя проекта в записи; задание называет либо ключ
   («PRJ-777 …»), либо проект явно. Формат не вшит: агент сессии
   сопоставляет как читатель текста.

## Risks / Trade-offs

- [Каталог отстаёт от репо-файлов] → каскад читает каталог только
  когда репо-файла нет в cwd; коллизия — в пользу репо-файла;
  свежесть индекса — забота генератора, не скилла.
- [SSH-адреса в общем репо] → пример фиксирует: общий репо каталога
  закрытый (доступ только команды); чувствительное не шире репо-файлов.
- [Скилл не должен «искать»] → запрет сканирования сохраняется: чтение
  только двух названных источников (репо-файл cwd, каталог из
  конвенции задания), никакого перебора путей.
- [Дубликаты прорастают в индекс] → генератор атомарен: ошибка = индекс
  не обновляется; свежий индекс всегда либо валиден, либо отсутствует.

## Migration Plan

Роллаут текстовый: правки SKILL.md/docs/QWEN примера не ломают
существующие прогоны (без второго источника каскад не активируется).
Откат — реверт коммита; генератор примера не участвует в поставке.
