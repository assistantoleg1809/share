# Proposal

## Why

Детектор дрейфа версии (введён 2.1.0 по итогам `research/upgrade-config-sync/`,
паттерн Terraform-lock) не окупился: за пять бампов 2.1.0→2.5.0 ни одна секция
`docs/upgrade.md` не потребовала обязательного действия в проекте — детектор
срабатывал бы вхолостую. Читатель `plan.md` — LLM, толерантное чтение уже
штатный механизм комплекта для легаси (журналы без дат, `skill-runs/`), а
версионные маркеры обслуживают строгих парсеров. В популярной экосистеме
скиллов рантайм-детектора дрейфа нет ни у кого; ближайший паттерн
(superpowers «Skills evolve. Read current version») решает противоположно.
Продюсер и потребитель комплекта — одно лицо: уведомление «комплект
обновился» не сообщает нового. Решение человека 2026-11-21 (эксплор,
вариант B): детектор убрать, changelog оставить.

## What Changes

- **REMOVED** требование «Детектор дрейфа версии комплекта»: план прогона
  больше не хранит строку `ship-kit: <версия>`, Шаг-0 `task` не сверяет
  план с манифестом и не читает манифест.
- `extensions/ship-kit/skills/task/SKILL.md` — удалить блок
  «Версия комплекта» (~строки 70–77).
- `extensions/ship-kit/QWEN.md` — «Состояние прогона»: убрать строку
  версии и сверку из инварианта.
- `extensions/ship-kit/docs/ship-kit.md` — убрать описание сверки (п.74,
  118–119); upgrade.md описать как changelog для чтения при переустановке.
- `extensions/ship-kit/docs/upgrade.md` — шапка без детектора (рецепты
  читаются человеком при переустановке комплекта), секция 2.6.0.
- `qwen-extension.json` — 2.5.0 → 2.6.0 (дисциплина: change меняет
  поведение Шага-0 → бамп + секция; дисциплина сохраняется).
- Легаси-планы со строкой `ship-kit: <версия>` — толерантное чтение:
  строка игнорируется и не переписывается, сообщений нет.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `base-skills`: требование «Детектор дрейфа версии комплекта» удаляется
  (REMOVED, 4 сценария); план прогона перестаёт быть носителем версии
  комплекта. Поле `version` манифеста и `docs/upgrade.md` остаются
  changelog'ом вне спеки — это не поведение прогона.

## Impact

- `extensions/ship-kit/`: `skills/task/SKILL.md`, `QWEN.md`,
  `docs/ship-kit.md`, `docs/upgrade.md`, `qwen-extension.json`. `pr`/`ci`
  не затронуты (механизм жил только в `task`).
- Спека `base-skills`: 22 → 21 требование.
- Поведение: Шаг-0 `task` короче (нет чтения манифеста и процедуры
  дрейфа); существующие планы читаются как есть; при переустановке
  комплекта рецепты по-прежнему доступны человеку в `docs/upgrade.md`.
