# Design

## Context

Кейс-2 (сессии 23012ed4, c114f661): минимальный промпт → вопрос про
MCP при существующей конвенции; спека пропущена при конвенции
openspec. Лесенка «порядка прогона» уже трёхступенчатая — переносим
её на аргументы и спеку.

## Goals / Non-Goals

**Goals:** одна лесенка во всех правилах; права конвенции проекта
(аргументы, обязательность спеки, инструмент) — машинные, без слов в
задании. **Non-Goals:** изменение гейтов/границ; введение формата
конвенции в комплекте; правки примеров кроме сида кейса-2.

## Decisions

1. **Средняя ступень — «конвенция проекта», не «файл проектов».**
   Формулировка спеки не называет ни имени, ни формата файла:
   конвенция — любой проектный контекст сессии. «Ноль вшивания» цел.
2. **Спека: конвенция сильнее храповика, слабее задания.** Проект
   может запретить лёгкий путь; человек в задании может его вернуть.
3. **Скиллы читают конвенцию как контекст** (не как конфигурацию):
   тексты Шага-0 заменяют двухступенчатое правило на лесенку; у ci
   цепочка источников карточки дополняется ступенью конвенции.
4. **Сопутствующее (вне базовых текстов):** конвенция песочницы-2
   дописывается («спека обязательна», «аргументы берутся из файла —
   называть в задании не нужно»); make_sandbox2 создаёт минимальный
   openspec-корень (config+project.md — эквивалент init, без
   интерактива); мок объявляет настоящие inputSchema (get_issue
   принимает ключ — находка транскрипта).

## Risks / Trade-offs

- [«Конвенция» размывает «без конфигурации»] → спека требует: комплект
  не требует и не фиксирует формат; без конвенции поведение прежнее.
- [flash перепутает конвенцию с реестром] → тексты говорят «обычный
  контекст сессии», без слова-«реестр».
