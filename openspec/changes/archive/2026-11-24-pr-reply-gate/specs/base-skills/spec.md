# Spec Delta

## ADDED Requirements

### Requirement: Карточка фикса — подтверждение ответов и пуша

Цикл фикса замечаний (ответы add_comment + пуш в ту же ветку +
resolve закрытых) MUST гейтиться одной карточкой-превью: черновики
ответов на каждый чужой комментарий, ветка, коммиты, закрываемые
замечания. Отправка ответов и пуш выполняются только после явного
«да» по правилам «Гейты необратимого — три правила»; пуш не удался —
стоп, resolve не отмечается. Ответы на свои комментарии (id-журнал
плана прогона) не пишутся и в карточку не входят.

#### Scenario: карточка фикса с черновиками

- **WHEN** fix готовит цикл фикса: два чужих замечания, коммит фикса в ветке PR
- **THEN** карточка показывает черновик ответа на каждый чужой комментарий, ветку, коммиты, закрываемые замечания; после «да» отправляются ответы (add_comment), пуш, resolve закрытых

#### Scenario: отказ останавливает цикл

- **WHEN** человек ответил на карточку фикса отказом
- **THEN** ни один ответ не отправляется, пуша нет, resolve не ставится; стоп без перебора

#### Scenario: пуш не удался после отправки ответов

- **WHEN** после «да» ответы отправлены, пуш упал (транспортные повторы исчерпаны)
- **THEN** стоп с ошибкой, resolve не отмечается; id отправленных ответов уже в журнале плана, повтор цикла — новой карточкой

### Requirement: Игнорируемые авторы комментариев

Комментарии авторов из списка игнорирования (агенты-ревьюеры, боты)
MUST не считаться замечаниями: `check` не включает их в счёт замечаний
и unresolved, `fix` не отвечает на них и не помечает resolve. Список
MUST собираться объединением: задание (`ignore-authors=<автор1,автор2>`)
+ конвенция проекта; совпадение автора — дословное (без масок и
регистронезависимости). Пустой список — никто не игнорируется, вопрос
человеку не задаётся.

#### Scenario: список из задания

- **WHEN** задание передало `ignore-authors=review-bot`, в PR есть unresolved-комментарий автора review-bot
- **THEN** `check` не включает его в счёт замечаний, `fix` не отвечает на него и не помечает resolve

#### Scenario: объединение с конвенцией

- **WHEN** конвенция проекта называет агентов-ревьюеров, задание молчит о них
- **THEN** их комментарии игнорируются так же, как заданные заданием; списки задания и конвенции складываются

#### Scenario: пустой список

- **WHEN** ни задание, ни конвенция не назвали авторов
- **THEN** никто не игнорируется: все чужие комментарии (не из id-журнала) — замечания; вопрос человеку не задаётся

#### Scenario: дословное совпадение

- **WHEN** автор комментария «Review-Bot», а в списке «review-bot»
- **THEN** автор не совпадает дословно — комментарий считается замечанием по общим правилам

## MODIFIED Requirements

### Requirement: Гейты необратимого — три правила

Необратимые действия — пуш ветки, создание PR, запуск джобы,
отправка ответов на комментарии PR — MUST оформляться тремя
правилами: (1) карточка-превью (действие, ветка, параметры)
показывается человеку до применения; (2) применение — только после
явного «да»; отказ = стоп без перебора альтернатив; (3) дословное
«подтверждаю …» в задании равносильно подтверждению (pre-approved).
Семантика наследования подтверждений между карточками MUST NOT
использоваться. Когда в сессии доступен инструмент вопроса с
закрытыми опциями, вопрос-гейт (карточка, подтверждение чек-листа
плана, переспрос повтора) MUST задаваться этим инструментом:
согласие = выбор утвердительной опции, отказ = выбор опции отказа;
ответ свободным текстом вне опций подтверждением не считается —
ответь на содержание и переспроси один раз тем же инструментом,
затем стоп. Имя инструмента комплектом не фиксируется. Инструмента
в сессии нет — действует текстовый канал: подтверждением MUST
считаться только дословная фраза закрытого списка — **«да», «ок»,
«подтверждаю», «подтверждаю \<действие карточки\>»** (совпадение —
ответ целиком; часть фразы или фраза с добавками — не
подтверждение); отказом — **«нет», «стоп»**; любой другой текст
решением не является: ответь на содержание и переспроси один раз,
затем стоп (default-deny).

#### Scenario: карточка и подтверждение

- **WHEN** pr подготовил пуш ветки и создание PR
- **THEN** человеку показывается карточка с веткой, числом коммитов и целевой веткой; пуш выполняется только после явного «да»

#### Scenario: отказ останавливает

- **WHEN** человек ответил на карточку отказом
- **THEN** скилл останавливается с честным итогом и не предлагает альтернативные действия самовольно

#### Scenario: pre-approved дословной фразой

- **WHEN** задание содержит дословное «подтверждаю запуск сборки PRJ-42»
- **THEN** ci запускает джобу без повторного вопроса, отметив источник подтверждения в отчёте

#### Scenario: гейт спрашивается структурным вопросом

- **WHEN** в сессии доступен инструмент вопроса с закрытыми опциями и pr показывает карточку «пуш+PR»
- **THEN** карточка задаётся этим инструментом; выбор утвердительной опции выполняет действие, выбор опции отказа останавливает фазу; свободный текст человека в ответ не трактуется как согласие

#### Scenario: текст вне опций — не подтверждение

- **WHEN** человек ответил текстом вне утвердительной опции (поле свободного ввода), без выбора опции
- **THEN** действие не выполняется: скилл отвечает на содержание ответа и один раз переспрашивает карточку тем же инструментом; повторный не-выбор опции — стоп

#### Scenario: текстовый канал — дословное «ок»

- **WHEN** headless-прогон без инструмента закрытых опций, человек ответил на карточку пуша дословным «ок»
- **THEN** это подтверждение: пуш выполняется, источник (текстовый канал, фраза списка) отмечается в отчёте

#### Scenario: текстовый канал — расплывчатая фраза не подтверждение

- **WHEN** headless-прогон без инструмента закрытых опций, человек ответил на карточку запуска «сделай как считаешь нужным»
- **THEN** это не подтверждение и не отказ: скилл отвечает на содержание и один раз переспрашивает карточку; повторная расплывчатая фраза — стоп без запуска

#### Scenario: текстовый канал — совпадение частью фразы

- **WHEN** headless-прогон без инструмента закрытых опций, человек ответил на карточку пуша «ну да, наверное»
- **THEN** это не подтверждение: совпадение со списком только частью фразы не считается (ответ читается целиком) — переспрос один раз, затем стоп без пуша

#### Scenario: инструмент вопроса недоступен

- **WHEN** сессия идёт без инструмента закрытых опций (headless-прогон, чисто текстовый канал)
- **THEN** гейт работает по правилам текстового канала: дословные фразы закрытого списка, прочее — переспрос один раз, затем стоп

### Requirement: Различение своих и чужих комментариев в PR

Когда агент и человек пишут в один PR под одной учёткой (одно имя
автора у комментариев), `pr` MUST различать своих и чужих по
id-журналу плана прогона: id каждого отправленного комментария
фиксируется в журнале (запись с даты и времени). Служебные подписи
и маркеры в текст комментария добавляться MUST NOT. Цикл замечаний
(fix) и подсчёт unresolved (check) MUST работать только с чужими
комментариями: свои (id из журнала) замечаниями не считаются,
ответы на свои комментарии не пишутся.

#### Scenario: подпись своего комментария

- **WHEN** pr отправляет ответ на замечание ревью (add_comment) после «да» на карточку фикса
- **THEN** id комментария заносится в журнал плана прогона; служебной подписи в тексте комментария нет

#### Scenario: свой unresolved — не замечание

- **WHEN** в PR есть unresolved-комментарий, чей id есть в id-журнале прогона
- **THEN** `check` не включает его в счёт замечаний, `fix` не отвечает на него и не пушит по нему фикс

#### Scenario: чужой unresolved — замечание

- **WHEN** в PR есть unresolved-комментарий, чей id отсутствует в id-журнале прогона
- **THEN** это замечание: `check` показывает его в числе замечаний, `fix` отвечает на него и доставляет правку по действующим правилам
