# Design

## Context

См. proposal.md — Why. Текущее состояние: `fix` в pr отправляет
ответы (add_comment) без гейта, пуш фикса гейтится отдельной
карточкой; каждый комментарий агента подписан маркером `[ship-kit]`,
id продублированы в журнале плана. Схема flow.html (артефакт
заархивированного change resume-plan-approval) показывает цепочку
плана со слотом archive.

## Goals / Non-Goals

**Goals:**

- ответы на замечания — под подтверждением, одной карточкой на цикл фикса;
- убрать подпись `[ship-kit]` из комментариев, сохранив различение своих/чужих;
- схема flow.html: короче, цепочка плана без archive, виден цикл замечаний PR.

**Non-Goals:**

- не меняем правила ожидания MERGED, тех-PR, маршрут фикса CI;
- не трогаем эталон example-plan.md (слот archive в нём — см. Risks);
- resolve_comment отдельной карточкой не гейтится — остаётся хвостом подтверждённого цикла.

## Decisions

1. **Одна карточка фикса (ответы + пуш + resolve), не отдельная
   карточка ответов.** Прецедент — «пуш+PR одной карточкой»: близкие
   необратимые действия одного смыслового шага идут одним
   подтверждением; черновики ответов и коммиты фикса описывают одно
   и то же изменение. Альтернатива — два гейта на цикл — отклонена:
   удваивает прерывания без новой информации для человека.
2. **Маркер убран, id-журнал — единственный механизм.** Журнал
   ведётся с pr-own-comments, маркер был дублирующим следом в чужом
   PR. Отказ от подписи не меняет поведение fix/check: фильтр «не из
   id-журнала» уже прописан. Альтернатива — оставить маркер страховкой
   на случай потери журнала — отклонена: план прогона — обязательное
   состояние, его потеря ломает прогон целиком, подпись не спасает.
3. **Порядок после «да» сохранён**: ответы → пуш → resolve; пуш не
   удался — стоп, resolve не отмечается (id отправленных ответов уже
   в журнале, повтор цикла — новой карточкой).
4. **flow.html правился там, где жил** (артефакт change'а
   resume-plan-approval), затем по решению человека оба документа
   переехали в корень репо: `example-plan.md` и `flow.html` —
   документы воркспейса разработки, в поставку эталона
   (`extensions/ship-kit/`) не входят. Заголовок обобщён до схемы
   ship-kit. Цепочка плана:
   propose → pr 🔒 → apply → pr 🔒 → ci 🔒; отдельный блок «жизнь PR»
   с циклом замечаний и карточкой фикса.
5. **Игнорируемые авторы — объединение задания и конвенции.** Список
   агентов-ревьюеров постоянный для проекта — место ему в конвенции;
   разовое расширение — аргумент задания `ignore-authors=<…>`;
   списки складываются. Совпадение автора дословное — как у меток
   слотов: предсказуемо и тестируемо. Альтернатива — эвристика
   «ботоподобных» авторов с вопросом — отклонена: ненадёжно, список
   держит человек.
6. **Правило «archive (не) входит в план» в скиллы не вносится.**
   Состав плана — настройка проекта (задание/конвенция): схема
   flow.html и эталон example-plan.md показывают один пример без
   archive-слотов, но комплект не запрещает проекту поставить такой
   слот. Категоричная пометка из схемы убрана, эталон выровнен.

## Risks / Trade-offs

- [Состав плана зависит от проекта, а схема показывает один пример] →
  flow.html помечен как пример одного проекта, категоричная пометка
  «архивация в план не входит» убрана; правило в скиллы не вносится,
  эталон example-plan.md выровнен (archive-слоты убраны).
- [Комментарии агента из другого прогона без маркера считаются
  чужими замечаниями] → так было и с маркером: маркер не различал
  прогоны; id-журнал своего плана в контуре достаточен.

## Migration Plan

Текстовая правка, миграции нет: действующие прогоны продолжаются
фразой «продолжи <КЛЮЧ>»; легаси-комментарии с маркером покрыты
своими id из журнала. Версия комплекта 2.7.0 → 2.8.0, секция в
docs/upgrade.md. Откат — реверт коммитов.
