# Design

## Context

Механизм жил только в `task` (Шаг-0) и описывался тремя текстами комплекта
(`skills/task/SKILL.md`, `QWEN.md`, `docs/ship-kit.md`) + шапкой
`docs/upgrade.md`; спека — требование «Детектор дрейфа версии комплекта»
(base-skills:554). `pr`/`ci` механизма не касались. Мотивация удаления —
proposal.md (Why); вариант выбран человеком (B из эксплора 2026-11-21).

## Goals / Non-Goals

**Goals:**
- Убрать рантайм-механику: строку версии в plan.md, чтение манифеста и
  сверку на Шаге-0, процедуру «манифест не читается».
- Сохранить changelog: поле `version` манифеста и `docs/upgrade.md` с
  дисциплиной «меняющий change бампает версию и пишет секцию».

**Non-Goals:**
- Не трогаем легаси-планы: строки `ship-kit: <версия>` в существующих
  планах не чистим и не переписываем.
- Не меняем `pr`/`ci`, спека «Состояние прогона» не правится (строку
  версии не упоминает).

## Decisions

1. **Полное удаление процедуры из task, не ослабление** (альтернативы A
   «оставить» и C «снять вместе с upgrade.md» взвешены в эксплоре; B).
2. **Легаси-планы — толерантное чтение**: строка игнорируется, не
   переписывается, сообщений нет — зеркалит контракт «легаси-журнал без
   дат читается как есть». Альтернатива «дописывать/чистить строку при
   возобновлении» отвергнута: переписывание легаси стилем комплекта
   запрещено, а чистка — работа без адресата.
3. **Манифест и upgrade.md остаются changelog'ом**: точка чтения
   рецептов — переустановка комплекта (реальный сценарий: копии
   `.qwen/skills`, конвейер), а не взятие паузы в прогоне. Дисциплина
   бампа сохраняется: этот change меняет поведение Шага-0 → 2.6.0 +
   секция.
4. **Спека — чистый REMOVED без MODIFIED «Состояния прогона»**: после
   удаления требование исчезает (22 → 21), контракт легаси-чтения
   зафиксирован в Migration-поле REMOVED. Отдельный ADDED-сценарий про
   игнорирование строки не вводим — общий принцип толерантного чтения
   легаси в спеке уже есть.

## Risks / Trade-offs

- [Человек пропустит смену поведения Шага-0 при переустановке] →
  секция 2.6.0 в upgrade.md; новое поведение строго проще старого,
  деградации нет.
- [Строка версии в старых планах выглядит осиротевшей] → безвредна,
  контракт игнорирования задокументирован в Migration.
- [Детектор понадобился бы будущему «далёкому» потребителю] → сценарий
  закрывается чтением upgrade.md при переустановке; возврат детектора —
  отдельный change при появлении реальных данных.

## Migration Plan

Правки текстов + бамп манифеста 2.6.0 + секция upgrade.md. Откат —
revert текстов: состояние для механизма не требовалось, планы без строки
версии валидны и в 2.5.0 (легаси-сценарий существовал с самого 2.1.0).
