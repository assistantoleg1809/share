# Proposal

## Why

Отправка ответов на замечания ревью (add_comment) — такое же
необратимое действие в чужом PR, как пуш и запуск джобы, но шла без
подтверждения: человек впервые видел текст ответа уже отправленным.
Подпись `[ship-kit]` в конце каждого комментария агента оказалась
лишней — свои комментарии и так распознаются по id-журналу плана.
Замечания приходят и от агентов-ревьюеров (ботов) — отвечать на них
не нужно, нужен список игнорируемых авторов. Схема вызовов flow.html
перегружена словами, не показывала цикл замечаний, а цепочка плана
включала archive-слоты примера, которых в эталоне быть не должно
(состав плана — свой у каждого проекта, правилом комплекта это не
делается).

## What Changes

- Цикл фикса замечаний гейтится **одной карточкой фикса**: черновики
  ответов на каждый чужой комментарий + ветка + коммиты + закрываемые
  замечания; после «да» — ответы (add_comment), пуш, resolve
  закрытых. Отказ = стоп без отправки и пуша.
- Ответы на комментарии вошли в перечень необратимых действий
  («Гейты необратимого — три правила»).
- Маркер `[ship-kit]` убран: свои/чужие — только по id-журналу плана
  прогона; служебных подписей в тексте комментария больше нет.
- Комментарии игнорируемых авторов (агенты-ревьюеры) не считаются
  замечаниями: `check` не считает, `fix` не отвечает и не resolve'ит;
  список — задание (`ignore-authors=<автор1,автор2>`) + конвенция
  проекта, объединение, совпадение дословное; пусто — никто.
- Схема и эталон: категоричная пометка «архивация в план не входит»
  убрана из flow.html (состав плана — настройка проекта, не скилла;
  схема помечена как пример одного проекта), archive-слоты убраны из
  example-plan.md.
- flow.html: из цепочки плана убран `pr 🔒 → archive`; схема
  переработана — меньше слов, отдельная ветка «жизнь PR» с циклом
  замечаний и карточкой фикса.

  resume-plan-approval по решению человека): правка схемы и эталона.

  маркером в открытых прогонах покрыты своими же id из журнала;
  действий в проектах не требуется.
