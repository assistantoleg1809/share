# Design

## Context

База 2.0.0 применена (65dab29) и заархивирована (08f90ea); мейн-спека
`base-skills` (12 требований). Схемы падений build/deploy показаны
mermaid в сессии, но не материализованы. Пользователь попросил пример
целевого проекта: данные вызова — из файла проектов, спека — openspec-
скиллами. Изменение — чистый пример (`skip_specs: true`): поведение
базы не меняется.

## Goals / Non-Goals

**Goals:** один читаемый прогон PRJ-777 от задания до зелёных стендов,
с файлом проектов как источником аргументов, дословными карточками/
отчётами и падением деплоя ровно по диаграмме (infra → issues.md →
эскалация → повтор по «продолжи»).

**Non-Goals:** рабочие MCP-моки и e2e (тесты отложены до ~2 недель
использования); изменения скиллов, спек или поставки; конвейер v2
(его образец — examples/conveyor).

## Decisions

1. **Файл проектов — контекст проекта, не конфигурация комплекта.**
   `ship-kit.projects.md` лежит в целевом проекте; агент читает его в
   сессии и подставляет значения в аргументы вызова. Скиллы базы файл
   не читают, формат нигде не вшит — соответствует требованиям
   base-skills («работа без конфигурации», «инструмент не вшивается»).
   README фиксирует таблицу «строка файла → аргумент».
2. **Спека — openspec-скиллы, найденные discovery.** В walkthrough
   task находит в списке скиллов openspec-propose (description про
   оформление изменения) и зовёт его; в демо-проекте это отражено
   командой и результатом, без исполнения.
3. **Сценарий один, сквозной.** PRJ-777 «экспорт CSV»: чек-лист
   порядка (макрос «feature») → task (openspec-спека + TDD в repo/) →
   pr (карточка, PR-1) → ci build #114 SUCCESS → deploy DEV #57 ок →
   deploy ST #23 FAILURE (infra, агент) → диагноз по kind-файлу
   deploy.md (тикет DEVOPS-311, runbook) → fixable: false → issues.md
   + эскалация → «продолжи PRJ-777» → ST #24, IFT #9, PSI #6 — зелёные.
   План и issues в skill-runs/ соответствуют журналу дословно.
4. **repo/ минимально, но исполняемо.** app.js + app.test.js + test.sh
   (зелёный локальный прогон) — TDD-шаг walkthrough воспроизводим
   руками; Jenkinsfile — декоративная иллюстрация CI.

## Risks / Trade-offs

- [Пример устареет при эволюции базы] → README: «соответствие — на
  момент коммита»; ссылки только на имена ship-kit:task/pr/ci.
- [Перепутают с образцом конвейера v2] → первый абзац README: это
  целевой проект базы; конвейер — ../conveyor.
