# Proposal

## Why

Живые прогоны кейса-2 (сессии пользователя 2026-11-15) вскрыли разрыв
лесенки приоритетов: у «порядка прогона» три ступени (задание >
конвенция проекта > вопрос), а у «аргументов вызова» и «спеки» — две.
Следствия: минимальный промпт `/ship-kit:task SDF-1` породил вопрос
«какие MCP использовать», хотя алиасы лежали в файле проектов; задача
PRJ-888 ушла в лёгкий путь без спеки, хотя проект работает через
openspec. Человек не должен повторять правила проекта в каждом
задании.

## What Changes

- **MODIFIED** `base-skills` / «Работа без конфигурации проекта»:
  аргументы (алиасы, джобы, стенды, ветки) разрешаются лесенкой
  **задание > конвенция проекта > один вопрос**; конвенция — обычный
  контекст сессии (файлы проекта), комплект по-прежнему не требует и
  не фиксирует ни имени, ни формата.
- **MODIFIED** `base-skills` / «Инструмент спекирования не вшивается»:
  конвенция проекта сильнее умолчания скилла — может **обязывать
  спецификацию** (полный путь всегда) и называть инструмент; задание
  сильнее конвенции.
- Тексты трёх скиллов (`task`, `pr`, `ci`) синхронизируются с лесенкой
  (Шаг-0 MCP; Шаг-0.3 спеки; цепочка источников карточки запуска);
  QWEN.md и docs/ship-kit.md — одна строка каждая.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `base-skills`: два требования получают среднюю ступень «конвенция
  проекта» (аргументы; обязательность спеки) + по новому сценарию.

## Impact

- `extensions/ship-kit/skills/{task,pr,ci}/SKILL.md`, `QWEN.md`,
  `docs/ship-kit.md`; установленная копия переустанавливается.
- Проекты без конвенции: поведение не меняется (вопрос / храповик —
  как раньше). «Ноль вшивания» сохранён: формат и имя файла конвенции
  нигде в комплекте не зафиксированы.
