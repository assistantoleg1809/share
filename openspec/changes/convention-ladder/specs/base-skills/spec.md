# Spec Delta

## MODIFIED Requirements

### Requirement: Работа без конфигурации проекта

Всё необходимое скиллы получают аргументами вызова: MCP-алиасы, имена
джоб, стенды, ветки. Аргументы MUST разрешаться лесенкой: **задание >
конвенция проекта > один вопрос человеку**. Конвенция проекта —
обычный контекст сессии (файлы проекта, например файл проектов);
комплект MUST NOT требовать её, фиксировать имя или формат. После
конвенции недостающее скилл MUST запросить у человека. Комплект MUST
NOT требовать реестра, манифеста или иного файла конфигурации.
Сканирование серверов и перебор джоб/путей («поиск») запрещён.

#### Scenario: алиасы переданы вызовом

- **WHEN** вызов содержит `mcp-jira=jira-corp, mcp-bitbucket=bb`
- **THEN** скилл работает ровно с этими серверами и не читает никаких файлов конфигурации

#### Scenario: алиасы не названы, конвенция проекта есть

- **WHEN** задание не назвало алиасы, но конвенция проекта их содержит
- **THEN** алиасы берутся из конвенции без вопроса; источник отмечается в отчёте

#### Scenario: не хватает аргумента джобы

- **WHEN** задание просит запустить сборку, имя джобы не названо ни в задании, ни в конвенции
- **THEN** ci спрашивает у человека; перечисление джоб сервера не выполняется

### Requirement: Инструмент спекирования не вшивается

Комплект MUST NOT фиксировать имя или формат инструмента спекирования
ни в одном поставляемом файле (скиллы, QWEN.md, docs). Полный путь
`task` оформляется скиллом спекирования, доступным в сессии (кандидаты
определяются по description); несколько кандидатов — один вопрос,
ни одного — мини-дизайн в чате; явное указание в задании сильнее.
**Конвенция проекта сильнее умолчания скилла**: может обязывать
спецификацию (полный путь всегда, лёгкого пути нет) и называть
инструмент; задание сильнее конвенции. Реализация идёт по чек-листу
изменения независимо от формата каталогов.

#### Scenario: в проекте установлен спек-скилл

- **WHEN** задание просит спеку и в сессии доступен один скилл спекирования
- **THEN** task оформляет изменение этим скиллом по его собственным правилам; отчёт упоминает использованный инструмент как факт, не как настройку

#### Scenario: спек-скилла нет

- **WHEN** задание просит спеку, подходящего скилла в сессии нет
- **THEN** task делает мини-дизайн в чате и честно отмечает в отчёте отсутствие инструмента спеки

#### Scenario: смена инструмента спекирования

- **WHEN** в проекте один спек-скилл заменён другим
- **THEN** файлы ship-kit не меняются: task в рантайме находит новый скилл

#### Scenario: конвенция обязывает спеку

- **WHEN** конвенция проекта требует спецификацию для каждой задачи
- **THEN** task оформляет изменение до кода даже для мелкой правки, без собственного усмотрения; инструмент — из конвенции
