# Design

## Context

Сессии пользователя: f0c0b43f (task завершился HANDOFF и встал — ждали
продолжения), ранее — план не создавался без внешних скиллов. Разворот
решения 2026-11-14 «явный вызов не тянет цепочку» — осознанный, по
прямому требованию: «план всегда», «без остановки вызывать скиллы,
если только не вызван конкретный скилл человеком».

## Goals / Non-Goals

**Goals:** план в каждом прогоне; фазы идут по плану без остановки
(паузы — только 🔒-карточки и вопросы); одиночный вызов человеком —
без цепочки. **Non-Goals:** гейты (не меняются), движок-диспетчер v2
(не возвращается — цепочку ведёт план-чек-лист, не отдельный скилл).

## Decisions

1. **Цепочка авторизована планом, не усмотрением скилла.** Де-фолтный
   план `task → pr 🔒 → ci 🔒` не спрашивает подтверждения: задание уже
   мандат, а каждое необратимое действие внутри — за карточкой. Это
   отличает авто-цепочку от v2-`run`: нет ни стадий, ни счётчиков, ни
   отдельного диспетчера.
2. **«Одиночный вызов» = вызов скилла вне слотов плана** (нет плана по
   ключу, скилл не следующий слот, человек явно попросил только этот
   шаг): выполняется без цепочки. Вызов фикса по ключу с планом после
   завершения продолжает ближайший незакрытый слот (обычно ci-слот —
   перезапуск под новой карточкой).
3. **Слот ci открывается после MERGED PR** — до MERGED цепочка стоит
   на слоте pr (проверки статуса — по мере необходимости, без опроса).
4. Сценарий кейса-2 упрощается: пользователю остаются карточки «да» и
   служебные инъекции; SCENARIO-2 дополнен заметкой об авто-цепочке.

## Risks / Trade-offs

- [flash пойдёт в ci без спроса после pr] → так задумано: спрашивает
  карточка, не фаза; границы («ничего не искать», ветки) не меняются.
- [Цикл цепочки при повторных падениях] → гейт перезапуска всегда
  спрашивает; issues.md и остановка при не-кодовых исходах — как было.
- [Смешение «одиночный» vs «по плану»] → правило одно: есть незакрытый
  слот этого плана — продолжай; нет — стоп.
