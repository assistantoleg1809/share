# Design

## Context

Ветка v3 от чистого v2 (архив pr-reply-gate — `7679100`): база —
три скилла расширения `extensions/ship-kit` (QWEN.md-контекст,
манифест 2.8.0, скиллы `ship-kit:task/pr/ci`, kind-файлы ci),
мейн-спека `base-skills` — 31 требование. Решения человека
2026-11-24: форма поставки — скиллы, имена `ship-kit-task/-pr/-ci`,
дефолт план-файлов `.qwen/tmp/ship-kit/<КЛЮЧ>/` проектной .qwen,
**без dev-установки и e2e-прогонов**, легаси не поддерживается,
установка — ручная копия (без установщика), и после разбора цены
скрытия — **`disable-model-invocation` не выставлять: автономность
сохранить**. Почему уход от расширения — см. proposal.md (Why).

Возможности Qwen Code проверены по официальной доке (qc-helper,
`docs/features/skills.md`): скиллы ищутся в `~/.qwen/skills`,
`~/.agents/skills` (персональные) и `.qwen/skills`,
`.agents/skills` (проектные) + `skills.directories`; коллизия имён:
project > personal > extension > bundled; каталог скилла несёт
произвольные файлы рядом (`reference.md`, kind-файлы); опции
`disable-model-invocation` / `user-invocable` / `hooks:` существуют,
но не используются комплектом (видимость — дефолт).

## Goals / Non-Goals

Goals: самодостаточные каталоги скиллов, видимые модели (автономное
ведение плана — как v2.7); частичная установка ручной копией; каскад
директории плана с временным дефолтом; синхронизация текстов вокруг
(docs, examples, корневые схемы).

Non-Goals: скрытие скиллов от модели (рассмотрено и отклонено
человеком 2026-11-24 — цена автономности); hooks-гейты
(`PreToolUse` deny пуша в целевые ветки) — опция на будущее;
деинсталляция расширения `~/.qwen/extensions/ship-kit` и установка
скиллов на dev-машине — решение человека, вне скопа; e2e-прогоны на
моках — вне скопа; изменение механики гейтов, MCP-ролей, каскада
конвенции, слотов, типов задач — не делается.

## Decisions

1. **Источник в репо — `skills/` в корне, не `.agents/skills/`.**
   Репо разработки не должно активировать собственные поставочные
   скиллы у каждого клона (`.agents/skills` проекта подхватывается
   Qwen Code как проектные скиллы); источник — видимый каталог, из
   которого установка копирует. Альтернатива «клонируй репо и получи
   скиллы» отвергнута: частичность и чистота dev-репо важнее.

2. **Имена `ship-kit-task/-pr/-ci` — дефис (решение человека, Q1).**
   Вызов `/ship-kit-task PRJ-42`. `ship-kit:task` (двоеточие в
   authored-имени допустимо по доке) сохранил бы старое написание,
   но `:` сворачивается в `_` в файле аргументов вызова, выглядит
   как префикс расширения, которого больше нет, и даёт каталог с
   `:` в имени.

3. **Видимость модели сохранена — `disable-model-invocation` не
   выставляется** (разворот по решению человека 2026-11-24 «чтобы
   автономность была»; ранее я предлагал скрытие, пользователь
   отклонил цену: модель не могла бы вести цепочку фаз и резюмить
   «продолжи <КЛЮЧ>»). Следствия: цепочка утверждённого плана и
   резюм работают как в v2.7 — слоты комплекта и внешние скиллы
   модель вызывает сама; descriptions трёх фаз постоянно видны в
   списке скиллов сессии (как у любого установленного скилла) —
   компактная цена вместо QWEN.md-автоконтекста; фиксируется ADDED
   «Скиллы комплекта видимы модели», чтобы разворот не потерялся.

4. **Инварианты — `reference.md` в каждом каталоге, дублирование
   принято.** Частичная установка исключает общий файл: каталог
   самодостаточен. Дублирование уже существует в v2 (гейты, роли,
   транспортные повторы повторены в трёх SKILL.md) — v3 фиксирует
   его и закрывает смоук-проверкой идентичности трёх `reference.md`.
   QWEN.md удаляется; уникальные строки (один вызов = одна фаза,
   каскад директории прогона, границы, OK:true с дословными строками)
   распределяются в SKILL.mds и `reference.md`. SKILL.md остаётся
   фазовым (лимит ~500 строк не давит: самый большой — ~150).

5. **Каскад директории прогона: задание → конвенция → дефолт
   `.qwen/tmp/ship-kit/<КЛЮЧ>/`** (решение человека, Q3).
   Определённая директория — с уровнем `<ПРОЕКТ>` (формат как у
   `runs/`); дефолт — без него: `.qwen` уже проектный. `issues.md`
   и `archive/` — в том же корне. **Легаси не поддерживается**
   (решение человека 2026-11-24: комплект не публиковался): старое
   требование «Состояние прогона» заменено REMOVED + тремя ADDED —
   валидатор не позволяет выбрасывать сценарии через MODIFIED.
   Наличие фаз комплекта при построении плана — по списку скиллов
   сессии (фазы видимы, единый механизм с внешними скиллами);
   «ничего не искать» не нарушается — список скиллов не сканирование
   серверов.

6. **Установка — ручная копия каталогов, скрипт не вводится**
   (решение человека 2026-11-24: «мы обычно копируем скиллы в нужную
   директорию»). `cp -r skills/ship-kit-<фаза> <цель>/` — частичность
   и выбор места очевидны из самой операции; инструкция — в
   docs/ship-kit.md; обновление = повторная копия поверх.

7. **Docs: `extensions/ship-kit/docs/` → `docs/` корня.**
   `ship-kit.md` — общий manual (не инсталлится), `upgrade.md` —
   changelog; секция 3.0.0 продолжает нумерацию (манифеста нет,
   дрейф-детектор снят в 2.6 — нумерация чисто документационная).

8. **Синхронизация окружения.** `examples/conveyor/README.md`
   (база — скиллы, не расширение; вызовы `/ship-kit-*`), корневые
   `flow.html` и `example-plan.md`, `openspec/project.md`
   (description упоминает «Расширение Qwen Code ship-kit
   (extensions/ship-kit)» — переписать). Исторические упоминания в
   архивах openspec не правятся.

## Risks / Trade-offs

- [Постоянный автоконтекст инвариантов исчезает: без вызванного
  скилла агент в проекте не соблюдает «пуш только в рабочие ветки» и
  пр.] → Принято: видимость фаз через descriptions оставляет
  подсказку «какой скилл звать», но не сами правила; смягчение на
  будущее — hooks `PreToolUse` во frontmatter (скиллам доступно,
  расширению не было).
- [Фазы видимы в каждой сессии: три description в списке скиллов,
  модель может позвать фазу по фразе-триггеру вне прогона] →
  Триггеры в descriptions узкие и конкретные («возьми PRJ-…»,
  «сделай ПР», «запусти сборку»); поведение вне плана — одиночный
  вызов без цепочки; при ложном срабатывании скилл честно спросит
  контекст (лесенка аргументов).
- [Правка общих инвариантов = три файла] → смоук-проверка
  идентичности `reference.md` в задачах; дублирование существовало и
  в v2.
- [Совместное проживание: расширение ещё установлено, скиллы не
  установлены] → Коллизий имён нет (`ship-kit:task` ≠
  `ship-kit-task`); удаление расширения и установка — по команде
  человека, вне скопа.
- [Матрица частичных наборов не прогоняется живьём] → По решению
  человека: проверки — `openspec validate --strict` и текстовые
  смоук-grep; живой прогон — позже по желанию.

## Migration Plan

- Миграции нет: комплект не публиковался, внешних прогонов со
  старыми путями не существует; легаси-пути (`runs/`, `skill-runs/`)
  и журналы без дат не поддерживаются (решение человека 2026-11-24).
  Dev-прогоны тест-контура при желании читаются явным путём в
  задании/конвенции.
- Вызовы: `/ship-kit:task` → `/ship-kit-task` (человеку — заменить
  привычку и скрипты).
- Откат: ветка v2 остаётся эталоном прошлой формы; git-история
  хранит `extensions/ship-kit` до удаления.
