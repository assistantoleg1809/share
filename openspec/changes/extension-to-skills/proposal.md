# Proposal

## Why

Расширение — не та форма: установка возможна только всем набором,
QWEN.md и манифест принадлежат механизму расширений, план прогона по
умолчанию пишется в репо (`runs/`), хотя человек директорию не
определял. Нужен набор из трёх атомарных скиллов: каталоги
копируются в нужную директорию (частично, без установщика), модель
видит фазы и ведёт цепочку плана автономно, как в v2.7.

## What Changes

- **BREAKING** Поставка: `extensions/ship-kit/` удаляется целиком
  (QWEN.md, манифест, скиллы `ship-kit:task/pr/ci`); источник — три
  самодостаточных каталога `skills/ship-kit-task/`,
  `skills/ship-kit-pr/`, `skills/ship-kit-ci/`: SKILL.md фазы +
  `reference.md` общих инвариантов (гейты, MCP-роли, транспортные
  повторы); ci сохраняет kind-файлы `build.md`/`deploy.md`. Установка
  — копия выбранных каталогов в `~/.qwen/skills/` или
  `.qwen/skills/` проекта (обычная файловая копия, без установщика),
  ставить можно не всем набором.
- Скиллы остаются видимыми модели: `disable-model-invocation` не
  выставляется — автономность сохраняется (цепочка утверждённого
  плана ведётся моделью, «продолжи <КЛЮЧ>» — канонический вход
  возобновления, как в v2.7); человек тоже может вызывать фазы
  напрямую `/ship-kit-task PRJ-42, …`.
- План-файл: директория прогона каскадом задание → конвенция →
  дефолт `.qwen/tmp/ship-kit/<КЛЮЧ>/` (временная директория .qwen
  проекта; определённая директория — с уровнем `<ПРОЕКТ>`, как
  сегодня `runs/`); `issues.md` и архив — в корне прогона. Легаси
  (`runs/`, `skill-runs/`, журналы без дат) не поддерживается:
  комплект не публиковался, внешних прогонов нет.
- Частичная установка: план строится из установленных фаз — наличие
  фазы по списку скиллов сессии; неустановленные — пометкой «фаза не
  установлена» в плане и отчёте, без вопроса; любая установленная
  фаза — входная точка прогона (первый вызов по ключу создаёт план).
- QWEN.md уходит: инварианты живут в SKILL.md фаз и `reference.md`,
  грузятся при вызове; постоянный автоконтекст исчезает, видимость
  фаз в сессии — как у обычных скиллов (description в списке).
- Отсутствие конфигурации проекта уже специфицировано («Работа без
  конфигурации проекта»: лесенка задание > конвенция > один вопрос
  человеку) — сохраняется, дельты не требует.

### Modified Capabilities

- `base-skills`: ADDED «Скиллы комплекта видимы модели»
  (`disable-model-invocation` не выставляется, вызов человеком и

  issues.md» — легаси-пути и журналы без дат не нужны (комплект не
  публиковался), замена — ADDED «Директория прогона — каскад с
  временным дефолтом», ADDED «Чек-лист и журнал план-файла», ADDED
  «Токен возобновления и статусы из MCP»; MODIFIED «Три скилла-фазы с
  говорящими именами» (имена `ship-kit-*`, поставка каталогами без
  QWEN.md, цепочка и одиночные вызовы — как в v2), «Инструмент
  спекирования не вшивается» (перечень файлов поставки без QWEN.md),
  «Порядок прогона с внешними скиллами» (создание плана любым входом,
  чек-лист с неустановленными фазами, слот ci после MERGED),
  «Архивация прогона и worktree» (корень архива по каскаду),
  «Сомнение возобновления — вопрос закрытыми опциями» (план ищется по
  каскаду директории, вопрос задаёт вызванный скилл).

## Impact

- Репо: `extensions/ship-kit/` удаляется; добавляется `skills/`;
  `extensions/ship-kit/docs/` → `docs/`; обновляются
  `examples/conveyor/README.md` (база ставится скиллами, не
  расширением), корневые `flow.html` и `example-plan.md`,
  `openspec/project.md` (описание формы поставки).
- Пользователи: вызов меняется с `/ship-kit:task` на
  `/ship-kit-task`; постоянный автоконтекст инвариантов исчезает
  (правила грузятся при вызванном скилле; видимость фаз — через
  descriptions, как у обычных скиллов); обновление = повторная копия
  выбранных каталогов. Миграции нет: комплект не публиковался,
  внешних прогонов со старыми путями не существует.
- Скоп проверок: `openspec validate --strict` и текстовые
  смоук-проверки (идентичность блоков инвариантов в трёх каталогах,
  отсутствие `ship-kit:`-вызовов в активных текстах); e2e-прогоны на
  моках и dev-установка на машине — вне скопа (решение человека
  2026-11-24).
