# examples/conveyor — образец полного конвейера v2

Рабочий образец стадийной модели ship-kit v2 (1.0.0, 2026-11-13):
диспетчер `run`, диагноз/фикс `doctor`, ведение реестра `registry`,
правила доработки `adapt-kit`. **Не продукт**: репо ship-kit
поставляет базу из трёх скиллов — `ship-kit-task` /
`ship-kit-pr` / `ship-kit-ci` ([skills](../../skills)); этот
каталог — читаемый снимок более сложного решения.

## Когда нужен полный конвейер

- несколько стадий и стендов (DEV→ST→IFT→PSI) с лимитами на каждую;
- циклы «фикс → PR → MERGED → перезапуск» под счётчики и loop guard;
- центральный реестр нескольких проектов (стадии, записи знания,
  servers, подмены исполнителей `executors`);
- WAIT-режим починки джобы человеком с заморозкой бюджета.

Для обычного «задача → PR → сборка» достаточно базы: порядок с
внешними скиллами база собирает подтверждённым чек-листом план-файла
прогона (директория — каскадом, дефолт `.qwen/tmp/ship-kit/<КЛЮЧ>/`).

## Состав

- `skills/` — `run`, `doctor` (kind-файлы `build.md`/`deploy.md`),
  `registry`, `adapt-kit`;
- `docs/` — [conveyor.md](docs/conveyor.md) (полная документация v2),
  [positions.md](docs/positions.md) (манифест позиций),
  [ship-kit.projects.example.md](docs/ship-kit.projects.example.md)
  (схема реестра), [specs-snapshot.md](docs/specs-snapshot.md) (мейн-спеки
  v2: conveyor/registry/executors — дословный снимок);
- `tests/`, `e2e/` — выжившие проверки и стенд v2 (моки MCP,
  сценарии; yaml-валидатор реестра yaml-эпохи удалён вместе с форматом).

## Зависимость от базы

Образец вызывает скиллы базового комплекта: `ship-kit-task` (спека и
правки кода), `ship-kit-pr` (ветка/PR/замечания), `ship-kit-ci`
(запуск/ожидание джоб). Позиции манифеста (`task`, `pr`, `ci`,
`detective`, `mechanic`) — словарь образца; `detective`/`mechanic`
исполняет `doctor` самого образца.

## Как «оживить» в проекте

Скопируйте каталоги скиллов образца в `.qwen/skills` проекта (или в
каталог пользовательских скиллов): `run`, `doctor`, `registry`,
`adapt-kit` — база `ship-kit-task/pr/ci` уже установлена скиллами
(копия каталогов `skills/` репо). Создайте реестр
`ship-kit.projects.md` по схеме примера, подключите MCP-серверы в
`settings.json → mcpServers`. Прогоны — на glm-5.3-flash.

## Миграция с v1.0.0 (v2-расширения)

Переустановите расширение ship-kit (2.0.0): скиллы
`analyst`/`courier`/`operator` больше не поставляются — их роли в базе
исполняют `task`/`pr`/`ci`; реестр в базе не читается никем (полный
конвейер читает его сам — через этот образец). yaml-реестр v1
сконвертируйте в md по схеме примера.

## Честное ограничение

Соответствие образца базе гарантируется только на момент коммита:
образец не версионируется и не адаптируется под чужие проекты. Снимок
спек v2 и реестр конвертированы в md по решению от 2026-11-14; имена
исполнителей в журналах прогонов (`e2e/`, `tests/`) оставлены как
историческая правда.
