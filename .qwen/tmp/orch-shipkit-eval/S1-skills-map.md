2. **Формула вызова следующего слота** есть только в task (стр. 73–75 «инструментом вызова скиллов») и в общих reference (стр. 11–12 «модель вызывает его сама»). В pr/SKILL.md и ci/SKILL.md прямого указания на инструмент вызова следующего слота нет — только строки HANDOFF отчёта и ci-команда «вызови \`ship-kit-task\` (fix по диагнозу)» (стр. 131–132).
3. **Состав передаваемых исполнителю данных** текстом описан только для связи ci→task (диагноз: категория, rootCause, fixable, fixHint, knownIssues, связанность — ci/SKILL.md:83–86; вход fix — task/SKILL.md:113–114) и для слота spec («реализация по чек-листу изменения» — task/SKILL.md:90). Формального описания «что передать при обычном переходе task→pr→ci» в комплекте нет.
4. Слот-механика выбора исполнителя (slot:spec/slot:business/slot:technical, каскад, ноль кандидатов) сосредоточена **целиком в task/SKILL.md:83–102**; pr и ci её не дублируют — у них «слот» только в смысле «слот плана/статус слота».
