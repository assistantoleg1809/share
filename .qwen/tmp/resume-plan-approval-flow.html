resume-plan-approval — схема вызовов скиллов

ship-kit: продолжение прогона одной фразой, план на утверждение, слоты без печати имён

печатает человек подтверждение / вопрос task делает сам
Вход 1 — старт прогонапечатает: /ship-kit:task PRJ-42
с профилем набора («профиль openspec») или перечнем скиллов
Вход 2 — продолжениепечатает: продолжи PRJ-42
новая сессия — строка копируется из отчёта «ДАЛЬШЕ»
↓каждый вход получает ровно одно подтверждение
Чек-лист всего плана → одно «да»слоты в порядке перечисления + pr/ci на названных местах
Остаток плана одним блоком → одно «да»сомнение → один вопрос с опциями: слоты плана / другой ключ / новая задача
↓
Диспетчер: task берёт следующий незакрытый слот и вызывает его самимена скиллов человек не печатает; подтверждение остатка не наследуется карточками — каждый пуш и запуск спрашивается своим 🔒
План прогона — runs/ПРОЕКТ/PRJ-42/plan.md
propose→ pr 🔒→ apply→ pr 🔒→ archive→ pr 🔒→ ci 🔒
PR может стоять после любого слота — порядок задаёт план; ci стоит там, куда его поставили (по умолчанию хвост)
↓диспетчер отправляет в очередной слот; закрытый слот возвращает сюда же
Слот набора
(spec · apply · любой другой)после слота spec — пауза-ревью спеки: продолжить / доработать / стоп; после выбора «продолжить» — ⟲ к диспетчеру
Слот pr — 🔒 карточка «пуш+PR»после «да»: ожидание MERGED опросом (без вопроса) → ⟲ к диспетчеру
Слот ci — 🔒 карточка запуска джобызелёная → план закрывается; упавшая → петля фикса (ниже)
↓петля падения сборки — без команд человека
Причина в диффе задачификс в ветку задачи → пуш в тот же PR → снова MERGED → ci ×N
Посторонняя причинатех-ветка от базовой → слот pr: тех-PR дописывается в план и показывается на ближайшей карточке → MERGED → ci ×N
↓
План закрыт → предложение архивации прогонаruns/archive/ПРОЕКТ/PRJ-42/; строка «ДАЛЬШЕ» больше не выводится
📄 Пока план открыт, отчёт каждой фазы заканчивается строкой ДАЛЬШЕ: продолжи PRJ-42 — копируешь её одной строкой в новую сессию вместо имени скилла.
  • Человек печатает два текста: стартовый вызов и «продолжи PRJ-42». Всё остальное — выбор опций в вопросах и 🔒-карточках.
  • Набор скиллов у каждого проекта свой — диспетчер читает имена из плана, openspec не зашит нигде.
  • Ревью-точка одна: после слота spec — проверка спеки человеком не пропускается.
