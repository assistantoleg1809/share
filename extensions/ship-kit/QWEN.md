# Ship Kit

Комплект скиллов для конвейера
«Jira → OpenSpec → правки → PR → ревью → сборка → деплой → исправление».
Полная документация: [docs/agents-and-workflows.md](docs/agents-and-workflows.md)
(состав, e2e-стенд, скилл-контур §10, чек-лист адаптации §7).

## Статус разработки (2026-11-10)

**Скилл-контур — приоритет; 9 скиллов** (консолидация 15→9): `run`
(диспетчер и прогон), `jobs` (запуск/ожидание джоб, kind=build|deploy),
`diagnosis` и `repair` (+командные файлы build.md/deploy.md — сборку и
деплой обслуживают разные команды, инструкции эскалации разные),
`openspec`, `pr`, `review`, `registry` (ведение md-реестра), `adapt-kit`
(правила доработки комплекта). **Агенты и workflows заморожены** и будут
удалены: не дорабатывать; их зеркала 11 скилл-ролей удалены консолидацией —
запуск замороженного контура не поддерживается. md-реестр
`ship-kit.projects.md` — схема
[docs/ship-kit.projects.example.md](docs/ship-kit.projects.example.md).

## Что даёт расширение

- **9 скиллов** (`/ship-kit:<имя>`; тела — в `skills/`):
  - `run` — диспетчер и прогон: вход «`<тег> <что сделать>`» (напр.
    «PRJ-123 запусти джобу и исправь ошибки»), сам выбирает ступени,
    ведёт план `skill-runs/<тег>/` (состояние + аргументы джоб с
    источниками), циклы до успеха с fixFlow direct|pr и ожиданием апрува
    (waiting-approval → «продолжи прогон»), лимиты/бюджет из реестра,
    ETA из истории джобы;
  - `jobs` — запуск (один вызов, без ретраев) и ожидание джоб
    (статус/лог/ETA/possiblyStuck); kind из alias;
  - `diagnosis` — разбор падения: категория/fixable/knownIssues;
    командные файлы build.md|deploy.md — разные команды и эскалации;
  - `repair` — минимальная правка по диагнозу, TDD
    (красный → правка → зелёный), коммит, push в рабочую ветку;
    командные файлы build.md|deploy.md;
  - `openspec` — контекст (Jira/Confluence/mmap) и оформление изменения
    OpenSpec; реализацию tasks.md делает скилл OpenSpec, если установлен;
  - `pr` — обвязка контура: ветка task/<КЛЮЧ>, коммиты, PR через
    mcp-bitbucket, цикл замечаний (check/fix);
  - `review` — ревью диффа, только чтение;
  - `registry` — единственная точка ведения `ship-kit.projects.md`;
  - `adapt-kit` — обязательные правила доработки комплекта (читать перед
    любой правкой).
- **Инварианты скилл-контура**: только MCP из аргументов вызова
  (alias→сервер разрешает вызывающий); файл проектов роли не читают;
  ничего не искать; явный вызов одного скилла не запускает следующие —
  цепочку ведёт только `run`; push только в рабочие ветки; статусы Jira
  не трогать.
- **Реестр проектов** (md): `ship-kit.projects.md` в корне проекта или
  `~/.qwen/ship-kit/projects.md`: jira-ключ, ssh-репо, КЭ, alias MCP
  (`mcp-build`/`mcp-deploy`/`mcp-sonar`/…) → фактический сервер,
  пути/названия джоб, fixFlow, лимиты запусков. Ведение — только скилл
  `registry`.
- **История прогонов**: `skill-runs/<тег>/` в корне проекта — plan.md
  (состояние, ступени, аргументы джоб с источниками, журнал) + issues.md
  (провал = отдельная задача с ошибкой, чинит другой скилл). План —
  токен возобновления («продолжи прогон <тег>»).
- **Замороженные агенты/workflows** (agents/*.md, workflows/*.js):
  поставляются как есть, доработке не подлежат, будут удалены; json-реестр
  `ship-kit.projects.json` и run-журналы `openspec/changes/<tag>/run-*.json`
  — их_legacy, не развиваются.

## Условия работы

- Скиллы MCP-серверы не выбирают: вызывающий (человек или скилл `run`)
  передаёт alias→сервер аргументами из md-реестра.
- `tools.workflowsEnabled: true` — только если используете замороженные
  workflows (не поддерживается после консолидации).
- Не заводить в проекте `.qwen/agents/*.md` с теми же именами — конфликт
  с замороженными агентами расширения, пока они не удалены.
- Имена джоб (сборка/деплой) живут в md-реестре или передаются args,
  никогда не хардкодятся.
