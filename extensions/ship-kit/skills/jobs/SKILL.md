# jobs — запуск и наблюдение джоб

Одна механика для сборки и деплоя; kind приходит с alias из аргументов
вызова: `mcp-build` или `mcp-deploy` → фактический сервер, путь и название
джобы, номер запуска. Режим задаёт задание: «запусти» или «жди/дай лог».

## Шаг 0 — проверка MCP из аргументов (обязательна)

Скилл не выбирает сервер сам: alias (`mcp-build`/`mcp-deploy` → фактический
сервер) и название джобы передаются аргументами вызова. Не передано —
запроси у пользователя, какой MCP использовать (id сервера из
settings.json → mcpServers), и остановись до ответа; не подбирай молча.

Убедись, что инструмент нужного режима доступен на переданном сервере
(объявлен напрямую или найден через tool_search). Инструмента нет — верни
блок ошибки и остановись:

```
❌ Инструмент джобы недоступен (<запуск или статус/лог>)
Симптом: <чего не хватает, дословно>
Рекомендации:
1. Выполнить /mcp — жив ли переданный сервер и как называются инструменты.
2. Сверить alias с фактическим id сервера в файле проектов
   (ship-kit.projects.md) и settings.json → mcpServers — их читает
   вызывающий, не ты.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
```

## Режим «запуск»

1. 🔒 **Гейт перед вызовом.** Задай пользователю один вопрос (ask_user_question)
   с карточкой запуска: kind, джоба (путь/имя), ветка, стенд (kind=deploy),
   параметры с их источниками, ожидаемая длительность. Подтверждение —
   только явное: ответ на вопрос или дословное «подтверждаю …» в задании
   (передано вызывающим — работай без вопроса, укажи
   `pre-approved(источник)`). Вызывающий передал `gate=inherited(<причина:
   таймаут предыдущего>)` — не спрашивай, укажи `inherited(причина)`.
   Отказ → отчёт ok=false, gate=declined — вызова нет.
2. Один вызов запуска с переданными параметрами. Повторы запрещены: упал
   вызов — так и отчитайся, ретраи делает вызывающий (скилл `run` или
   человек), не ты.
3. Аргументы приходят полностью от вызывающего: если параметры запуска не
   заданы, вызывающий сам берёт их из предыдущей успешной джобы и передаёт
   тебе — наследование не твоя забота. Ничего не искать: не перечислять
   джобы, не сканировать сервер, не угадывать пути. Аргумента нет — верни
   ошибку с перечнем недостающего, без попыток доугадаться. Имя инструмента
   запуска может быть запинковано в реестре (`<alias>.tool.run`) — оно
   приходит аргументом; не запинковано — найди инструмент запуска на
   переданном сервере по описанию.
4. Из ответа возьми номер запуска и URL. Статус не ждать — это режим
   «ожидание».
5. Параметры не придумывать: не передали — запускай с дефолтами джобы.
6. Стенд: передан аргумент stand — включи его в параметры запуска и укажи
   в отчёте.

## Режим «ожидание»

1. Узнай статус (номер или последний по джобе и ветке).
2. Идёт — подожди через shell `sleep 45` и проверь снова. Интервал не чаще
   45 секунд, очередь не дёргать.
3. Бюджет одного захода — около 8 минут. Всё ещё идёт — верни state=RUNNING:
   вызывающий вызовет следующего наблюдателя.
4. Терминальные состояния: SUCCESS, FAILURE, UNSTABLE, ABORTED.
5. При FAILURE/UNSTABLE приложи: первую ошибку (errorSnippet) и последние
   ~100 строк лога (logTail).
6. Вызывающий передал «ожидаемую длительность» (из истории джобы) — укажи
   eta в отчёте; идёт дольше ~2× ожидаемого — поставь possiblyStuck: true.

## Формат отчёта

Запуск: ok: true/false; kind (build/deploy); stand (если передан);
number; url; gate: confirmed | pre-approved(источник) |
inherited(причина) | declined; error (при ok=false — дословно что вернул
инструмент).

Ожидание: state (RUNNING/SUCCESS/FAILURE/UNSTABLE/ABORTED/UNKNOWN); kind
(build/deploy); stand (если передан); number; url; errorSnippet; logTail;
eta (мин, если передана ожидаемая длительность); possiblyStuck. Ожидание
— чтение, без гейта.

## Ограничения

- Только MCP, переданный аргументами вызова. Файл проектов не читается:
  alias→сервер знает вызывающий, не ты.
- Shell — исключительно для `sleep` в режиме ожидания, никаких других
  команд. Файлы не менять.
- Кроме инструмента текущего режима ничего не вызываешь: другие MCP,
  чтение логов в режиме запуска — не твои.

## Соседние шаги

Упала и нужен диагноз — скилл `diagnosis`; после фикса — снова запуск
здесь. Переход — только явный вызов (пользователем или скиллом `run`):
сам следующий скилл не запускай.
