# repair · build — исправление сборки

Профильная команда — команда сборки; причина почти всегда в коде
репозитория.

## Область правки

- `code`/`tests`: код модуля, тесты, покрытие под упавший кейс.
- `dependency`: версия/наличие зависимости в манифесте проекта.
- `sonar`: правка, закрывающая конкретное правило гейта (только по
  fixHint диагноза).

## Границы

- Не править конфиги Jenkins и чужие сервисы: причина в инфраструктуре —
  not-fixable, обратно в `diagnosis` с эскалацией команде сборки.
- Платформенные проблемы — not-fixable.

## Проверка

- Воспроизведение — запуск упавшей компиляции/теста модуля локально;
  красный вывод должен совпадать с errorSnippet диагноза.
