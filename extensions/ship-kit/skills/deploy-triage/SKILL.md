# deploy-triage — диспетчер инцидентов деплоя

На вход — упавший деплой (джоба, номер, хвост лога). Задача — диагноз:
известная проблема DevOps, инфраструктура, конфиг или код репозитория.
Ничего не правишь: падения деплоя чаще всего не кодовые, и главный
результат — правильная эскалация.

## Шаг 0 — проверка MCP из аргументов (обязательна)

Скилл работает с MCP, переданными аргументами вызова: до пяти alias —
`mcp-deploy` (лог деплоя), `mcp-jira`, `mcp-confluence`, `mcp-sonar`,
`mcp-bitbucket`; alias → фактический сервер знает вызывающий (файл проектов
скилл не читает). Проверь каждый переданный одним лёгким вызовом. Хоть один
недоступен — верни блок ошибки:

```
❌ MCP <переданный сервер> недоступен
Симптом: <что произошло, дословно>
Рекомендации:
1. Выполнить /mcp и посмотреть статус сервера.
2. Сверить alias с фактическим id в файле проектов
   (ship-kit.projects.md) и settings.json → mcpServers — их читает
   вызывающий, не ты.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
4. Для удалённых серверов — проверить сеть и токен.
```

Alias не передан вовсе — в проекте этого MCP нет: работай без него и честно
отметь это в отчёте (confidence ниже). Не передан ни один MCP, непонятно,
какой использовать, — запроси у пользователя и остановись до ответа; не
подбирай серверы сам.

## Протокол

1. Лог деплоя (mcp-deploy): найди первую настоящую ошибку (rsync/место на
   диске, агент, сеть, артефакт, таймаут, конфиг, миграция). Отделяй причину
   от последствий.
2. mcp-jira (если передан): по тексту ошибки — открытые тикеты команды
   DevOps: известная ли проблема, массовая ли (сколько открытых с тем же
   симптомом).
3. mcp-confluence (если передан): runbook деплоя — есть ли одобренное
   решение/обход.
4. mcp-sonar / mcp-bitbucket (если переданы) — по необходимости контекста
   (что менялось перед деплоем).
5. Собери диагноз: категория (infra / devops-known / config / code /
   dependency / flaky / other), первопричина, fixable — правится ли
   конфигом/кодом репозитория, fixHint, knownIssues — найденные тикеты.
   infra и devops-known = not-fixable: тикеты и рекомендация эскалации
   DevOps; ретрай той же джобы на том же агенте при стабильном падении
   бесполезен.

## Ограничения

- Только MCP, переданные аргументами вызова; ничего сверх них не вызывать.
  Файл проектов не читается.
- Только чтение, без shell. Правки, комментарии, статусы — запрещены.
- Данных мало — честно ставь confidence: low.

## Формат отчёта

category, rootCause, fixable, fixHint, knownIssues (ключ, ссылка, суть),
confidence (high/medium/low).

## Соседние шаги

Диагноз config/code fixable — скилл `deploy-fix`; повторный запуск после
фикса — скилл `deploy-trigger`. Переход — только явный вызов (пользователем
или скиллом `run`): сам следующий скилл не запускай.
