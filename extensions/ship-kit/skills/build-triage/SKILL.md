# build-triage — диспетчер инцидентов сборки

На вход — упавшая сборка (джоба, номер, хвост лога). Задача — диагноз:
категория причины, можно ли исправить кодом, известные проблемы. Код не
правишь.

## Шаг 0 — проверка MCP из аргументов (обязательна)

Скилл работает с MCP, переданными аргументами вызова: до пяти alias —
`mcp-build` (лог сборки), `mcp-jira`, `mcp-confluence`, `mcp-sonar`,
`mcp-bitbucket`; alias → фактический сервер знает вызывающий (файл проектов
скилл не читает). Проверь каждый переданный одним лёгким вызовом (статус
сборки, поиск по ключу, получение страницы, проект/PR, последний коммит).
Хоть один недоступен — верни блок ошибки:

```
❌ MCP <переданный сервер> недоступен
Симптом: <что произошло, дословно>
Рекомендации:
1. Выполнить /mcp и посмотреть статус сервера.
2. Сверить alias с фактическим id в файле проектов
   (ship-kit.projects.md) и settings.json → mcpServers — их читает
   вызывающий, не ты.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
4. Для удалённых серверов — проверить сеть и токен.
```

Alias не передан вовсе — в проекте этого MCP нет: работай без него и честно
отметь это в отчёте (confidence ниже). Не передан ни один MCP, непонятно,
какой использовать, — запроси у пользователя и остановись до ответа; не
подбирай серверы сам.

## Протокол

1. Лог сборки (mcp-build): найди первую настоящую ошибку (компиляция, тест,
   sonar-гейт, инфраструктура, таймаут, зависимость). Отделяй причину от
   последствий.
2. mcp-jira (если передан): по тексту ошибки поищи открытые тикеты команды
   DevOps — известная ли проблема, массовая ли (сколько открытых с тем же
   симптомом).
3. mcp-confluence (если передан): runbook/инструкции по этой ошибке —
   есть ли одобренное решение.
4. mcp-sonar (если передан): если падение по качеству — какой гейт/правило,
   что показывает отчёт.
5. mcp-bitbucket (если передан): последний коммит в ветку — что менялось
   перед падением, кто автор.
6. Собери диагноз: категория (code/tests/sonar/infra/config/dependency/
   flaky/other), первопричина, fixable — исправит ли её исполнитель правкой
   кода, fixHint — конкретная подсказка для правки, knownIssues — найденные
   тикеты.

## Ограничения

- Только MCP, переданные аргументами вызова; ничего сверх них не вызывать.
  Файл проектов не читается.
- Только чтение. Правки кода, комментарии в Jira, статусы — запрещены.
- Данных мало — честно ставь confidence: low, не выдавай догадку за диагноз.

## Формат отчёта

category, rootCause, fixable, fixHint, knownIssues (ключ, ссылка, суть),
confidence (high/medium/low).

## Соседние шаги

Диагноз fixable — скилл `build-fix`; запуск пересборки после фикса —
скилл `build-trigger`. Переход — только явный вызов (пользователем или
скиллом `run`): сам следующий скилл не запускай.
