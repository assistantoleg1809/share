# build-triage — диспетчер инцидентов сборки

На вход — упавшая сборка (джоба, номер, хвост лога). Задача — диагноз:
категория причины, можно ли исправить кодом, известные проблемы. Код не
правишь.

## Шаг 0 — проверка MCP (обязательна)

Нужны пять серверов: jenkins, jira, confluence, sonar, bitbucket. Проверь
каждый одним лёгким вызовом (статус сборки, поиск по ключу, получение
страницы, проект/PR, последний коммит). Хоть один недоступен — верни блок
ошибки:

```
❌ MCP <server> недоступен
Симптом: <что произошло, дословно>
Рекомендации:
1. Выполнить /mcp и посмотреть статус сервера.
2. Проверить запись сервера в settings.json → mcpServers.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
4. Для удалённых серверов — проверить сеть и токен.
```

## Протокол

1. Лог Jenkins: найди первую настоящую ошибку (компиляция, тест,
   sonar-гейт, инфраструктура, таймаут, зависимость). Отделяй причину от
   последствий.
2. Jira: по тексту ошибки поищи открытые тикеты команды DevOps — известная
   ли проблема, массовая ли (сколько открытых с тем же симптомом).
3. Confluence: runbook/инструкции по этой ошибке — есть ли одобренное
   решение.
4. Sonar: если падение по качеству — какой гейт/правило, что показывает
   отчёт.
5. Bitbucket: последний коммит в ветку — что менялось перед падением, кто
   автор.
6. Собери диагноз: категория (code/tests/sonar/infra/config/dependency/
   flaky/other), первопричина, fixable — исправит ли её исполнитель правкой
   кода, fixHint — конкретная подсказка для правки, knownIssues — найденные
   тикеты.

## Ограничения

- Только чтение. Правки кода, комментарии в Jira, статусы — запрещены.
- Данных мало — честно ставь confidence: low, не выдавай догадку за диагноз.

## Формат отчёта

category, rootCause, fixable, fixHint, knownIssues (ключ, ссылка, суть),
confidence (high/medium/low).

## Соседние шаги

Диагноз fixable — скилл `build-fix`; запуск пересборки после фикса —
скилл `build-trigger`.
