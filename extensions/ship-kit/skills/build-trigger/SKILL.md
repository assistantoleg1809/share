# build-trigger — кнопка «Запустить сборку»

Одна задача — один вызов инструмента запуска. Повторы, ожидание статуса,
чтение логов — не здесь.

## Шаг 0 — проверка MCP из аргументов (обязательна)

Скилл не выбирает сервер сам: MCP для запуска (alias `mcp-build` → фактический
сервер) и название джобы передаются аргументами вызова. Не передано —
запроси у пользователя, какой MCP использовать (id сервера из
settings.json → mcpServers), и остановись до ответа; не подбирай молча.

Убедись, что инструмент запуска сборки доступен на переданном сервере
(объявлен напрямую или найден через tool_search). Инструмента нет — верни
блок ошибки и остановись:

```
❌ Инструмент запуска сборки недоступен
Симптом: <чего не хватает, дословно>
Рекомендации:
1. Выполнить /mcp — жив ли переданный сервер и как называется инструмент запуска.
2. Сверить alias mcp-build с фактическим id сервера в файле проектов
   (ship-kit.projects.md) и settings.json → mcpServers — их читает
   вызывающий, не ты.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
```

## Протокол

1. Один вызов запуска с переданными параметрами. Повторы запрещены: упал
   вызов — так и отчитайся, ретраи делает вызывающий (workflow или человек),
   не ты.
2. Из ответа возьми номер сборки и URL.
3. Статус сборки не ждать — за этим соседний шаг (скилл `build-status`).

## Ограничения

- Кроме инструмента запуска ничего не вызываешь: чтение логов, статусы,
  другие MCP — не твои.
- Только MCP, переданный аргументами вызова. Файл проектов не читается:
  alias→сервер знает вызывающий, не ты.
- Параметры сборки не придумывать: не передали — запускай с дефолтами джобы.

## Формат отчёта

ok: true/false; buildNumber; url; error (при ok=false — дословно что вернул
инструмент).
