# registry — ведение файла проектов

Единственная точка изменений реестра `ship-kit.projects.md`: новые проекты,
новые элементы, правки значений. Скиллы-роли реестр не читают — его читаешь
ты и основная сессия, чтобы передавать alias→сервер и джобы аргументами.

## Где файл

Цепочка поиска (первый найденный — рабочий):

1. `ship-kit.projects.md` в корне проекта;
2. `~/.qwen/ship-kit/projects.md` (центральный, на несколько проектов).

Файла нет — спроси у пользователя, где создавать (в проекте или центральный),
и создай по схеме примера
[docs/ship-kit.projects.example.md](../../docs/ship-kit.projects.example.md).

## Протокол

1. Найди файл по цепочке; покажи, какой выбран.
2. Прочитай целиком. Секции — `## [default]` и `## <имя проекта>`, внутри
   плоские строки `ключ: значение`.
3. Внеси изменение:
   - новый проект — новая секция `## <имя>` (имя — короткий slug, без
     пробелов);
   - новый элемент — строка `ключ: значение` в нужной секции;
   - правка — замени значение, сохранив ключ и форматирование.
4. Сверь схему (ключи и обязательность — в примере): у проекта обязательны
   `jiraKey`, `repoSsh`, `ce`; alias-ключи — только из фиксированного списка
   (`mcp-build`, `mcp-deploy`, `mcp-sonar`, `mcp-jira`, `mcp-confluence`,
   `mcp-bitbucket`, `mcp-mmap`); для `mcp-build`/`mcp-deploy` — `.job.path`
   и `.job.name`, для `mcp-sonar` — `.projectKey`; опционально
   `<alias>.tool.run|.tool.status|.tool.log` — точные имена инструментов
   MCP запуска/статуса/лога на сервере alias; при наличии `mcp-deploy.*` —
   `deploy.stands`: значения только `DEV`, `ST`, `IFT`, `PSI`, в
   каноническом порядке, IFT и PSI обязательны в составе (опционально
   `mcp-deploy.job.name.<СТЕНД>` — своя джоба на стенд); `retryLimit` —
   число.
5. Убедись, что каждый `*.server` существует в `settings.json → mcpServers`
   проекта (или центрального, для центрального реестра). Не существует —
   скажи об этом пользователю и не пиши значение молча.
6. Отчитайся диффом (до/после) и списком проверенных ключей.

## Ограничения

- Значения не выдумывать: сервер, джоба, КЭ, лимит — спроси пользователя,
  если их не назвали.
- Не трогать `settings.json → mcpServers` — конфигурация серверов остаётся
  за пользователем.
- Не удалять проекты и элементы без явной команды пользователя.
- MCP не используется вовсе — это работа с файлом.

## Формат отчёта

Файл (какой из цепочки); что изменено (дифф); предупреждения схемы, если
были.
