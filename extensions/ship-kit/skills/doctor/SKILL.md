# doctor — диагноз и не-код фикс падения

Две позиции, один скилл — **режим задаёт вызывающий** (run или человек), сам
не переключаешь; один вызов = один шаг:

- **diagnose** (позиция detective): вход — упавшая джоба (kind, номер, хвост
  лога). Только чтение: категория, первопричина, fixable, fixHint,
  knownIssues, confidence. MCP — из `diagnosisRef` стадии (передаёт
  вызывающий).
- **fix** (позиция mechanic): вход — диагноз (kind, категория, первопричина,
  fixHint). Минимальная правка, локальная проверка, коммит, 🔒 карточка
  пуша, push. MCP — из `repairRef` (лог упавшей джобы для сверки).

## Правила действий (ask-таблица)

| действие | diagnose | fix |
|---|---|---|
| чтение лога/статуса/тикетов/runbook | allow | allow |
| правка файлов репозитория | deny | allow (минимальная, по fixHint) |
| локальный коммит | deny | allow |
| пуш | deny | ask · всегда (карточка пуша) |
| всё сверх переданных MCP | deny | deny |

## Шаг 0 — проверки (обязательны)

1. MCP: лёгкий вызов каждого переданного сервера (статус сборки, поиск по
   ключу, страница, проект, последний коммит). Хоть один недоступен — блок
   ошибки и стоп (❌ MCP <сервер> недоступен; рекомендации: /mcp; сверка alias
   с ship-kit.projects.yaml и settings.json — их читает вызывающий;
   перезапуск сессии; сеть/токен). Alias не передан — в проекте этого MCP
   нет: работай без него и отметь в отчёте (confidence ниже). Не передан ни
   один — запроси у пользователя и остановись.
2. Git (только режим fix): ты в свежем worktree (pwd вида
   `.qwen/worktrees/...`) — создай рабочую ветку бага `bugfix/<КЛЮЧ>`
   (шаблон из задания сильнее; повторная попытка — суффикс `-2`, `-3`, …).
   В основном чекауте — ветка должна быть рабочей (не main/master), каталог
   чистым, upstream настроен. Проблема — ошибка с описанием, ничего не трогай.

## Командный файл — по kind, обязательно до работы

> Определи kind (build/deploy — передан аргументом) и прочитай **только свой
> файл**: build → [build.md](build.md), deploy → [deploy.md](deploy.md).
> Внутри файла читай **только секцию своего режима**: `## diagnose` или
> `## fix`. Остальное не открывай.

## Режим diagnose (только чтение)

1. Лог джобы (mcp-build/mcp-deploy по kind): найди первую настоящую ошибку;
   отделяй причину от последствий.
2. mcp-jira (если передан): открытые тикеты профильной команды по тексту
   ошибки (какой команды — см. командный файл): известная ли, массовая ли.
3. mcp-confluence (если передан): runbook по этой ошибке — одобренное
   решение/обход.
4. Детали (taxonomy, приоритеты, эскалация) — строго по секции `## diagnose`
   командного файла.
5. Собери диагноз: category, rootCause, fixable (правится ли правкой
   кода/конфига репозитория), fixHint, knownIssues.
6. Данных мало — честно confidence: low; не выдавай догадку за диагноз.

## Режим fix (позиция mechanic)

1. Прочитай код/конфиг по fixHint (детали — секция `## fix` командного
   файла). **Подтверди первопричину логом упавшей джобы** (MCP из
   переданного `repairRef`): не подтверждается — верни not-fixable с
   объяснением, ничего не правь.
2. Минимальная правка: только то, что нужно для первопричины.
3. Локальная проверка (TDD): (а) воспроизведи упавшее — зафиксируй «красный»
   вывод; (б) правка; (в) повтор — «зелёный». Невоспроизводимо — напиши это в
   verification и чем заменил проверку; последние строки прогона вставь
   дословно.
4. Коммит: `fix(build): <первопричина> [build #N]` / `fix(deploy): … [deploy
   #N]`. Один коммит, без мусора.
5. **prepare — карточка пуша**: ветка, коммит, суть правки. Подтверждение —
   только явное (ответ на карточку или дословное «подтверждаю …» в задании →
   `pre-approved(источник)`). Отказ → отчёт OK: false, PUSHED: false,
   GATE: declined — без пуша.
6. **apply**: push в ту же рабочую ветку. Пересборку запускает вызывающий,
   не ты.

## Ограничения

- Только MCP, переданные аргументами; реестр не читается.
- Режим diagnose — только чтение: правки, комментарии в Jira, статусы —
  запрещены.
- Пуш — только в рабочую ветку `<X>/<КЛЮЧ>`; целевые ветки (branchDefault,
  база PR) запрещены.
- Не править чужие сервисы и окружения за пределами репозитория. Статусы
  Jira не менять.

## Формат отчёта

Режим diagnose — свободный markdown с разбором, но закончи строками:

```
CATEGORY: <категория>
FIXABLE: true|false
CONFIDENCE: high|medium|low
```
(rootCause, fixHint, knownIssues — в теле отчёта.)

Режим fix:

```
OK: true|false
COMMIT: <sha или пусто>
BRANCH: <ветка или пусто>
PUSHED: true|false
GATE: confirmed | pre-approved(источник) | declined
SUMMARY: <суть правки одной строкой>
WORKTREE: <путь из pwd; пусто, если не в worktree>
```

## Соседние шаги

Диагноз fixable → режим fix (вызывает run); перезапуск после пуша —
operator. Переход — только явный вызов (пользователем или скиллом `run`):
сам следующий скилл не запускай.
