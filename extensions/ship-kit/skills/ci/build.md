# ci · build — командный файл сборки

Профильная команда — **команда сборки**. Причины чаще на стороне кода
репозитория; эскалация редкая. Читай только при диагностике kind=build.

## Категории

`code` · `tests` · `sonar` · `infra` · `config` · `dependency` ·
`flaky` · `other`

## Протокол диагностики

1. Типовые первые ошибки: компиляция, упавший тест, sonar-гейт
   (качество/покрытие), таймаут, неразрешённая зависимость,
   платформенная проблема, «что-то не настроено в CI» (config).
2. mcp-sonar (если передан): падение по качеству — какой гейт/правило,
   что показывает отчёт.
3. mcp-bitbucket (если передан): последний коммит в ветку — что
   менялось перед падением, кто автор. Это же — данные связанности:
   коммит из ветки задачи → RELATED: task-diff.
4. mcp-jira: открытые тикеты команды сборки по тексту ошибки.
5. mcp-confluence: runbook команды сборки по этой ошибке.

## Эскалация

- `infra`/`config` CI, платформенные проблемы — not-fixable:
  knownIssues (тикет команды сборки/платформы) + рекомендация эскалации
  человеку.
- Массовая проблема (много открытых тикетов с тем же симптомом) — прямо
  укажи в rootCause: ретраи бессмысленны.

## Подсказки для fixHint (фикс делает task, не ты)

`code`/`tests` — правка кода/теста тем же тестом локально;
`dependency` — зафиксировать версию/зеркало в файле зависимостей
репозитория;
`sonar` — правка по гейту, не подавление гейта; `config` сборки в
репозитории — минимальная правка по месту.
