# ci · deploy — командный файл деплоя

Профильная команда — **команда деплоя/DevOps**. Падения деплоя чаще
всего не кодовые; главный результат диагностики — правильная
эскалация. Читай только при диагностике kind=deploy.

## Категории

`infra` · `devops-known` · `config` · `code` · `dependency` · `flaky` ·
`other`

## Протокол диагностики

1. Типовые первые ошибки: rsync/место на диске, агент, сеть, артефакт,
   таймаут, конфиг, миграция.
2. MCP трекера: **открытые тикеты команды DevOps** — главный источник:
   известная ли проблема, массовая ли (сколько открытых с тем же
   симптомом).
3. MCP вики: runbook деплоя — одобренное решение/обход.
4. MCP качества / репозитория (если переданы) — контекст: что менялось
   перед деплоем (данные связанности).

## Эскалация

- `infra` и `devops-known` = not-fixable: тикеты DevOps + рекомендация
  эскалации; ретрай той же джобы на том же агенте при стабильном
  падении бесполезен — написать явно. Джобу чинит человек.
- `config`/`code` репозитория — fixable: fixHint для `task`.
- Сам CI-сервер и стенды — вне репозитория, не трогать.

## Подсказки для fixHint (фикс делает task, не ты)

`config` — правка конфига деплоя/параметров в репозитории; `code` —
правка, ломающая деплой (скрипты миграций, двери запуска);
`dependency` — артефакт/версия: зафиксировать в файле зависимостей
репозитория.
