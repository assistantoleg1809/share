# diagnosis — разбор падения джобы

На вход — упавшая джоба (kind: build/deploy, номер, хвост лога). Задача —
диагноз: категория причины, известные проблемы, fixable. Код не правишь.

**Сборку и деплой обслуживают разные команды** — инструкции и эскалация
разные, поэтому обязательный шаг:

> Определи kind и прочитай **только свой командный файл**: kind=build →
> [build.md](build.md), kind=deploy → [deploy.md](deploy.md). Другой файл
> не открывай. Читай его до анализа лога.

## Шаг 0 — проверка MCP из аргументов (обязательна)

Скилл работает с MCP, переданными аргументами вызова: до пяти alias —
`mcp-build`/`mcp-deploy` (лог упавшей джобы, по kind), `mcp-jira`,
`mcp-confluence`, `mcp-sonar`, `mcp-bitbucket`; alias → фактический сервер
знает вызывающий (файл проектов скилл не читает). Проверь каждый переданный
одним лёгким вызовом (статус сборки, поиск по ключу, получение страницы,
проект/PR, последний коммит). Хоть один недоступен — верни блок ошибки:

```
❌ MCP <переданный сервер> недоступен
Симптом: <что произошло, дословно>
Рекомендации:
1. Выполнить /mcp и посмотреть статус сервера.
2. Сверить alias с фактическим id в файле проектов
   (ship-kit.projects.md) и settings.json → mcpServers — их читает
   вызывающий, не ты.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
4. Для удалённых серверов — проверить сеть и токен.
```

Alias не передан вовсе — в проекте этого MCP нет: работай без него и честно
отметь это в отчёте (confidence ниже). Не передан ни один MCP, непонятно,
какой использовать, — запроси у пользователя и остановись до ответа; не
подбирай серверы сам.

## Протокол (общий скелет)

1. Лог джобы (mcp-build/mcp-deploy по kind): найди первую настоящую
   ошибку. Отделяй причину от последствий.
2. mcp-jira (если передан): по тексту ошибки — открытые тикеты профильной
   команды (какой — см. командный файл): известная ли проблема, массовая ли.
3. mcp-confluence (если передан): runbook/инструкции по этой ошибке —
   есть ли одобренное решение.
4. Детали по kind (taxonomy, приоритеты, источники, эскалация) — строго по
   командному файлу build.md / deploy.md.
5. Собери диагноз: category, rootCause, fixable — правится ли правкой
   кода/конфига репозитория, fixHint — конкретная подсказка для правки,
   knownIssues — найденные тикеты.

## Ограничения

- Только MCP, переданные аргументами вызова; ничего сверх них не вызывать.
  Файл проектов не читается.
- Только чтение. Правки, комментарии в Jira, статусы — запрещены.
- Данных мало — честно ставь confidence: low, не выдавай догадку за диагноз.

## Формат отчёта

category, rootCause, fixable, fixHint, knownIssues (ключ, ссылка, суть),
confidence (high/medium/low).

## Соседние шаги

Диагноз fixable — скилл `repair`; перезапуск после фикса — скилл `jobs`.
Переход — только явный вызов (пользователем или скиллом `run`): сам
следующий скилл не запускай.
