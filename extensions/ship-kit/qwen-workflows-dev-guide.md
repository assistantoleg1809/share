# Qwen Workflows — справочник разработчика

Самодостаточная выжимка: что важно знать при разработке с инструментом Workflow
(Dynamic Workflows) в Qwen Code. Без внешних ссылок — всё нужное внутри.

Проверено по Qwen Code 0.24.6 (фича активно меняется между релизами — сверяй
лимиты и ключи настроек с версией, на которой запускаешь).

---

## 1. Что это и когда применять

Workflow — модель за один ход пишет небольшой JavaScript-скрипт, который
оркестрирует субагентов: параллельные проверки, конвейеры, изолированные правки
в git-worktree, ограничение инструментов/MCP у каждого агента, бюджет токенов,
фазы с живым прогрессом и resume.

Три причины достать workflow:

1. **Comprehensive (полный охват)** — работа декомпозируется, все части
   закрываются параллельно: аудит всех вызовов API, проверка всех модулей,
   миграция по всем файлам.
2. **Confident (уверенность)** — независимые перспективы и adversarial-проверки
   до фиксации ответа: несколько подходов к дизайну, судьи, опровержение находок.
3. **Scale (масштаб)** — миграции, аудиты, широкие свипы, не влезающие в один
   контекст сессии.

**Когда НЕ применять:** короткая последовательность правок, одиночный вопрос,
задачи с жёсткими зависимостями между шагами или требующие общего контекста у
всех исполнителей. «Параллельность сама по себе» — не причина. Workflow не
заменяет обычный цикл правок.

**Мультиагентная экономика:** параллельные агенты тратят на порядки больше
токенов, чем один агент в чате. Это оправдано только когда ценность задачи
высокока. Дешёвая механика — на `effort: low`, дорогая верификация — на `high`.
Явно задавай размер в промпте: «small workflow, 5 agents max».

## 2. Включение и режимы запуска

Три уровня, все opt-in:

1. **Инструмент постоянно:** `tools.workflowsEnabled: true` в settings —
   только User/System scope, workspace-значения игнорируются. Или env
   `QWEN_CODE_ENABLE_WORKFLOWS=1` (`QWEN_CODE_DISABLE_WORKFLOWS=1` сильнее).
   Требуется рестарт.
2. **Ключевое слово на один ход:** `ultracode:` или слово `workflow` в сообщении
   человека (например `ultracode: проверь эти три модуля`). Работает только на
   интерактивный human-input: `qwen -p`, stdin и обычные SDK-строки триггер НЕ
   активируют. Вставленный в композер текст считается human-input; контекст от
   хуков — нет. Отключается `ui.disableWorkflowKeywordTrigger: true`.
3. **Session Workflow mode:** `--workflow-mode on` / `/workflows mode on` —
   сохранённое на сессию предпочтение «рассматривать Workflow для обычных
   сообщений». Напоминания модели на 1-м, 11-м, 21-м… подходящем ходе.
   Состояние разделяется: `requested` (сохранённое предпочтение) /
   `available` (инструменты доступны) / `effective` (оба). Включение требует
   доступности инструментов; SDK — опция `workflowMode`, ACP — `workflow_mode`.

Ключевое слово НЕ запускает workflow и ничего не разрешает — модель лишь
получает напоминание рассмотреть инструмент; все permissions и бюджеты
продолжают действовать.

## 3. Анатомия скрипта

Скрипт исполняется в песочнице `node:vm`. **Нет** доступа к файловой системе,
shell, сети, окружению; `import` запрещён (скрипт с `import()` вообще не
стартует). Всё I/O — только через промпты субагентам.

Начинается с литерального экспорта метаданных — он показывается человеку
**в диалоге подтверждения до запуска**:

```js
export const meta = {
  name: 'Review changes',
  description: 'Ревью диффа по измерениям с проверкой каждой находки',
  whenToUse: 'Когда нужно проверить правки перед PR',  // опц., для saved-скриптов
  phases: [
    { title: 'Review', detail: 'По одному ревьюеру на измерение' },
    { title: 'Verify', detail: 'Независимый верификатор пытается опровергнуть' },
  ],
};
```

Глобалы скрипта:

| Глобал | Назначение |
|---|---|
| `phase(title)` | объявить текущую фазу (прогресс в UI) |
| `log(msg)` | строка в лог прогона |
| `agent(prompt, opts?)` | запустить субагента; результат — текст или валидированный объект |
| `parallel(thunks)` | запустить массив thunk'ов параллельно |
| `pipeline(items, ...stages)` | конвейер: каждый item проходит все стадии |
| `workflow(nameOrRef, args?)` | вложенный вызов сохранённого workflow (1 уровень) |
| `args` | аргументы запуска (в т.ч. «сейчас» — время передают через них) |
| `budget` | бюджет прогона (`budget.total`) |

**Детерминизм обязателен:** `Math.random()` и все `Date`-функции бросают
исключение (нужно для resume-журнала). Любое «время» — через `args`.

## 4. agent() — опции и промптинг

| Опция | Что делает |
|---|---|
| `schema` | JSON Schema ответа: валидация, 3 попытки, иначе `null` |
| `model` | модель агента (дешёвые стадии — на дешёвую модель) |
| `effort` | `low…max`: механика на `low`, верификация на `high` |
| `label` | метка агента в прогресс-дереве (`review:perf`, `verify:3`) |
| `isolation: 'worktree'` | свежий git-worktree под агента (`.qwen/worktrees/agent-<hex>`); нет изменений — авто-удаление, есть — возвращаются путь и ветка |
| `workingDir` | прикрепить агента к СУЩЕСТВУЮЩЕМУ worktree (например, подготовленному предыдущей стадией) |
| `disallowedTools` | запретить инструменты: `mcp__<server>` целиком или `mcp__<server>__<tool>` точечно |
| `tools` | белый список инструментов |
| `stallMs` | watchdog «нет прогресса» с ретраями |

**Промпт агенту = задание на делегирование.** Главные причины провалов
фан-аута — расплывчатые задания: агенты дублируют работу или оставляют дыры.
Каждому агенту давай:

1. **Цель** — что конкретно сделать (не «исследуй X», а «найди все вызовы Y в Z»).
2. **Формат вывода** — что вернуть (и `schema`, если нужен объект).
3. **Ограничения** — какие инструменты/источники можно, только чтение или правки.
4. **Границы задачи** — чем НЕ заниматься, чтобы не пересечься с соседями.

Субагентам workflow **недоступны**: AskUserQuestion, SendMessage, Monitor,
Plan-mode, Agent tool. Субагент не может ни спросить человека, ни породить
своих субагентов — весь фан-аут и все развязки описываются в скрипте заранее.

**Верификатору — задачу опровергнуть.** Найти ошибку в чужой находке проще,
чем безусловно подтвердить: «Проверь опровержением: файл, утверждение. Сначала
прочти код». Выжившее после попытки опровержения — подтверждено.

## 5. parallel / pipeline — правила выживания

- `parallel` принимает **только thunks**: `() => agent(...)`.
  `parallel([agent(...)])` с готовыми промисами отказывает на корню —
  агенты уже потрачены.
- Упавший агент (или 3 неудачные попытки schema) даёт **`null`** — это штатный
  случай. Проверяй `null` в той стадии, которая звала, иначе молча потеряется
  измерение/файл: `return r === null ? [] : r.findings;`
- Стадия `pipeline`, вернувшая `null` или бросившая исключение, роняет весь
  item без запуска остальных стадий этого item (другие item живут дальше).
- `pipeline` ≠ барьер: медленный item не блокирует остальные.

---

## 6. Сохранённые workflows

- Проектный скоуп: `.qwen/workflows/<name>.js` (+ доверенные родительские
  каталоги до git-корня). Пользовательский: `~/.qwen/workflows/`.
- Имя файла = slash-команда `/name`.
- Расширения Qwen Code поставляют свои: `'<extension>:<name>'`.
- Поле `whenToUse` позволяет модели запускать сохранённый скрипт по смыслу
  запроса без явного имени.
- Вложенный `workflow(name, args)` из скрипта разрешён, один уровень вложенности;
  разделяет лимиты и бюджет внешнего прогона.
- Запуск headless: просьба к модели вызвать `Workflow({ name, args })` при
  включённых инструментах; host-приложения могут запускать сохранённые
  workflows поверх ACP (`run-saved`).

## 7. Лимиты и настройки

| Что | Значение |
|---|---|
| `tools.workflowsEnabled` | `false` по умолчанию; включает инструмент |
| `tools.workflowSizeGuideline` | `small` (<5 агентов) / `medium` (<15, дефолт) / `large` (<50) / `unrestricted` |
| `tools.workflowNameOnly` | только сохранённые по имени — модель не может писать inline-скрипты |
| `ui.disableWorkflowKeywordTrigger` | выключить keyword-триггеры |
| Параллельность | `max(2, min(16, CPU-2))`; env `QWEN_CODE_MAX_WORKFLOW_CONCURRENCY` |
| Агентов на прогон | 1000 (`QWEN_CODE_MAX_WORKFLOW_AGENTS`); список `parallel`/`pipeline` ≤ 4096 |
| Wall-clock | 30 мин (`QWEN_CODE_MAX_WORKFLOW_SECONDS`) |
| На агента | 50 ходов / 10 мин / 3 stall-ретрая |
| Бюджет | `budget.total` (директива `+500k` в сообщении или кап); по исчерпании новые `agent()` бросают исключение |

## 8. Resume

- Журнал прогона — JSON-line на событие; `resumeFromRunId` подхватывает прогон.
- Неизменённый префикс вызовов берётся из кэша, выполняются только изменённые.
- **Требование:** те же `args` (они сеют цепочку кэша) и детерминированный
  скрипт (поэтому `Date`/`Math.random` запрещены).
- Прогресс: живое дерево фаз в `/workflows`, кооперативные pause/resume/cancel.

## 9. Паттерны

Типовые однофазные формы:

| Форма | Конвейер |
|---|---|
| **understand** | параллельные читатели подсистем → синтез в общую карту |
| **design** | независимые подходы → судьи → синтез |
| **review** | измерения (корректность/безопасность/производительность) → находки → adversarial-проверка каждой |
| **research** | широкий свип → глубокое чтение → синтез |
| **migrate** | обнаружить места → преобразовать каждое в изоляции (`isolation: 'worktree'`) → проверить |

**Гибрид — скаутинг первым:** сначала в главном цикле собери список
(файлы, объём диффа, падающий тест), потом список отдай в workflow.
Fan-out по «найди само» дороже и менее предсказуем, чем fan-out по готовому
списку.

**Несколько маленьких workflows по ходам лучше одного большого безнадзорного.**

Скелет adversarial-ревью (pipeline: измерение → находки → опровержение):

```js
const reviewed = await pipeline(
  DIMENSIONS,
  async (d) => {
    const r = await agent(
      `Ревью изменений в ${args.target}: ${d.lens}. Только чтение.`,
      { label: `review:${d.key}`, schema: FINDINGS });
    return r === null ? [] : r.findings;
  },
  (findings, d) => parallel(findings.map((f, i) => async () => {
    const v = await agent(
      `Проверь опровержением: ${f.file} "${f.claim}". Сначала прочти код.`,
      { label: `verify:${d.key}:${i + 1}`, schema: VERDICT });
    return v === null ? null : { ...f, verdict: v };
  })),
);
```

Триаж упавшей сборки (последовательные фазы + параллельный второй эшелон):

```js
const err = await agent(
  `Прочитай лог ${args.logPath}. Классифицируй: sonar / компиляция / тесты / инфра / деплой.`,
  { schema: ERROR_SCHEMA });
const known = await parallel([
  () => agent(`Найди открытые тикеты по этой ошибке на ${args.devopsBoard}`, { schema: TICKETS_SCHEMA }),
  () => agent(`Проверь, массовая ли проблема (сколько тикетов с той же ошибкой)`, { schema: MASS_SCHEMA }),
]);
return { error: err, known };
```

## 10. Безопасность и корпоративное внедрение

- Подтверждение до запуска: name/description/phases показываются человеку;
  все permissions, trust и бюджеты сессии продолжают действовать.
- `tools.workflowsEnabled` ставится **только в User/System scope** —
  workspace-файл не сработает (проверяй корп. политику на этот счёт).
- Безопасный режим для корп. среды: `tools.workflowNameOnly: true` — модель
  запускает только сохранённые workflow через `Workflow({ name, args })`, каждый
  запуск покрыт правилом разрешения `Workflow(name:...)`. Name-only сессия
  предлагает только сохранённые скрипты, не предлагает писать новый.
- Точечный контроль MCP у агентов: `disallowedTools: ['mcp__confluence']`
  или белый список `tools: [...]`.
- Worktree-изоляция (`isolation: 'worktree'`) держит рабочий каталог чистым:
  нет изменений — worktree исчезает; есть — получена ветка с результатом.

## 11. Грабли (чеклист перед запуском)

- [ ] Скрипт без `import`, без `Date`/`Math.random`, без FS/shell/сети.
- [ ] `parallel([...])` — только thunks `() => agent(...)`, не готовые промисы.
- [ ] Каждый результат `agent()` проверен на `null` там, где звали.
- [ ] Стадии pipeline не предполагают, что предыдущая стадия не вернула `null`.
- [ ] Время/случайность — только через `args`; `args` неизменны для resume.
- [ ] Промпты агентам содержат цель, формат вывода, ограничения и границы.
- [ ] Размер осознан: `workflowSizeGuideline`, `budget.total`, «small, 5 agents max».
- [ ] Вложенность `workflow()` — не глубже одного уровня.
- [ ] 30-минутный wall-clock по умолчанию достаточен (или env-кап поднят осознанно).
- [ ] Верификация находок — adversarial («опровергни»), не подтверждающая.
- [ ] Скаутинг сделан в главном цикле до фан-аута.
- [ ] Для корп. среды: `workflowNameOnly` + правила `Workflow(name:...)`.
