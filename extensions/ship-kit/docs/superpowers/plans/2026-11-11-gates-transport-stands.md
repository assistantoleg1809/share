# Items-конвейер, гейты и стенды — Implementation Plan (v3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перестроить конвейер ship-kit на items-модель `item(action, skill, knowledge, PR)` с гейтами человека на необратимых действиях, стендами деплоя DEV→ST→IFT→PSI и knowledge-паками вместо привязки скиллов к бренду CI.

**Architecture:** Конвейер = последовательность item; run — диспетчер (аргумент — какой item/скилл вызвать; не задано → дефолтный конвейер openspec→build→deploy). PR — часть item; у деплоя PR может отсутствовать, когда исправления кода нет (решение — починка джобы); замечания правятся пушем в тот же PR; код-фиксы делает openspec-скилл (точный называет человек), не-кодовые падения — диагноз по MCP из реестра + knowledge-пак. Гейты 🔒 — в ролях (jobs/pr/repair), run фиксирует и стопает по отказу.

**Tech Stack:** markdown-скиллы ship-kit (`skills/*/SKILL.md`), md-реестр, python3-валидатор (создаётся планом тестов), моки `mcp/`.

**Spec:** `docs/superpowers/research/2026-11-11-loop-architecture-alternatives.md` §8 (решение + обе схемы), решения ниже.

- Командные файлы `diagnosis/{build,deploy}.md`, `repair/{build,deploy}.md` и мок `mcp/jenkins` не трогаем: первые — содержимое knowledge-пака, второй — стенд.

## Решения (финальные, 2026-11-11)

1. **items-конвейер**: item = `(action, skill, knowledge, PR)`; источники: задание > реестр > дефолт `item1(openspec) → item2(build) → item3(deploy)`. Слоты меняются независимо; `skill` поглощает прежний `impl`-параметр.
2. **PR внутри item**, не отдельная ступень. Замечания любого PR → правки → 🔒 пуш в **тот же** PR; новый PR — только на новый фикс после упавшей сборки/деплоя.
3. Между openspec и «пушем ветки + PR» других скиллов нет.
4. **run — диспетчер**: аргумент — какой item/скилл вызвать; не указан → дефолтный конвейер.
5. Код-фиксы (компиляция/тесты/замечания PR) — openspec-скилл; **точный скилл называет человек** (пауза-вопрос в точке выбора или назван в задании; фиксируется в плане).
6. Не-кодовые падения — диагноз по MCP из реестра + knowledge-пак; фикс — код/конфиг репозитория → PR. **У деплоя может отсутствовать исправление кода** — тогда PR нет вообще: решение в починке самой джобы (эскалация DevOps/тикет по диагнозу), затем повтор деплоя (🔒 гейт). Прямого пуша без PR нет.
7. **Гейты 🔒**: запуск джобы (каждый, включая каждый стенд), любой пуш, создание PR. Закрытие — только явные слова человека: ответ на вопрос (ask_user_question, карточка действия) или дословное «подтверждаю …» в задании. Отказ → `gate=declined`, run → STOPPED.
8. **Таймауты и flaky не переспрашивают**: тот же запуск (джоба+параметры+стенд) после обрыва вызова по таймауту или падения с категорией таймаута/flaky → один повтор без фикса и без нового гейта (`retryLimit`, дефолт 1); стабильное падение → item-fix. Изменение параметров/ветки/стенда или фикс между запусками — снова полный гейт.
9. **Целевые ветки запрещены**: пуш только в рабочую ветку `<X>/<КЛЮЧ>` этого прогона; `branchDefault`/база PR — никогда. Роль сверяет ветку с шаблоном и целевой (передана аргументом).
10. **Стенды**: `deploy.stands` — упорядоченное подмножество DEV, ST, IFT, PSI (канонический порядок), обязателен при `mcp-deploy.*`, IFT и PSI обязательны в составе; опционально `mcp-deploy.job.name.<СТЕНД>`. Каждый стенд — свой запуск (гейт). `runLimit.deploy` — на стенд; `runBudget` — общий, заморожен на время ожидания гейта/апрува.
11. **Транспорт-контракт**: три операции — запуск (джоба+ветка/параметры → номер+URL), статус (номер → состояние), лог (номер → текст); имена инструментов не фиксированы, опционально пинуются в реестре (`mcp-build.tool.run|.status|.log`, аналогично mcp-deploy). Бренд CI живёт в **knowledge-паке** (дефолт `jenkins` — сегодняшние командные файлы), не в текстах скиллов.

**Содержание:**

- retry-lazy (решение 8) и `retryLimit`; фиксация гейтов в журнале плана (действие, результат, источник); отказ → STOPPED с причиной «гейт отклонён»; заморозка `runBudget` в ожидании.
- Шаблон plan.md: items и их слоты, PR-N, стенды «i/n, попытка j/k», журнал гейтов.
