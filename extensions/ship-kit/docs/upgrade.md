# upgrade — рецепты синхронизации проекта при обновлении ship-kit

Комплект обновился (переустановка расширения) — проектные файлы, на
которые он опирается, могли отстать: рецепты по версиям ниже читает
человек при переустановке. Детектор дрейфа убран в 2.6.0: план прогона
строку версии не хранит, легаси-строки `ship-kit:` в планах
игнорируются. Синхронизация — решение человека: скилл конфиги
проекта не правит.

Дисциплина (для change'ов комплекта): change, меняющий проектные
ожидания (`.gitignore`, `settings.json`, макрос
`ship-kit.workflows.md`, конвейер-копии `.qwen/skills`) или поведение
Шага-0, бампает `version` в `qwen-extension.json` и добавляет секцию
ниже.

## 2.7.0 — продолжение прогона одной фразой (2026-11-23)

«продолжи <КЛЮЧ>» — канонический вход возобновления (триггер в
description `task`): остаток плана одним блоком → одно подтверждение →
слоты ведутся сами, имена скиллов человек не печатает (внешние скиллы
task вызывает сам); после закрытия слота `spec` — пауза-ревью спеки;
план живой: тех-PR дописывается слотом `pr: тех-PR`, повтор ci —
попыткой ×N; отчёты фаз при незакрытом плане завершаются строкой
`ДАЛЬШЕ: продолжи <КЛЮЧ>`. Профиль в задании назван, а файла
`ship-kit.workflows.md` или секции профиля нет — теперь честная пометка
и один вопрос (назвать слоты напрямую / продолжить без профиля), не
молчаливый дефолтный план. Обновление текстовое, формат plan.md
совместим: действующие прогоны продолжаются фразой без миграции,
действий в проекте нет.

## 2.6.0 — детектор дрейфа версии убран (2026-11-21)

План прогона больше не хранит строку `ship-kit: <версия>`: Шаг-0
`task` манифест не читает, сверки и сообщений о дрейфе нет.
Легаси-планы со строкой читаются как есть — строка игнорируется и не
переписывается. Действий в проекте не требуется; рецепты этого
changelog читаются человеком при переустановке комплекта.

## 2.5.0 — чистка по ревью 2026-11-20 (f1–f4)

В Шаге-0 `task` перечень задания сильнее тип-набора: чек-лист задания
главный, тип-набор повторно не собирается, второго вопроса нет.
Мелкие правки текстов: склеено предписание об отсутствующем alias
(task), чек-лист адаптации больше не называет конкретный спек-инструмент.
Мейн-спека: легаси-пути `skill-runs/` в активных требованиях заменены
на `runs/<ПРОЕКТ>/<КЛЮЧ>/` (легаси-чтение сохранено).

## 2.4.0 — гейты: текстовый канал — закрытый список фраз (2026-11-20)

Для headless/CI-прогонов без инструмента закрытых опций: подтверждение
гейта — только дословная фраза **целиком** из списка «да» · «ок» ·
«подтверждаю» · «подтверждаю \<действие карточки\>»; отказ — «нет» ·
«стоп». «ну да, наверное» и прочие фразы с добавками — не подтверждение
(совпадение частью фразы не считается): переспрос один раз, затем стоп.
Интерактивные сессии со структурным вопросом не меняются.

## 2.3.0 — типы задач business/technical (2026-11-20)

`task` на Шаге-0 определяет тип задачи и выполняет её набором типа.
Проектам: поставьте метки `slot:business` / `slot:technical` нужным
скиллам (в конец description SKILL.md; обе метки — универсальный
скилл) или назначьте наборы списком в конвенции проекта. Без меток и
списков: technical-задачи идут без применения скиллов (без вопроса),
business-задачи спрашивают одним вопросом «продолжить без скиллов /
назвать скиллы»; чтобы вопрос не возникал, зафиксируйте набор в
конвенции (даже явно «business — без набора»). Тип задаётся явно
маркером `(business)` / `(technical)` в задании или полем тикета;
дефолт — business.

## 2.2.0 — слоты переменных скиллов (2026-11-20)

Исполнитель спекирования ищется литеральной меткой, а не по смыслу
описания. Проектам со спек-скиллом: добавьте `slot:spec` в конец
description его SKILL.md — или назначьте слот конкретному скиллу /
перечислите набор кандидатов в конвенции проекта. Без метки и
назначения task честно уходит в мини-дизайн в чате. Метки неизвестных
комплекту слотов игнорируются — метки можно ставить вперёд
совместимости.

## 2.1.0 — детектор дрейфа версии (2026-11-20)

Проектных конфигов не касается. В plan.md появляется строка версии
`ship-kit: <версия>`; легаси-планы без строки дополняются при первом
Шаге-0 `task` без сообщения о дрейфе. Действий в проекте не требуется.

## Линия 2.0.0 — база комплекта (2026-11-14) и её накопленные изменения

Чек-лист адаптации проекта — [ship-kit.md](ship-kit.md): MCP-серверы
в `settings.json → mcpServers`, push-политика, `.gitignore: runs/`,
`permissions.allow`, опционально макрос `ship-kit.workflows.md` и файл
проектов (репо-файл мастер, центральный каталог-индекс).

Переезд с 1.x (runs-archive, 2026-11-18): каталог прогонов
`skill-runs/<КЛЮЧ>/` → `runs/<ПРОЕКТ>/<КЛЮЧ>/` — в `.gitignore`
проекта добавить `runs/` (легаси `skill-runs/` оставить, если был);
легаси-планы читаются при возобновлении, новые прогоны — только в
`runs/`; worktree прогона — `<ПРОЕКТ>-<КЛЮЧ>`; завершённые прогоны
архивируются в `runs/archive/<ПРОЕКТ>/<КЛЮЧ>/`.
