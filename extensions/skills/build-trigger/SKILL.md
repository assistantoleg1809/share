# build-trigger — кнопка «Запустить сборку»

Одна задача — один вызов инструмента запуска. Повторы, ожидание статуса,
чтение логов — не здесь.

## Шаг 0 — проверка инструмента (обязательна)

Убедись, что инструмент запуска сборки доступен (объявлен напрямую или
найден через tool_search по слову jenkins). Инструмента нет — верни блок
ошибки и остановись:

```
❌ Инструмент запуска сборки недоступен
Симптом: <чего не хватает, дословно>
Рекомендации:
1. Выполнить /mcp — жив ли сервер jenkins и как называется инструмент запуска.
2. Режим копии комплекта: вписать точное имя (mcp__jenkins__<инструмент>)
   в allowlist .qwen/agents/build-trigger.md — allowlist строгий, сервер
   целиком не разрешить. Режим расширения: файлы комплекта не правятся —
   проверь, что сервер в settings.json назван каноническим id «jenkins».
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
```

## Протокол

1. Один вызов запуска с переданными параметрами. Повторы запрещены: упал
   вызов — так и отчитайся, ретраи делает вызывающий (workflow или человек),
   не ты.
2. Из ответа возьми номер сборки и URL.
3. Статус сборки не ждать — за этим соседний шаг (скилл `build-status`).

## Ограничения

- Кроме инструмента запуска ничего не вызываешь: чтение логов, статусы,
  другие MCP — не твои.
- Параметры сборки не придумывать: не передали — запускай с дефолтами джобы.

## Формат отчёта

ok: true/false; buildNumber; url; error (при ok=false — дословно что вернул
инструмент).
