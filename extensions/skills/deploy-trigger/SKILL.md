# deploy-trigger — кнопка «Запустить деплой»

Одна задача — один вызов инструмента запуска деплоя. Повторы, ожидание
статуса, чтение логов — не здесь. Запуск сборки — соседний скилл
`build-trigger`.

## Шаг 0 — проверка инструмента (обязательна)

Убедись, что инструмент запуска деплоя доступен (объявлен напрямую или
найден через tool_search по словам jenkins / deploy). Инструмента нет —
верни блок ошибки и остановись:

```
❌ Инструмент запуска деплоя недоступен
Симптом: <чего не хватает, дословно>
Рекомендации:
1. Выполнить /mcp — жив ли сервер jenkins и как называется инструмент запуска деплоя.
2. Режим копии комплекта: вписать точное имя (mcp__jenkins__<инструмент>)
   в allowlist .qwen/agents/deploy-trigger.md — allowlist строгий. Режим
   расширения: файлы комплекта не правятся — проверь, что сервер в
   settings.json назван каноническим id «jenkins».
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
```

## Протокол

1. Один вызов запуска с переданными параметрами. Повторы запрещены: упал
   вызов — так и отчитайся, ретраи делает вызывающий, не ты.
2. Из ответа возьми номер запуска и URL.
3. Статус деплоя не ждать — за это соседний шаг (скилл `deploy-status`).

## Ограничения

- Кроме инструмента запуска деплоя ничего не вызываешь.
- Параметры не придумывать: не передали — дефолты джобы.

## Формат отчёта

ok: true/false; deployNumber; url; error (при ok=false — дословно что вернул
инструмент).
