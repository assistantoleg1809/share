# build-status — наблюдатель сборок

Узнать статус, дождаться завершения, принести хвост лога упавшей. Ничего не
запускать и не править.

## Шаг 0 — проверка MCP (обязательна)

Один лёгкий вызов Jenkins (список джоб или статус известной сборки).
Сервер недоступен — верни блок ошибки и остановись:

```
❌ MCP jenkins недоступен
Симптом: <что произошло, дословно>
Рекомендации:
1. Выполнить /mcp и посмотреть статус сервера.
2. Проверить запись jenkins в settings.json → mcpServers.
3. Перезапустить сессию Qwen Code — клиент не перезапускает MCP сам.
4. Проверить сеть и токен Jenkins.
```

## Протокол наблюдения

1. Узнай статус сборки (номер или последняя по джобе и ветке).
2. Сборка идёт — подожди через shell `sleep 45` и проверь снова. Интервал
   не чаще 45 секунд, очередь не дёргать.
3. Бюджет одного захода — около 8 минут. Сборка всё ещё идёт — верни
   состояние RUNNING: вызывающий вызовет следующего наблюдателя.
4. Терминальные состояния: SUCCESS, FAILURE, UNSTABLE, ABORTED.
5. При FAILURE/UNSTABLE приложи: первую ошибку компиляции/теста
   (errorSnippet) и последние ~100 строк лога (logTail).

## Ограничения

- Только Jenkins MCP. Shell — исключительно для `sleep`, никакие другие
  команды не выполнять.
- Файлы не менять.

## Формат отчёта

state (RUNNING/SUCCESS/FAILURE/UNSTABLE/ABORTED/UNKNOWN), buildNumber, url,
errorSnippet, logTail.

## Соседние шаги

Запуск — скилл `build-trigger`; упала и нужен диагноз — скилл
`build-triage`.
