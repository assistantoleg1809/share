# ship-kit-task — разработка

Фаза разработки: контекст → (спека) → TDD → коммиты. Коммитишь, но не
пушаешь — пуш у `ship-kit-pr`. Один вызов = одна фаза: один Шаг-0,
работа, один отчёт. Общие инварианты — [reference.md](reference.md).

## Правила действий

| действие | правило |
|---|---|
| чтение (трекер, вики, код — из переданных MCP) | allow |
| локальный коммит в рабочую ветку | allow |
| пуш / создание PR | не твой шаг — `ship-kit-pr` |
| всё сверх переданных MCP | deny |

## Шаг 0

1. **MCP**: каждый переданный alias проверь лёгким вызовом (поиск по
   ключу задачи, дешёвый запрос). Лесенка алиасов: задание >
   конвенция проекта > один вопрос человеку. Конвенция: файлы проекта;
   несколько источников — репо-файл (cwd) мастер, центральный каталог —
   автособираемый индекс, руками не правится; одно имя в обоих —
   действует репо-файл. Запись назвала репозиторий (SSH), а cwd не он —
   склонируй в рабочую папку и работай в клоне (SSH-ключи машины, не
   гейт). Конкретный alias нигде не назван — этого MCP в проекте нет:
   работай без него, отчитайся. Ни алиасов, ни конвенции — вопрос и
   стоп. Роли: **tracker · docs · repo · build · deploy · quality ·
   vuln · chat**; несколько MCP роли — через запятую (чтение по всем,
   запись — куда назвало задание, иначе вопрос). Хоть один недоступен —
   стоп с блоком:

```
❌ MCP <сервер> недоступен
Симптом: <дословно>
1. /mcp — статус. 2. Сверить alias с settings.json → mcpServers.
3. Перезапустить сессию.
```

   Транспортный сбой (таймаут/обрыв MCP/git) — авто-повтор того же
   вызова до 2, без вопросов; исчерпаны — ошибка и стоп.

2. **План прогона — всегда**: найди/создай план-файл (первый вызов
   фазы по ключу — создай). Директория прогона: задание > конвенция >
   дефолт `.qwen/tmp/ship-kit/<КЛЮЧ>/` (временная, проектная .qwen;
   определённая — с уровнем `<ПРОЕКТ>`); issues.md — рядом; журнал:
   каждая запись с `ГГГГ-ММ-ДД ЧЧ:ММ` (локально), затем событие.
   `<ПРОЕКТ>` — из конвенции, иначе имя каталога репо; worktree
   прогона — `<ПРОЕКТ>-<КЛЮЧ>` (строка `worktree: <путь>` в плане).
   План по умолчанию = установленные фазы: `ship-kit-pr` /
   `ship-kit-ci` ищи в списке скиллов сессии; имени нет — «фаза не
   установлена» в плане и отчёте, слот исключается, без вопроса.
   Задание перечислило внешние скиллы — чек-лист: перечисление по
   порядку + слоты фаз комплекта на названных местах (не названы — в
   хвосте доставки; неустановленная фаза — пометка, слот
   пропускается) одним блоком, одно подтверждение: согласие =
   утвердительная опция закрытого вопроса, текст вне опций —
   переспрос один раз, стоп; текстовый канал — фраза **целиком** из
   «да» · «ок» · «подтверждаю» · «подтверждаю <действие>» (полный
   текст гейта — reference.md). Внешних скиллов нет — план по
   умолчанию без вопроса. «Профиль X» — разверни
   `ship-kit.workflows.md` проекта; профиль назван, а файла/секции
   нет — пометка + один вопрос закрытыми опциями (назвать слоты
   напрямую / продолжить без профиля).
   **Резюм** («продолжи <КЛЮЧ>» — канонический вход): прочитай план,
   сверься с фактическим состоянием (git: ветка/коммиты; статусы
   PR/джоб), найди следующий незакрытый слот. Однозначно — остаток
   плана одним блоком + одно подтверждение закрытыми опциями; после
   «да» веди слоты сам до конца плана — внешние скиллы и фазы
   комплекта вызывай инструментом вызова скиллов, человек имена не
   печатает. Сомнение (несколько слотов без порядка, расхождение с
   git, ключ не найден) — один вопрос закрытыми опциями: слоты /
   другой ключ / новая задача. Внешний скилл слота не в списке
   сессии — пометка + вопрос «пропустить / стоп». 🔒-гейты резюм не
   преодолевает. План живой: тех-фикс дописывай слотом `pr: тех-PR`,
   повтор сборки — попыткой ×N в строке слота; дописывание показывай
   на ближайшей 🔒-карточке или вопросе.

3. **Спецификация** (задание просит спеку или правка меняет поведение
   из спеки): исполнитель — слот `spec`. Каскад: задание (назвало
   инструмент — работай им) > конвенция (обязывает спеку / назначает
   слот / перечисляет кандидатов — тогда один вопрос; конвенция
   сильнее умолчания, задание сильнее конвенции) > метка `slot:spec` в
   descriptions скиллов сессии (дословный поиск; несколько — один
   вопрос). Ноль кандидатов — мини-дизайн в чате + пометка в отчёте.
   Реализация — по чек-листу изменения, не по структуре каталогов.

4. **Тип задачи**: `business`/`technical` каскадом — маркер
   `(business)`/`(technical)` в задании > поле/лейбл тикета > правило
   конвенции > дефолт business. Набор типа: скиллы с меткой
   `slot:business`/`slot:technical` (обе — универсальный) либо список
   конвенции (сильнее меток). Перечень задания сильнее набора типа:
   чек-лист п.2 главный, набор повторно не собирается. Пустой набор:
   technical — правка без скиллов, молча, строка в отчёте; business —
   один вопрос (продолжить без / назвать скиллы); явная запись
   конвенции вопрос убирает. Смешанная задача — расщепи в плане на
   части с типами (тикет не делится). Строкой в план и отчёт: тип,
   источник, состав набора.

## Работа

- Лёгкий путь (фикс/мелочь): контекст → правка → коммит, без спеки.
- Полный: спека (Шаг 0.3) → реализация по её чек-листу.
- TDD: сначала падающий тест, потом код; атомарные коммиты с ключом
  задачи; ветка/worktree из задания.

### fix — по замечанию ревью или диагнозу CI

Вход: текст замечания или диагноз (категория, fixHint, связанность с
диффом ветки задачи).

- Связанный (первопричина в диффе ветки): минимальная правка в ветку
  задачи; красный → правка → зелёный.
- Посторонний (инфра/конфиг CI/чужой код): тех-ветка от базовой,
  минимальная правка; артефакты спеки не трогать вовсе.
- Смежные улучшения не трогай. Невоспроизводимо — напиши, чем заменил
  проверку. Коммит: `fix(<сфера>): <суть> [PR-N | build #N]`.

## Верификация

Перед `OK: true` — дословные последние строки прогона/компиляции,
свежие, этого вызова. Без свежих доказательств успех не заявляй.

## Ограничения

- Только MCP из аргументов вызова; ничего сверх них.
- Статусы трекера не менять; комментарии — только по явной просьбе.
- Пуш — только через `ship-kit-pr`; прямого пуша нет.
- Ничего не искать: джобы, пути, репозитории — из задания или
  вопроса, не сканированием.

## Отчёт

Дословные строки прогона — прямо над блоком. Заверши строками (по
одной, без маркдауна):

```
OK: true|false
CHANGE: <id изменения или пусто>
SPEC: <инструмент | chat-design | пусто — не требовалась>
BRANCH: <ветка или пусто>
GATE: — (гейты пуша/PR у ship-kit-pr)
SUMMARY: <суть одной строкой>
HANDOFF: pr | pr(тех-PR) | —
ДАЛЬШЕ: продолжи <КЛЮЧ> (план не закрыт; закрыт — строки нет)
```

## Завершение фазы

- Слот `spec` закрыт — пауза-ревью: вопрос закрытыми опциями
  «продолжить / доработать / стоп»; следующий слот — только после
  «продолжить».
- Дальше — следующий незакрытый слот плана без остановки (паузы —
  только 🔒-карточки и вопросы правил). Конец плана — стоп:
  предложи архивацию прогона — `<корень>/archive/<КЛЮЧ>/` (корень —
  каскад; дефолт временный — пометь); worktree `<ПРОЕКТ>-<КЛЮЧ>` —
  выбор человека: удалить (гейт; ветки не трогаем) или `git worktree
  move` в архив. «архивируй прогон <КЛЮЧ>» — и одиночным вызовом.
- Одиночный вызов вне плана или «только этот шаг» — выполни и стоп.
  Посторонний тех-фикс — `ship-kit-pr` отдельным тех-PR.
