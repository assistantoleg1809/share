# ship-kit — общие инварианты

Справка для всех фаз (`ship-kit-task` / `ship-kit-pr` / `ship-kit-ci`);
исполнение — по SKILL.md фазы (правила продублированы там по ходу).
Установка — копией каталогов (можно частично); соседние фазы видны в
списке скиллов сессии.

## Фаза и цепочка

- Один вызов = одна фаза: Шаг-0 → работа → один отчёт.
- Цепочка авторизована планом: закрытый слот продолжается следующим
  незакрытым — модель вызывает его сама; паузы — только 🔒-гейты и
  вопросы правил; конец плана — стоп.
- Одиночный вызов человеком вне плана — без цепочки.
- Незакрытый план — отчёт фазы кончается `ДАЛЬШЕ: продолжи <КЛЮЧ>`.

## Аргументы и MCP

- Лесенка: задание > конвенция проекта > один вопрос человеку
  (закрытыми опциями, если инструмент вопроса есть в сессии).
  Конвенции может не быть — обязательное не названо: спроси.
- Роли MCP: tracker · docs · repo · build · deploy · quality · vuln ·
  chat; несколько серверов роли — через запятую: чтение по всем,
  запись — куда назвало задание, иначе один вопрос.
- Alias не назван нигде — этого MCP в проекте нет: работай без него,
  отчитайся. Ни одного и конвенции нет — вопрос и стоп.
- Транспортный сбой (таймаут/обрыв MCP или git) — авто-повтор того же
  вызова до 2, без вопросов и повторного гейта; исчерпаны — ошибка и
  стоп.

## Гейты 🔒 — три правила

Необратимое (пуш, создание PR, запуск джобы, ответы на комментарии):
карточка-превью → явное «да» → действие; отказ = стоп без перебора;
дословное «подтверждаю …» в задании = pre-approved. Инструмент
закрытых опций есть — гейт им: текст вне опций ≠ подтверждение
(ответь на содержание, переспроси один раз, стоп). Нет — текстовый
канал: подтверждение = фраза целиком из «да» · «ок» · «подтверждаю» ·
«подтверждаю <действие карточки>»; отказ — «нет» · «стоп»; прочее —
переспрос один раз, затем стоп.

## Границы

- Пуш — только в рабочие ветки `<X>/<КЛЮЧ>` (или тех-ветку от
  базовой); целевые ветки (main/master/develop/release, база PR) —
  запрещены, сверяй до любых действий.
- Статусы задач трекера не менять; комментарии — по явной просьбе.
- Ничего не искать: джобы/пути/PR/репозитории — из задания, конвенции
  или вопроса, не сканированием.
- Правки репозитория — только через PR.

## План-файл прогона

- Директория: задание > конвенция > дефолт `.qwen/tmp/ship-kit/<КЛЮЧ>/`
  (временная, проектная .qwen); определённая — с уровнем проекта
  `<директория>/<ПРОЕКТ>/<КЛЮЧ>/`. issues.md — рядом с планом.
- Каждый запуск материализует план: найти по ключу или создать
  (первый вызов любой фазы).
- Журнал: каждая запись с `ГГГГ-ММ-ДД ЧЧ:ММ` (локальное время), затем
  событие; записей без даты не писать.
- `<ПРОЕКТ>` — из конвенции, иначе имя каталога репозитория; worktree
  прогона — `<ПРОЕКТ>-<КЛЮЧ>`.
- Архив завершённого прогона — `<корень>/archive/<КЛЮЧ>/` (корень —
  тот же каскад; дефолтный — временный, пометь в отчёте).
- План по умолчанию = установленные фазы (`task → pr 🔒 → ci 🔒`);
  неустановленная фаза — пометка «фаза не установлена», слот
  исключается, без вопроса.
- Резюм: «продолжи <КЛЮЧ>» — канонический вход `ship-kit-task`; скилл
  читает план, сверяется с фактическим состоянием и продолжает.

## Верификация

`OK: true` — только с дословными свежими строками прогона/статусов
этого вызова; без свежих доказательств успех не заявляй.
