# ship-kit-ci — запуск, ожидание, диагноз

Фаза CI: запускаешь, ждёшь, читаешь лог, ставишь диагноз. Правки
репозитория — не твои (их делает `ship-kit-task` по диагнозу).
Следующую фазу сам не запускаешь. Общие инварианты —
[reference.md](reference.md).

## Правила действий

| действие | правило |
|---|---|
| чтение статуса/лога/тикетов/runbook | allow |
| запуск джобы | ask · всегда (карточка) |
| правки репозитория, пуш, статусы трекера | deny |
| всё сверх переданных MCP | deny |

## Шаг 0

1. **MCP**: лёгкий вызов каждого переданного сервера (статус известной
   джобы, поиск по ключу задачи); недоступен — блок ошибки и стоп
   (как в `ship-kit-task`). Лесенка: задание > конвенция > один
   вопрос. Alias нигде не назван — этого MCP в проекте нет: работай
   без него, отчитайся (confidence ниже); ни одного и конвенции нет —
   вопрос и стоп. Роли MCP — как в `ship-kit-task`. Транспортный
   сбой — авто-повтор до 2, потом стоп.
2. **План прогона**: найди по ключу (директория: задание > конвенция >
   дефолт `.qwen/tmp/ship-kit/<КЛЮЧ>/`); нет — создай (любая фаза
   входная), пометь слоты невыставленных фаз «фаза не установлена»;
   issues.md — в директории прогона; записи журнала — с
   `ГГГГ-ММ-ДД ЧЧ:ММ`, затем событие.

## Гейт запуска — три правила

Карточка-превью → явное «да» → запуск; отказ = стоп; дословное
«подтверждаю …» в задании = pre-approved с источником. Согласие —
утвердительная опция инструмента закрытых опций; текст вне опций ≠
подтверждение (ответь на содержание, переспроси один раз, стоп);
текстового инструмента нет — фраза **целиком** из списка «да» · «ок» ·
«подтверждаю» · «подтверждаю <действие>», отказ — «нет» · «стоп».
Карточка запуска: kind (build/deploy), джоба (имя/путь), ветка и
**её источник** (MERGED-база или рабочая ветка — по решению человека
при расхождении статуса PR), стенд (для деплоя), параметры — **с
источником каждого**: задание → конвенция → прошлая успешная джоба →
ответ человека. Сборка на рабочей ветке — только после явного «да»;
успех на неподтверждённой базе помечай в плане ⚠ (жёлтым), не
зелёным. Прошлой успешной нет и аргументы не названы — спроси, не
запускай молча. **Ничего не искать**: джобы не перечислять, сервер не
сканировать, пути не угадывать.

## Запуск и ожидание

Запусти, наблюдай статус; долгая джоба — отчитывайся этапами, а не
молчи. Итог: SUCCESS/FAILURE/UNSTABLE + номер и URL джобы.

## Flaky-повтор

Таймаут вызова или явно flaky в логе — предложи повтор тех же
параметров одной строкой «повторить те же параметры?» (закрытыми
опциями при наличии). Максимум один повтор подряд; дальше —
диагностика.

## Диагностика падения

Определи kind (build/deploy — из задания или имени джобы) и читай
**только свой командный файл**: build → [build.md](build.md), deploy →
[deploy.md](deploy.md).

1. Лог: найди первую настоящую ошибку; причину отдели от последствий.
2. Тикеты и runbook — из переданных MCP, по протоколу командного
   файла.
3. Диагноз: категория, rootCause, fixable (правится ли правкой
   кода/конфига репозитория), fixHint, knownIssues и **связанность** —
   первопричина в диффе ветки задачи или вне его (сверь с последними
   коммитами ветки через MCP repo/git).
4. Данных мало — честно confidence: low; догадку за диагноз не
   выдавай.

### Исходы диагноза

- fixable, первопричина **в диффе задачи** → HANDOFF: `ship-kit-task`
  (fix в ветку задачи, доставка в тот же PR).
- fixable, **посторонний** (инфра/конфиг CI/чужой код) → HANDOFF:
  `ship-kit-task` (тех-ветка от базовой, отдельный PR; артефакты спеки
  не трогать).
- не-код (infra/devops-known и т.п.) → задача в issues.md прогона +
  рекомендация эскалации человеку.
- Перезапуск после фикса — новая карточка запуска.

## Верификация

В отчёт — дословный хвост лога (последние строки джобы) и статус с
номером. Без свежих строк успех не заявляй.

## Ограничения

- Только переданные MCP; правки репозитория запрещены.
- Статусы трекера не менять. Ничего не искать.
- План прогона отмечай в план-файле по каскаду директории; записи
  журнала — с даты и времени.

## Отчёт

Разбор диагноза — свободным текстом в теле, дословный хвост лога —
над блоком. Заверши строками:

```
OK: true|false
JOB: <имя джобы> · #<номер> · <SUCCESS|FAILURE|UNSTABLE|—>
CATEGORY: <категория или пусто>
FIXABLE: true|false
RELATED: task-diff | external | —
CONFIDENCE: high|medium|low
HANDOFF: ship-kit-task | ship-kit-task-tech | human | —
ДАЛЬШЕ: продолжи <КЛЮЧ> (план не закрыт; закрыт — строки нет)
```

## Завершение фазы

Падение fixable — продолжай без остановки фазой фикса: вызови
`ship-kit-task` (fix по диагнозу), после него — перезапуск слота ci
под новой 🔒-карточкой. Не-код — issues.md и стоп. Зелёные фазы до
конца плана — финальный отчёт, предложение архивации прогона (правило
`ship-kit-task`: архив `<корень>/archive/<КЛЮЧ>/`, судьба worktree —
выбор человека) и стоп. Одиночный вызов человеком вне плана — без
цепочки.
