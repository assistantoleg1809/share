# Workflows или субагенты: критерии выбора

## Коротко

**Оба. Субагенты — исполнители, Workflow — конвейер.**

| Критерий | Субагенты (agent-delegation, superpowers) | Qwen Workflows |
|---|---|---|
| Природа задачи | одноразовая, исследовательская, интерактивная | повторяемый процесс с фикс. шагами |
| Гарантии формата | на промпте | JSON Schema + валидация (3 попытки, иначе null) |
| Лимиты/бюджет | общий контекст сессии | на прогон: 30 мин wall-clock; на агента: 50 ходов/10 мин; budget.total |
| Отказоустойчивость | упал — заметил человек | null-протокол + resume прогона |
| Параллельность | вручную | parallel/pipeline из thunks |
| Изоляция правок | worktree вручную (скилл using-git-worktrees) | `isolation:'worktree'` у агента |
| Контроль MCP | permissions сессии | `disallowedTools`/`tools` на каждого агента |
| Цена | дёшево для 1–2 задач | фан-аут дорог; оправдан конвейером |

## Правило большого пальца

- Одноразовая задача или вопрос → **субагент** (или вообще без него).
- Процесс, который повторяется и должен быть предсказуем (сборка→триаж→фикс→пересборка) → **workflow**, внутри которого работают субагенты.
- Несколько маленьких workflows по ходам лучше одного большого безнадзорного (dev-guide §9).

## В этом проекте

- `build-failure-triage` — workflow: две фазы, параллельный второй эшелон, схемы ответов.
- `build-fix-loop` — workflow-конвейер; исполнители (триаж, чеки, фикс) — субагенты с точечными правами.
- Superpowers-скиллы (TDD, systematic-debugging) задают дисциплину промптов агентов.
