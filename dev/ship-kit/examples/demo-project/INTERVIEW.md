# INTERVIEW — интервью-тест примера demo-project

Дешёвая проверка вместо отложенных агентных тестов: пример считается
готовым, если свежий читатель (человек или модель) отвечает на вопросы
**только по файлам примера**, не подглядывая в спеки и конвейер.

## Инструкции по прохождению

**Общие правила (оба режима).** Открывать разрешено ТОЛЬКО
`examples/demo-project/**` (README.md, ship-kit.projects.md,
ship-kit.workflows.md, skill-runs/PRJ-777/, repo/) и, при острой нужде,
справочник базы `extensions/ship-kit/docs/ship-kit.md`. До окончания —
НЕ открывать `openspec/`, `examples/conveyor/`, спеки и архивы.
Эталоны (курсив под вопросом) читать только ПОСЛЕ своего ответа.
Ответы записывать дословно.

**Режим А — человек-коллега (основной).** Ведущий = любой, кто не
участвовал в дизайне. 20–30 минут, вопросы по порядку 1→15, на
вопросах 1–13 отвечать письменно одним-тремя предложениями; вопрос 15 —
засечь время. После каждого ответа ведущий сверяет с эталоном и
ставит GREEN/RED.

**Режим Б — модель (точечный).** Один вопрос = один вызов, модель
только glm-5.3-flash, из корня репо, командой:

```
qwen --model glm-5.3-flash -p "<вопрос, дословно> Отвечай ТОЛЬКО по файлам examples/demo-project (README.md, ship-kit.projects.md, ship-kit.workflows.md, skill-runs/PRJ-777/, repo/), кратко: ответ + файл-источник."
```

**Оценка.** Закрытые 1–13: GREEN = совпадение с эталоном по ключевым
точкам. Итог: **≥11/13 GREEN** + разумные ответы 14–15 → пример принят;
9–10 → точечные правки файлов по таблице ниже; **≤8 → README не доносит
модель, пример дорабатывать целиком**. Вопрос 15: найдено за ≤2 мин =
GREEN. Результаты — в «Журнал прохождений».

## Вопросы и эталоны

1. **Источник аргументов.** По каким данным агент сессии собрал вызов
   `/ship-kit:task PRJ-777 …, mcp-jira=jira-corp, …`?
   *Эталон:* из `ship-kit.projects.md` — агент читает файл как контекст
   проекта и подставляет значения в аргументы вызова.
2. **Читает ли скилл `task` файл проектов?**
   *Эталон:* нет — скиллы работают только с MCP из аргументов вызова;
   файл — контекст агента/человека.
3. **Порядок прогона.** Откуда взялся чек-лист прогона и сколько раз
   его подтверждали?
   *Эталон:* макрос «feature» из `ship-kit.workflows.md` развернулся в
   перечень; одно подтверждение одним блоком; далее порядок живёт в
   `skill-runs/PRJ-777/plan.md`.
4. **Спека.** Как выбрали инструмент спекирования и попало ли его имя
   в файлы комплекта?
   *Эталон:* discovery по списку скиллов сессии (в примере найден
   openspec-скилл); имя в комплект не вшито нигде.
5. **Карточка «пуш+PR».** Когда она показана и сколько карточек на
   пуш + создание PR?
   *Эталон:* на входе в фазу `pr`; одна карточка на оба действия;
   повторный вопрос — только на новое действие.
6. **Подсчёт гейтов.** Перечислите все 🔒-карточки прогона PRJ-777 по
   журналу plan.md.
   *Эталон:* 7 — «пуш+PR», build #114, DEV #57, ST #23, ST #24, IFT #9,
   PSI #6; каждый запуск джобы — своя карточка.
7. **Падение ST #23 (infra).** Что сделал `ci` и чего НЕ делал?
   *Эталон:* диагноз по kind-файлу deploy (тикет DEVOPS-311, runbook),
   FIXABLE: false → задача в issues.md + эскалация DevOps; правок репо
   нет, ретрай не предлагался (стабильное инфра-падение).
8. **Почему не тех-ветка?** ST #23 — посторонняя ошибка, но тех-ветки
   не было. Почему?
   *Эталон:* fixable=false — первопричина вне репозитория; тех-ветка —
   только для постороннего **fixable** (правки в репо).
9. **Возобновление.** Что произошло по команде «продолжи PRJ-777»?
   *Эталон:* план прочитан, сверен с реальностью (статусы джоб/PR),
   продолжение с зафиксированного шага — новая карточка запуска ST.
10. **Если бы вместо infra был таймаут.** Что изменилось бы в
    поведении ci?
    *Эталон:* переспрос одной строкой «повторить те же параметры?», не
    более одного повтора подряд, без карточки-разбора; упал повтор —
    диагностика.
11. **Связанный фикс.** Build упал на строке, добавленной веткой
    задачи. Куда идёт правка?
    *Эталон:* `task` fix в ветку задачи → доставка пушем в тот же PR-1.
12. **Посторонний fixable.** Сборка упала из-за конфига CI в репо,
    вне диффа задачи. Маршрут?
    *Эталон:* `task` тех-фикс: ветка от базовой main → отдельный
    тех-PR; артефакты спеки не тронуты.
13. **Верификация.** Где в примере «дословные строки» и что они
    разрешают?
    *Эталон:* хвост лога над блоком `OK: true`, статусы с номерами
    джоб; без свежих дословных строк успех не заявляется.
14. **Открытый.** Уберите `ship-kit.workflows.md` — что сломается?
    *Эталон:* ничего критичного: порядок назовёт задание, не назван —
    один вопрос; макрос опционален.
15. **Практический (засечь ≤2 мин).** Найдите в `ship-kit.projects.md`
    строку, из которой взята джоба деплоя стенда ST.
    *Эталон:* секция «Джобы CI», deploy: джоба `calc-app-deploy`,
    стенды DEV→ST→IFT→PSI (стенд — параметром STAND).
