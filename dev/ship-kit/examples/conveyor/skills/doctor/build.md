# doctor · build — командный файл сборки

Профильная команда — **команда сборки**. Причины чаще на стороне кода
репозитория; эскалация редкая, в основном к владельцам платформенных
инструментов. Читай **только секцию своего режима**.

## diagnose

### Taxonomy категорий

`code` · `tests` · `sonar` · `infra` · `config` · `dependency` · `flaky` ·
`other`

### Что искать (в порядке протокола)

1. Типовые первые ошибки: компиляция, упавший тест, sonar-гейт (качество/
   покрытие), таймаут, неразрешённая зависимость, платформенная проблема,
   «что-то не настроено в Jenkins у меня» (config).
2. mcp-sonar (если передан): падение по качеству — какой гейт/правило, что
   показывает отчёт.
3. mcp-bitbucket (если передан): последний коммит в ветку — что менялось
   перед падением, кто автор.
4. mcp-jira: открытые тикеты команды сборки по тексту ошибки.
5. mcp-confluence: runbook команды сборки по этой ошибке.

### Эскалация

- `infra`/`config` Jenkins, платформенные проблемы — not-fixable: knownIssues
  (тикет команды сборки/платформы) + рекомендация эскалации.
- Массовая проблема (много открытых тикетов с тем же симптомом) — прямо
  укажи в rootCause: ретраи бессмысленны.

## fix

Чинить сборку — значит править **репозиторий** (код, тест, конфиг сборки в
репо, версии зависимостей). Сверяй первопричину логом **упавшей** джобы из
переданного `repairRef` (у фикс-стадии быстрая ci-джоба — не тот лог).

Типовые маршруты:

- `code`/`tests` — правка кода/теста; локально: `красный → правка → зелёный`
  тем же тестом/компиляцией.
- `dependency` — зафиксировать версию/зеркало в манифесте зависимостей
  репозитория.
- `sonar` — правка по гейту (не подавлять гейт без явного указания).
- `config` сборки в репозитории (например, Jenkinsfile) — минимальная правка
  по fixHint; не трогать чужие узлы.
- `infra`/платформенное — **не твой случай**: верни not-fixable с
  эскалацией, ничего не правь.
