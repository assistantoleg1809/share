# central-catalog — общий репозиторий с файлом проектов

Пример второго представления конвенции проекта: **один общий репозиторий
с каталогом всех проектов команды** (первое — файл проекта в каждом
репо, как в [../demo-project](../demo-project/ship-kit.projects.md)).
Оба представления поддерживаются каскадом:

**задание > репо-файл проекта (cwd, мастер) > центральный каталог
(индекс) > один вопрос**

Подробности механики —
[../../extensions/ship-kit/docs/ship-kit.md](../../extensions/ship-kit/docs/ship-kit.md),
пункт 7.

## Кто чем владеет

| Файл | Роль | Кто правит |
|---|---|---|
| `ship-kit.projects.md` в репо проекта | **мастер** записи | разработчик, руками |
| `projects.index.md` здесь | автособираемое зеркало | только генератор |

Ручные правки индекса запрещены: правка записи — в репо-файле проекта,
затем пересборка. Коллизия одинаковых имён между репо-файлом и
каталогом — в пользу репо-файла; дубликат внутри каталога — ошибка
сборки (генератор падает, индекс не обновляется).

## Сборка индекса

```bash
node collect.mjs <репо1> [репо2 ...]
```

Генератор без зависимостей (node:fs/node:path): читает
`ship-kit.projects.md` каждого репо, берёт имя проекта из заголовка
`## <имя>`, контролирует уникальность и пишет `projects.index.md`
рядом с собой — полное зеркало записей с маркером автогенерации,
датой и путём источника каждой записи. В живом центральном репо его
запускает cron/CI-джоба; здесь — руками (проверено на demo-project,
см. git-историю индекса).

Имя файла проектов и формат записи — конвенция организации: скиллы
ship-kit их не фиксируют, каталог для сессии — обычный текстовый
контекст.

## Доступ

Центральный репо **закрытый**: индекс содержит SSH-адреса и конфигурацию
всех проектов команды. Члены команды — чтение, CI-джоба генератора —
запись.

## Как сессия использует каталог

1. cwd — репозиторий проекта со своим файлом проектов → работает
   репо-файл, каталог не нужен.
2. cwd вне репо (рабочая папка сессии), задание назвало проект или
   ключ задач → агент сессии находит запись в `projects.index.md`,
   подставляет аргументы вызова (mcp-алиасы, джобы, ветки) и — по
   репозиторию из записи — `task` клонирует проект и работает в клоне.
3. Ничего не нашлось — один вопрос человеку.
