# INSTRUCTION — проверка ship-kit на стенде (без истории сессии)

Самодостаточная инструкция: запускающему (человеку или свежему агенту)
контекст прошлых сессий не нужен.

**Контекст.** Репо `~/projects/share`, ветка `v3`. Поставка — три
скилла `skills/ship-kit-task` · `ship-kit-pr` · `ship-kit-ci` (конвейер
«задача → PR → сборка»: гейты 🔒, план-файл прогона, ожидание MERGED и
джобы). Стенд `dev/ship-kit/` проверяет их живьём на моках MCP;
прогоны — **только glm-5.3-flash**. Правила поведения — спека
`openspec/specs/base-skills/spec.md`; эталоны для сверки —
`dev/ship-kit/review.md`.

**Предпосылки:** node ≥ 18, `qwen` CLI в PATH, доступ к
glm-5.3-flash; все команды — из корня репо `~/projects/share`.

## Режим A — прогон скриптом (headless)

```
bash dev/ship-kit/run_one.sh [сценарий]
```

(по умолчанию `green777`; = сборка песочницы `$TMPDIR/ship-kit/<сценарий>`
→ запуск агента → проверка критериев; песочница пересоздаётся с нуля).

Промпт green777 (зашит в `make_sandbox.mjs`):

```
PRJ-777 возьми задачу: добавь в калькулятор функцию умножения mul(a, b) и вызови её в run(). mcp-tracker=jira, mcp-repo=bitbucket, mcp-build=jenkins, poll=5. Подтверждаю пуш ветки и создание PR. Подтверждаю запуск сборки PRJ-777.
```

«Подтверждаю …» — pre-approved фразы гейтов (в headless человека для
карточек нет); `poll=5` — интервал опроса джобы (иначе дефолт 600 сек).

Ожидание: план создаётся без вопроса (внешних скиллов нет) → `mul` в
`app.py` → карточки пройдены pre-approved → PR MERGED (мок) → сборка
RUNNING→SUCCESS, агент ждёт сам → план закрыт → предложение архивации.

**Завис flash:** Ctrl-C, затем `bash "$TMPDIR/ship-kit/<сценарий>/retry.sh"`
(продолжит тот же прогон по плану).

## Режим B — ручной прогон глазами

```
bash "$TMPDIR/ship-kit/<сценарий>/manual.sh"
```

(интерактивная сессия qwen в каталоге песочницы; спросит доверие к
папке — согласиться; можно дописать `--yolo`, 🔒-карточки ship-kit
останутся — они в скилле.)

Промпт — тот же **без** «Подтверждаю …» (карточки закрываешь ты):

```
PRJ-777 возьми задачу: добавь в калькулятор функцию умножения mul(a, b) и вызови её в run(). mcp-tracker=jira, mcp-repo=bitbucket, mcp-build=jenkins, poll=5.
```

По шагам: Шаг-0 (моки, план без вопроса, mul, коммит) → 🔒 карточка
«пуш+PR» — ответь «да»/«ок» → агент сам ждёт MERGED опросом → 🔒
карточка запуска — «да» → агент сам ждёт джобу (опросы каждые 5 сек,
без «ждать ли») → план закрыт, предложение архивации.

По ходу смотреть: план-файл `.qwen/tmp/ship-kit/PRJ-777/plan.md`
(живой), `mock-state.json` (PR в `bitbucket.prs`, опросы в
`jenkins.polls`), `git log` в песочнице.

## Критерии успеха (оба режима)

1. План-файл создан, все слоты закрыты;
2. PR в моке MERGED, ветка `feature/PRJ-777` запушена в bare;
3. Джоба запускалась и опрошена ≥ 2 раз — агент **ждал**, вопрос
   «ждать ли» не задавал (в ручном режиме видно глазами);
4. Финальный отчёт: `OK: true`, строки `ДАЛЬШЕ` нет.

Машино-проверяемое — `bash dev/ship-kit/check.sh
"$TMPDIR/ship-kit/<сценарий>"` (без run.log пропустит пункт про лог —
ручной режим лога не пишет).

## После прогона

- **GREEN:** итог в `dev/ship-kit/e2e-run.md` (дата, режим, попытки,
  дословные строки `OK:`/`JOB:` и из check.sh) и команда «архив» —
  закроет активный change `dev-stand`.
- **RED:** причина в журнал; расхождение со скиллами/спекой —
  отдельной задачей (чинятся скиллы, не стенд).

## Новые сценарии — руками и скриптом

Сценарий = имя + промпт + фикстуры + сид мока + критерии. Добавление —
5 шагов, все в `dev/ship-kit/make_sandbox.mjs` (и запись в
`SCENARIOS.md`):

1. **Промпт:** в объекте `PROMPTS` — запись `'<имя>': '<промпт>'`
   (алиасы `mcp-tracker=jira, mcp-repo=bitbucket, mcp-build=jenkins`,
   `poll=<сек>`; для headless — фразы «Подтверждаю …» для каждой
   🔒-карточки сценария); имя добавь в usage-строку скрипта.
2. **Фикстуры:** рядом с `appPy` — ветка по `scenario` (например,
   синтаксическая ошибка в `app.py` для сценария «упавшей сборки»).
3. **Сид мока:** в объекте `state` — ветка по `scenario`:
   `jenkins.results['calc-app']` — последовательность исходов
   (`['FAIL_CODE', 'SUCCESS']` = упасть, после фикса зелёная),
   jira-тикет под ключ задачи (описание = что ожидает агент),
   `bitbucket.autoMerge`. Доступные падения (mock.mjs, `BASE_LOGS`):
   `FAIL_CODE` (чинится правкой кода), `FAIL_CONFIG` (конфиг),
   `FAIL_SONAR` (не чинить), `FAIL_INFRA` (эскалация DevOps — тикет
   добавь в jira-issues).
4. **Ручной вариант:** тот же промпт без «Подтверждаю …» — карточки
   закрывает человек; песочница и раннеры те же.
5. **Критерии:** ожидаемая цепочка и условие успеха — в
   `SCENARIOS.md`. `check.sh` проверяет green777: для нового сценария
   либо допиши блок проверок, либо сверяй руками по SCENARIOS.md.

Сборка и запуск нового сценария:

```
node dev/ship-kit/make_sandbox.mjs <имя>
bash "$TMPDIR/ship-kit/<имя>/run.sh"        # headless
bash "$TMPDIR/ship-kit/<имя>/manual.sh"     # руками
bash dev/ship-kit/run_one.sh <имя>          # всё одной командой (headless)
```

Итог — в `e2e-run.md`.

## Карта стенда

- `mcp/mock.mjs` — моки MCP (роли argv, состояние в файле, первый
  опрос джобы RUNNING);
- `make_sandbox.mjs` — песочница + раннеры (run.sh / retry.sh /
  manual.sh); `run_one.sh`, `check.sh` — прогон одной командой и
  критерии green777;
- `SCENARIOS.md` — сценарии; `e2e-run.md` — журнал; `review.md` —
  опросник ревью; `README.md` — краткий обзор.
