# dev/ship-kit/ — разработка ship-kit

Каталог разработки расширения `ship-kit` — в установку не попадает
(эталон — `../../extensions/ship-kit/`). Конвенция воркспейса —
`dev/<имя-расширения>/`, см. [../README.md](../README.md).

## Раскладка

| Путь | Что |
|---|---|
| `about-my-work.md` | транскрипт-источник требований пользователя (сырой ввод) |
| `tests-architecture.md` | план архитектуры тестов (4 уровня) |
| `plans/` | implementation-планы задач (superpowers-методика) |
| `research/` | исследования и решения по архитектуре |
| `e2e/mcp/` | 6 stdio-моков MCP + фикстуры логов (подключены `.qwen/settings.json` корня репо) |
| `e2e/target/` | таргет с инжектированным багом (`app.py:19`) |
| `e2e/registry.md`, `e2e/e2e-runs.md` | стендовый md-реестр и журнал прогонов (создаются/пополняются при исполнении тест-плана) |
| `e2e/bare.git/`, `e2e/e2e-run/` | изоляция прогона (gitignore) |
| `tests/` | детерминированные скрипты уровней 1–2 (создаются тест-планом) |

## Обновление эталона (установленной копии)

После правок в `extensions/ship-kit/` — из корня репо:

```bash
bash dev/sync-reference.sh ship-kit
```

Скрипт пересоздаёт `~/.qwen/extensions/ship-kit` из чистого корня эталона
(uninstall → install --consent) и показывает, что установилось. Альтернатива
на время активной разработки — `qwen extensions link <путь к extensions/ship-kit>`
(правки отражаются сразу, переустановка не нужна).

Модельные прогоны (уровни 3–4 тест-плана) — только на `glm-5.3-flash`.
