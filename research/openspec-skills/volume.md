## Наблюдения: объём ≠ функционал

1. **Один файл на скилл — вся «механика» вынесена в CLI.** У суперпауэрс 65% объёма — файлы поддержки (шаблоны промптов, скрипты, референсы); здесь поддержки нет вовсе: граф артефактов, шаблоны, счётчики задач и валидацию отдаёт `openspec` в JSON (`status`, `instructions`, `list`, `validate`). Скилл — интерпретатор CLI-контракта, а не носитель механизмов.
2. **21% корпуса — дословный boilerplate двух входных блоков.** Store selection (135 слов) идентичен по md5 во всех шести; Project check — в двух вариантах: 344 слова (propose, apply, update, explore) и 370 (archive, sync — плюс абзац про `<capability-path>`). Это плата за самодостаточность каждого скилла при генерации из шаблонов.
3. **Самые большие — explore (356 строк) и sync-specs (290).** explore тяжёл примерами диалогов и правилами stance; sync-specs — самый алгоритмичный скилл набора: правила слияния четырёх операций дельты и шесть условий ретира. Самый компактный update-change (109 строк) — потому что «интеллект» ревизии делает агент, текст задаёт только границы и процесс подтверждения.
4. **Исполняемого кода нет вообще — 6/6 файлов Markdown** (у суперпауэрс из 51 файла 9 — скрипты). `allowed-tools: Bash(openspec:*)` у всех: скилл говорит только с CLI; файловые операции (чтение артефактов, запись, mkdir/mv при архивации) выполняет сам агент по текстовым инструкциям.
5. **Иерархия авторитетов прописана в тексте, а не в коде.** CLI-значения (blocked/ready, счётчики, существование артефактов) — контролирующие; `context`/`operationGuidance` — advisory («prompt-level behavior contracts, not enforceable checks»); конфликт advisory с контролирующим — докладывать и сохранять контролирующее. Аналог дисциплинарных правил суперпауэрс, но проверяемая часть живёт в CLI.
6. **Дублирования функционала нет.** Пересечения разведены границами: propose создаёт / update ревизует существующее (никогда не создаёт пропавшее — только указывает на instructions) / apply движет код и чекбоксы / sync пишет мейн-спеки / archive завершает и единственный вызывает другой скилл (sync, inline).
