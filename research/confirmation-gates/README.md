# Исследование: подтверждения необратимых действий в агентских инструментах

Дата: 2026-11-18. Повод: риск ship-kit — «явное "да"» гейта модель трактует из
свободного текста; на дешёвой модели расплывчатая фраза человека может быть
ошибочно принята за подтверждение необратимого (пуш, PR, запуск джобы).

## Вопрос

Как известные агентские инструменты решают подтверждение необратимых действий;
что из готового переиспользовать.

## Метод

Веб-поиск (SearXNG) + чтение первоисточников официальной документации.
Делегирование поиска на флеш-модель в этот день было недоступно (мост
инструментов отвергал вызовы), поиск выполнен из основной сессии — 6 коротких
запросов, 4 чтения страниц.

## Находки — готовые механизмы

| Механизм | Кто использует | Суть | Источник |
|---|---|---|---|
| Согласие = структурный выбор (кнопки), не текст | Claude Code, Gemini CLI, Codex | permission prompt с фиксированными опциями; канал подтверждения идёт через хост, мимо трактовки модели | code.claude.com/docs/en/permissions; geminicli.com/docs/cli/settings/; learn.chatgpt.com/docs/agent-approvals-security |
| Структурированный request_permission в протоколе | ACP | агент шлёт список опций, хост рендерит кнопки, назад возвращается выбранная опция | github.com/github/copilot-cli/issues/845 (2025-12-28); discuss.ai.google.dev (Zed, 2026-11). Спека agentclientprotocol.com/specification на дату исследования отдавала 404 — механика подтверждена вторичными источниками |
| Exact match + default-deny | Claude Code (permission rules), Codex (network policy) | разрешение — дословное правило (порядок deny > ask > allow, deny всегда сильнее); всё неразрешённое — вопрос или отказ | те же страницы permissions / agent-approvals-security |
| Гейт по классу действия, не по уверенности модели | Codex (MCP destructive-аннотации) | деструктивные вызовы инструментов всегда требуют подтверждения — необратимость как свойство действия | learn.chatgpt.com/docs/agent-approvals-security |
| Typed confirmation («make me say it») | GitHub (ввод имени репо при удалении), AWS/GCP | подтверждение = ввод имени конкретного объекта; связывает согласие именно с этим действием | ux.stackexchange.com/questions/130147; saasui.design/blog/saas-destructive-actions-confirmation-ux-patterns (2026-07-03) |
| Узкое пред-разрешение с трением | Gemini CLI (yolo только флагом CLI, не сохраняется в settings; disableAlwaysAllow; enablePermanentToolApproval: false) | «разрешить всё» — отдельное осознанное действие, не дефолт и не фраза | geminicli.com/docs/cli/settings/ |

## Ключевой вывод

Крупные инструменты не доверяют модели трактовку свободного текста как
согласия на необратимое: согласие — это либо нажатая опция (структура от
хоста), либо дословное совпадение с правилом (exact match, deny wins), либо
ввод имени объекта.

## Отображение на ship-kit — три уровня переиспользования

1. **Структурный вопрос хоста** (паттерн Claude Code / Gemini / ACP): гейт
   спрашивается инструментом с закрытыми опциями, выбор утвердительной опции =
   решение; текст вне опций — не подтверждение. **Выбрано пользователем
   2026-11-18** → change `gate-structured-question`.
2. **Дословный список affirmations + default-deny** для чисто-текстовых
   каналов (headless-прогоны) — не выбрано, отложено.
3. **Echo-nonce «да \<id\>»** на карточке (паттерн GitHub type-to-confirm) —
   не выбрано, отложено.

## Предупреждение

Снимок зафиксирован на дату выше; документация продуктов меняется — перед
опорой на детали сверять с живыми страницами.
